# 영상 그래픽 설계

대본의 **문장 하나하나를 어떤 그림으로 만들 것인가**를 정하고, `youtube_pipeline`
으로 렌더하는 일.

## 이 스킬이 막으려는 것

올리브영 성수편 123컷을 다 만들고 나서 세어 봤더니 **82컷(67%)이
`LowerThirdCard` 하나**였다. 실사 위에 자막 얹는 카드다.
화면은 계속 바뀌는데 **문법은 하나**였다는 뜻이고, 그래서 "지겹다",
"같은 포맷이 또 있다" 는 지적이 반복됐다.

원인은 실력이 아니라 **순서**였다. 대본을 읽으며 소재부터 고르면 거의 모든
문장이 "여기 어울리는 영상"으로 풀린다. **문장의 구조를 먼저 보면** 값·비교·
인과·선택·배분처럼 그림이 따로 있는 것들이 갈라져 나온다.

그래서 규칙은 하나다 — **소재보다 구조를 먼저 정한다.**

## 순서

**렌더 전에 설계를 먼저 확정한다.** 123컷을 렌더하면 30분이고, 다 뽑고 나서
"이 포맷 또 나왔다" 는 피드백을 받으면 다시 30분이다. 설계 단계에서 고치면 몇 초다.

1. 초안을 깐다 — 컷 분할·길이·카드 추천이 한 번에 나온다

       python3 scripts/plan_from_script.py <대본>.md --project <이름> --dry

2. **맨 끝 「설계 상태」 리포트를 먼저 읽는다.** 이게 이 도구의 진짜 출력이다.
   - `규칙에 안 걸린 문장 N컷` → **N개는 도구가 못 골랐다. 내가 설계해야 한다**
     (올리브영 대본은 123 중 92개였다. 그걸 방치해서 67%가 한 카드로 갔다)
   - `실사 계열 N%` → 권장 52%. 넘으면 설명 문장을 소재로 때우고 있는 것
   - `최다 카드 N%` → 32% 넘으면 그 카드로 때우고 있는 것

3. 미매칭 컷을 **한 줄씩 직접 고른다.** `references/카드-고르기.md`,
   특히 **5번 구조·배분**부터 본다. 숫자·비교가 없는 문장일수록 그쪽이다

4. 고른 결과를 `projects/<이름>/design.json` 에 적는다 —
   컷 번호 → `[카드, 이유, props]`. **이게 대본→화면의 단일 원본이다.**

       python3 scripts/apply_design.py <이름> --check     # 검사만
       python3 scripts/apply_design.py <이름> --placeholder

   `scene_plan.json` · `scene_props.json` 은 여기서 만들어진다. 둘은
   gitignore 라 날아가지만 design.json 은 커밋되니 다시 만들면 된다.
   `--check` 가 네 가지를 렌더 전에 잡는다:
   설계 안 된 컷 / **등록 안 된 카드 이름**(놓치면 빨간 화면 한 장) /
   같은 카드 연속 / 계열 비중(실사 25~52%)

5. 소재를 고른다 (`references/규칙과-함정.md` 의 소재 규칙)

       python3 scripts/fetch_sources.py <이름> --q "검색어" --video "검색어"
       # 컨택트시트를 **눈으로 보고** 채택한다
       python3 scripts/fetch_sources.py <이름> --adopt <id> <파일명>

6. **설계 시트를 사용자에게 보여 주고 확정받는다** — 컷 / 나레이션 / 카드 /
   테마 / 소재 표. 렌더는 그다음이다

7. 렌더 → 검수 시트 → 고침. 검수는 눈이 아니라 **재서** 한다

       python3 scripts/render_parkside.py --still --project <이름>
       python3 scripts/contact_sheet.py <이름>      # 한 장에 모아 흐름을 본다

   컷을 하나씩 열면 흐름이 안 보인다. 같은 문법이 몇 컷 만에 돌아오는지,
   밝은 판과 먹 판이 어떻게 번갈아 오는지는 **나란히 놓아야** 보인다.

## 가장 중요한 판단 하나

**"이 문장은 설명인가, 장면인가."**

- **설명**이면 그림이 뜻을 져야 한다. 나레이션이 없어도 화면만으로 절반은
  전달돼야 한다. 회색 사각형 하나 띄우고 나레이션이 다 지고 가면 그건
  설명이 아니라 자막이다.
- **장면**이면 소재가 주인공이다. 꽉 채우고 글자는 최소로.

설명 문장인데 소재로 때우고 있으면 그 컷은 다시 만든다.
설명을 그림이 지게 하는 법은 `references/설명을-그림으로.md`.

## 한 계열로 붙어 있는가

이 저장소엔 배경 계열이 셋 있었다 — 종이(`themeOf`/`PaperBg`), v2(먹 배경 +
옐로 발광 + 원근 바닥), shared(먹 배경 + `GridBg`). 더그랜드롯데 편 182컷 중
**76컷이 뒤 두 계열**이라 한 영상에 채널이 셋 섞여 보였다. 2026-08-24 에
쓰이는 카드를 전부 종이로 옮겼다.

**새 카드를 만들거나 옛 카드를 되살릴 때 확인한다:**

    grep -L "themeOf\|PaperBg" motion/src/*Card.jsx     # 안 걸리면 옛 계열

옮길 때 바꾸는 것:
- 발광(`textShadow: glow()`·`drop-shadow`) → **형광펜 띠 / 먹 테두리.**
  발광은 어두운 바탕에서만 성립한다. 크림 종이 위에서는 번져 흐릿하기만 하다
- 카드가 따로 그리던 격자 → `PaperBg` 격자. 따로 그리면 간격이 안 맞는다
- `Footer`(캡션+출처 하단) → `PaperCaption` + `PaperSource`(**우상단**)
- 배경별 글자색 분기 → 없앤다. 테마가 색을 정한다
- 항목별 색 팔레트 → 없앤다. 먹 + 노랑 하나다. 색으로 항목을 구분하면
  색이 뜻을 갖게 되고, 그러면 색을 계속 설명해야 한다

## 옛 자료는 영상으로 만든다

1938년 반도호텔, 1970년 청와대. 이런 대목에 쓸 수 있는 건 정지 사진 한 장뿐인데
그냥 띄우면 화면이 멎고, 멎으면 안 보게 된다. `ArchiveCard` / `archive.jsx` 가
필름처럼 돌린다 — 게이트 흔들림 · 움직이는 그레인 · 먼지 · 깜빡임 · 비네팅 · 탈색.

- 사진을 영상처럼 만드는 건 "천천히 확대"가 아니다. 그건 슬라이드쇼다.
  필름이 영상으로 읽히는 이유는 **프레임마다 미세하게 다르기 때문**이다.
  1~2px 게이트 흔들림 하나만 있어도 정지 사진이 돌아가는 필름이 된다
- `era` 로 시대를 고른다 — `film`(1930~60) / `video`(1980~90 방송, 주사선) /
  `photo`(옛 사진 스캔)
- 4:3 자료는 `gate: 1.333`. 억지로 늘리면 사람이 홀쭉해지고, 그게
  "가짜 자료"로 보이는 제일 흔한 이유다
- **연도 스탬프는 뺄 수 없다.** 없으면 그냥 세피아 필터 먹인 사진이다

## 하면 안 되는 것 (채널 규칙 · 사용자 확정)

- 출처는 **화면 우상단 `Source : 0000`**. 예외 없다
- **나가는 모션 금지.** 들어오는 것만
- 전환 모션은 **18컷 안팎**만 (챕터 첫 컷 + 판이 뒤집히는 자리).
  늘 있으면 전환이 아무 뜻도 없다
- **막대 위에 숫자 올리지 않는다.** 01/02 는 세로선 **오른쪽**
- **디자인·그래픽·영상·이미지 소재를 반복해서 쓰지 않는다.** 0중복이 기준
- 배경을 베이지 한 종류로만 쓰지 않는다
- 저작권물은 **출처를 밝히고 쓴다**. 로고 포함
- 실존 장소·건물·브랜드는 **실사만**. 구조·개념은 도해 또는 생성 영상
- 가정·추정·시뮬레이션은 **화면에 명시**한다
