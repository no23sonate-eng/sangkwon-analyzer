## 1. 대원칙

1. **자막은 작고 균일하다.** 크기로 소리치지 않는다. 전 구간 같은 크기,
   위계는 색·박스·타이포 카드로 만든다.
2. **자료는 액자에 담는다.** 사진·문서·지도는 풀블리드가 아니라
   배경 캔버스 위 카드로. 여백이 고급스러움을 만든다.
3. **타이포와 자료화면은 겹치지 않는다.** 대형 타이포는 얼굴샷 위 전용.
4. **모션은 없다.** 컷과 크로스페이드, 사진의 느린 줌뿐.
   화려함 대신 정확한 레이아웃과 색.
5. **한 화면 한 메시지.** 인포그래픽 카드도 수치 하나, 비교 하나만.

## 2. 색 체계 (실측값)

| 용도 | 값 |

| 카드 배경 | #104030 딥 포레스트 그린 (또는 #16181D 차콜) |
| 지도/면 요소 | #307060 뮤트 민트그린 |

  레몬 옐로(#FAFF2E)로 치환 가능 — 단 하이라이트 박스와 병용 금지.

## 3. 텍스트 컴포넌트

### 3-1. 본문 자막 (모든 발화)
- 얇은 웨이트, 작게(1080p 기준 40px), 항상 한 줄, 하단 중앙.
- **타이트 다크 박스**: 글자에 딱 붙는 반투명 검정 박스(투명도 약 70~75%).
  두 채널 공통의 가독성 장치 — 어떤 배경에서도 읽힌다.
- 강조 단어만 레몬 옐로. 문장당 최대 2개.

### 3-2. 대형 키워드 타이포 (얼굴샷 전용)
- headline: 얇은 웨이트 초대형(84px), 화이트 — 질문/핵심 구문
- concept: 미디엄 웨이트(64px), 레몬 옐로 — 외국어 개념어·수치
- **concept 는 한국어 소형 설명을 아래 병기** (조승연 패턴):
  "High-end Blight" 큰 글씨 + 그 아래 "고급의 악영향" 작은 화이트(34px)
- 화면 중앙, 페이드 250ms, 노출 2.5~3초

### 3-3. 출처·브랜드 인용 칩 (2026-07 고해상도 재확인 — 추측이었던 내용 실측으로 교체)
- **위치는 좌상단 코너가 아니라 인물 옆 중우측**(화면의 60~75% 지점),
  인물 얼굴과 겹치지 않게 배치.
- **다크 박스가 아니라 웜 크림/화이트 라운드 카드** — 종이 질감 프레임과
  같은 톤. 카드 위에 위→아래로 3단: ①실제 기관 로고/엠블럼(원본 색
  유지, 무채색 처리 안 함) ②기관명 국문(로고 색과 맞춘 컬러, 볼드)
  ③영문 표기(더 작게, 연한 회색조).
- 카드 아래쪽, 화면 하단에는 이것과 별개로 항상 뜨는 캡션 바(계층 1
  본문 자막)가 따로 있다 — 인용 칩과 본문 자막은 서로 다른 레이어.
- 실제 출처(정부기관·논문·기업 등)가 있을 때만 쓴다 — 가짜 로고 생성 금지.

### 3-4. 구간/범위 인디케이터 (2026-07 재확인 — "타임라인" 추측을 대체)
- 조승연 채널이 아니라 **셜록현준 채널에서 확인됨**. 연대기적 다중 점
  타임라인이 아니라 **하나의 구간·기간을 나타내는 점선 막대**였다.
- 다크그린 카드, 제목 중앙 상단(볼드 화이트) → 점선 가로선(전체 폭의
  약 70~80%) 좌우 끝에 **화살촉(◄►)** → 선 양 끝 아래에 작은 라벨
  (예: 시작 시점 / 종료 시점) → 카드 맨 아래 출처 캡션 박스.
- 중앙에 작은 다이아몬드/화살표 마커가 뜨는 것은 아마 특정 지점을
  가리키는 강조 마커로, 애니메이션 중간 프레임일 가능성 있음(정적
  캡처라 단정은 어려움) — 구현 시엔 마커 없는 단순 구간 표시부터.

## 4. 자료화면 연출

- **사진/스틸**: 배경색 캔버스 + 흰 테두리(6px) 카드, 화면 높이 74%,
  카드 내부만 Ken Burns. 배경은 자료 밝기로 자동 (웜페이퍼/차콜).
- **문서/기사 인용**: 다크 카드 위 문서 스크린샷 + 핵심 문장에
  민트 하이라이트 박스 + 하단에 번역/요약 자막 (셜록 패턴).
- **지도**: 플랫 라인/면 지도. 다크그린 배경 + 민트 면 + 지명 크게.
  실사 위성지도 금지 (톤 깨짐).
- **두 장 비교**: 카드 두 개 나란히 (좌우 각 42% 폭), 같은 배경 캔버스.
- **아카이브 영상**: 풀블리드 허용 (질감 자체가 무드).

## 5. 리듬

- 얼굴샷 5~15초 ↔ 자료/B-roll 2~5초 교차. 오프닝은 얼굴샷.
- 인포그래픽 설명 구간은 길어도 됨(10초+) — 단 카드 안 요소가 단계적으로
  추가되는 방식(빌드업)이며 카메라 움직임은 없음.
- 나레이션은 쉼 없이 밀도 높게. 자막은 발화와 1:1 싱크.

## 6. 하지 않는 것

- 키네틱 타이포, 흔들림, 급줌, 화려한 트랜지션, 파티클
- 원색 대비 남발 (포인트 1색 원칙)
- 자막 2줄, 대형 글씨 남발
- 자료 위 대형 타이포
- 스톡 느낌 기업 홍보 클립

## 7. 픽토그램·데이터 그래픽 세부 스타일 (2026-07 추가 스터디)

> 셜록현준 6개 영상 스토리보드(약 600프레임: 부산/요코하마, 도쿄/서울,
> 벤치, 2026 신축건물 리뷰) 재분석. 조승연 채널은 팝업스토어·온천 2편도
> 함께 봤으나 픽토그램 활용은 셜록현준 쪽이 압도적으로 많음.

### 7-1. 막대그래프 — 고해상도 재확인으로 스펙 확정 (2026-07)
- 막대는 **위아래 모두 둥근 필/캡슐 형태**(사각이 아님). 폭은 좁고
  막대 사이 간격도 좁아 촘촘 — 대략 막대폭:간격 ≈ 1:0.6~0.8.
- **제목(+서브카피)은 카드 상단 중앙 정렬** — 지난 스터디에서 "좌상단"
  이라 썼던 건 오기. 제목 볼드 화이트, 그 아래 한 단계 작은 서브카피
  (연회색, 조사문 톤: "OO 대비 OO 비교" 식).
- **수치 라벨은 막대 위쪽**(막대 안이 아니라 막대 상단 바로 위), 볼드
  화이트. **카테고리 라벨은 막대 아래쪽**, 작은 화이트/연회색, 2줄까지
  허용.
- **강조 막대(포인트색)는 '마지막 값'이 아니라 '논지상 핵심 막대' 아무
  위치나 될 수 있다** — 실측 사례는 오히려 첫 번째(왼쪽) 막대가 강조색.
  즉 강조 기준은 데이터 순서가 아니라 "이 문장이 말하려는 값".
- 카드 맨 아래 **출처 캡션 박스**(흰 필박스, 작은 검정 텍스트) 상시 배치
  — 그래프·인디케이터·인용칩 공통 하단 요소로 표준화할 것.

### 7-2. 오브젝트 아이콘 비교 클러스터 (2026-07 고해상도 재확인)
- 단색 실루엣 픽토그램보다 **작은 컬러 일러스트 아이콘**(입체감은
  있지만 진짜 등각투영은 아닌 경우가 더 많음 — §8-2 참고)을 쓰는
  빈도가 높다.
- 비교 대상을 **2~3개씩 그룹으로 묶고, 그룹 사이에 얇은 "점선"
  세로 구분선**을 그어 좌/우 비교 구도를 만든다 (실선이 아니라 점선인
  것을 재확인 — 은은한 경계).
- **배경은 두 갈래**: ①딥그린/차콜 카드(퍼센트·통계 성격일 때) ②웜
  크림 카드(건축·사물 자체를 설명할 때, §8-2 사례). 카드색으로 "이게
  통계 설명인지 사물 설명인지"를 구분하는 셈 — 통일할 필요 없음.
- 각 그룹 아래 작은 라벨 + 그 아래 다시 더 작은 회색 보조설명, 그리고
  그룹 전체 밑에 민트색 캡션 바(축약 요약 문구)가 오는 3단 구조도 확인.
- 스케일 비교 시 작은 사람 실루엣을 옆에 두어 크기 감을 준다 — 계속
  활용 가치 높음.

### 7-3. 도넛/파이 차트 — 카드가 아니라 오버레이
- 지금까지 가정한 "카드 안에 그래프"와 달리, 도넛 차트는 **어두워진
  실사 푸티지 위에 직접 오버레이**로 뜨는 경우가 많다 (풀스크린 카드
  아님, 화면 한쪽에 작게).
- 가는 **리더라인(leader line)**으로 수치 라벨을 차트 밖으로 빼서 연결.

### 7-4. 특정 부지·건물 강조 — 항공사진 + 반투명 하이라이트 오버레이
- §4 의 "실사 위성지도 금지"는 **국가/도시 단위 지도**에 한정된 규칙.
- 특정 필지·건물·구역을 설명할 때는 오히려 **실사 항공사진 위에 대상
  구역만 반투명 포인트색으로 덧칠**하는 연출을 쓴다 (스톡 느낌 대신
  실제 자료 사진 자체가 신뢰도를 준다). 국가 단위는 플랫 지도,
  부지 단위는 항공사진+오버레이로 구분해서 써야 함.

### 7-5. 대형 숫자(빅 넘버) — 고해상도 재확인으로 스펙 확정 (2026-07)
- 실제 사례(도쿄/서울 "1,400만"): **화면 좌측 1/3 지점, 배경 카드 없이
  실사 푸티지 위에 직접** 3단 구성 —
  1. 작은 라벨(민트그린, 볼드, 예: "서울 인구")
  2. 초대형 숫자(화이트, 볼드, 예: "1,400만") — 라벨의 약 3~4배 크기
  3. 캡션 한 줄(화이트, 라벨보다 살짝 큼, 예: "서울의 1.5배")
- **좌측 정렬**이 화면 중앙 정렬보다 흔했다 — 인물 얼굴을 안 가리려는
  의도로 보임. 배경 없이도 읽히는 건 원본 영상이 애초에 어둡거나
  대비가 있는 구간을 골라 타이밍을 맞췄기 때문 — 아무 프레임에나
  올리지 않고 **배경이 상대적으로 단순한 순간**을 골라야 한다는 뜻.

### 7-6. 인증·뱃지형 아이콘 (신규)
- 신뢰도를 강조할 때 트로피·메달·문서 아이콘을 골드 톤으로 작게
  조합해서 쓴다 (예: 인증서 아이콘 + 메달 아이콘 + 작은 인물 실루엣).

## 8. 개념 도식화 — 사진·영상 없이 설명하는 그래픽 (2026-07 추가 스터디 ②)

> "숫자나 간단한 개념은 꼭 이미지·영상을 안 가져와도 도식화로 설명할 수
> 있다"는 방향으로 셜록현준 10개 영상을 다시 봄(부산/요코하마, 골프,
> 스타디움, 대학 비교 등). 소스를 못 구했을 때의 대체재가 아니라,
> **오히려 소스보다 명확할 때 적극적으로 쓰는 정식 표현 수단**이었다.

### 8-1. 단색 실루엣 지역 도형 (국가 지도보다 자주 씀)
- 여러 나라가 다 보이는 세계지도 대신, **설명 중인 지역 하나만 납작한
  단색 실루엣**으로 그려서 웜 페이퍼 배경에 얹는다 (예: 미국 전체가
  아니라 텍사스주 하나만 초록 실루엣 + 작은 점 마커 + 라벨).
- 지금 `flat_map`의 "여러 나라 + 국경선" 스타일과는 다른, **더 단순한
  변형** — 국경선·이웃나라 다 안 그리고 대상 하나의 실루엣 + 점 하나.
  화제가 좁을 때(도시·주(州) 단위)는 이 쪽이 더 어울림.

### 8-2. 건물 비교 다이어그램 (2026-07 고해상도 재확인 — "등각투영"에서 정정)
- 고해상도로 다시 보니 진짜 등각투영(isometric)이 아니라 **건물
  정면도(front elevation) 단순화 일러스트**인 경우가 더 많았다 — 창문
  격자가 그려진 건물 정면 실루엣 두 개를 높이만 다르게 나란히 세운
  형태. 등각/입체 버전과 정면도 버전 둘 다 관찰됨 — 상황에 따라 선택.
- 실측 레이아웃: **웜 크림 배경 위쪽 + 화면 하단 1/5 정도만 진회색/
  녹색 "지면" 띠**로 마감. 건물은 지면 띠 위에 서 있는 구도.
- 높이 차이가 나는 지점에 **작은 흰 라벨 박스 + 가는 리더선**으로
  수치(예: "25층 건물")를 표시 — 그래프 라벨과 달리 이건 도형 중간
  지점에서 옆으로 끌어낸 리더라인 방식.
- 화면 맨 아래 지면 띠 위에 출처 캡션(흰 텍스트, 작게).
- 실사 자료가 없어도 개념(높이·규모 비교)이 완벽히 전달되는 저비용
  고효율 표현 — 우선 구현 후보 1순위.

### 8-3. 픽토그래프(isotype) — 막대 자체를 의미있는 형태로
- 순수 사각 막대 대신, **비교 대상과 관련된 아이콘 형태 자체를 막대처럼
  쌓거나 늘여서** 수치를 표현하는 경우가 있다(예: 컨테이너/병 모양을
  세로로 늘여 막대처럼 사용). 오토·아이소타입 인포그래픽의 정석 기법 —
  숫자가 그 자체로 "무엇의 양인지" 형태로 보여준다.
- 무분별하게 아무 수치에나 쓰지 않고, **막대가 상징하는 대상이 명확할
  때만** 사용(예: 수출 물량 → 컨테이너 모양, 인구 → 사람 실루엣 반복).

### 8-4. 삼각형/원 등 순수 기하 도형 비교
- 피라미드·오벨리스크 등 실물이 있는 경우가 아니어도, **순수 삼각형/원
  실루엣만으로 크기·비율 비교**를 표현한다(§7-2 피라미드 사례와 같은
  원리를 일반화). 사진이 없는 추상적 개념(예: "격차", "비중")에도
  적용 가능 — 삼각형 2개의 높이 차이만으로 "격차"를 보여주는 식.

### 8-5. 원칙: 언제 도식화를 쓰는가
- 소스 확보가 어려운 경우의 **대체재가 아니라**, 다음 두 조건 중
  하나면 소스보다 도식화를 **우선** 검토한다:
  1. 설명 대상이 **수치·비율·순위**일 때 (그래프·픽토그래프가 실사보다
     정확하고 빠르게 읽힌다)
  2. 설명 대상이 **위치·구조·비교 관계**처럼 추상적 개념일 때 (지도·
     아이소메트릭 다이어그램·기하 도형 비교가 실사보다 명확하다)
- 반대로 **분위기·질감·현장감**이 핵심인 문장(거리 풍경, 사람들의 표정,
  공간의 느낌)은 여전히 실사 B-roll이 맞다 — 도식화로 대체하지 않는다.

## 9. 스토리보드 해상도의 한계 — 색상값에 대한 유의사항

이번 재스터디는 유튜브 스토리보드(영상 축소 썸네일, 타일당 최대
320×180px)로 진행했다. **레이아웃·비례·구성 순서는 신뢰도 높게
측정됐지만, 픽셀 단위 정확한 헥스 컬러는 이 해상도로 뽑을 수 없다**
(JPEG 압축 블록이 실제 색을 뭉갠다). 그래픽 제작 시 색상은 §2의 기존
실측 팔레트(#104030/#307060/#C0392B/#7FD8C0, 본인 채널 #FAFF2E 등)를
그대로 쓰고, 이번 스터디에서 나온 색 설명은 "톤"(예: 민트그린, 웜크림)
참고용으로만 취급할 것 — 새 헥스값을 억지로 추출해 팔레트에 넣지 말 것.

## 11. 그래픽 레퍼런스 교체 — Cleo Abram (@CleoAbram) (2026-07-09)

> 사용자 피드백: "그래픽은 Cleo Abram 채널만 따라해. 폰트는 빼고."
> 그래픽(차트·다이어그램·스탯카드·지도)의 색·형태·레이아웃은 이제부터
> 이 채널이 유일한 기준이다. 자막 폰트(A2Z)와 계층 구조(§3)는 그대로 —
> 이번 교체는 "그래픽"에만 해당.

### 11-1. 색 시스템 — 순블랙 + 네온 라임 단일 강조

- 배경은 **순블랙에 가까운 검정**(`#0A0A0A`) — 딥그린/차콜 카드 폐기.
  카드 테두리·흰 액자도 없음 — 화면 전체가 캔버스(풀블리드).
- 강조색은 **네온 라임(옐로그린) 단 하나**(근사값 `#C6FF3D` — 유튜브
  압축 스토리보드 특성상 §9 처럼 정확한 헥스는 아니고 근사치). 그녀의
  모든 영상에서 측정 라벨("1 METER"), 데이터 포인트, 강조 막대, 스폰서
  배지("AD")까지 이 한 색만 반복 등장 — 색을 여러 개 쓰지 않는다.
- 보조색은 화이트(`#F5F5F0`, 본문/1차 정보)와 뮤트그레이(`#4A4A4A`,
  비강조 데이터·그리드선·출처 캡션) 두 가지뿐. 옛 팔레트의 벽돌레드·
  민트그린은 그래픽에서 제거.
- **네온 발광(bloom/glow)**: 강조색 텍스트·도형 가장자리가 부드럽게
  번진다 — 실측 시그니처 텍스처. `assets_lib._add_glow()`로 구현
  (강조색에 가까운 픽셀만 골라 블러 후 스크린 합성).

### 11-2. 차트 — 데이터잉크 최소, 여백 최대

- 배경 100% 검정, **가는 가로 그리드선만**(세로선 없음) 4~5개, 축·테두리
  없음. 실측 사례(트랜지스터 개수 로그 스케일 산점도)는 제목도 없이
  축 라벨과 데이터만 있을 정도로 절제.
- 막대는 필(캡슐)이 아니라 **살짝만 둥근 미니멀 사각**(rounding ≈ 폭의
  8%). 막대 사이 간격은 넉넉하게(폭:간격 ≈ 1:0.9) — 빽빽하지 않게.
- 제목/부제는 **좌상단 정렬**(중앙정렬이었던 셜록현준 스펙에서 변경).
- 강조 데이터만 네온 라임+발광, 나머지는 뮤트그레이 — 그 외 원색 없음.

### 11-3. 스탯카드(빅넘버) — 숫자 자체가 네온

- 라벨(화이트, 작게) → 초대형 숫자(**네온 라임 + 발광**, 그녀의 "1
  CENTIMETER" 식 측정 라벨과 동일 문법) → 캡션(뮤트그레이, 작게) 3단.
- 화살표로 두 값을 잇는 흐름(예: "캡레이트 4% → NOI 52억")에서는
  입력값은 화이트, **결과값만 네온 라임**으로 강조해 시선을 끝으로 보낸다.

### 11-4. 이 채널 특유의 추가 문법 (향후 구현 후보)

- **그리드 바닥 스케일 연출**: 3D 격자 바닥 위에 사물을 놓고 "1 METER →
  1 CENTIMETER → 1 MICRON" 처럼 스케일을 좁혀가며 네온 라벨을 띄우는
  연출. 실측 사례는 실제 3D 렌더(등각 격자 바닥+사물)라 matplotlib로는
  뼈대만 흉내(원근 격자 라인 + 위에 뜬 발광 라벨) 가능한 수준.
- **손글씨 화이트보드 모드**: 흰 배경 + 손글씨체 수식/메모 + 정답이
  아닌 부분에 **빨간 스크래치(취소선/동그라미)** 표시 후 옆에 정답
  제시 — "틀린 답 → 정정" 서사에 유용. 폰트 요청 제외 지침에 따라
  손글씨 폰트 자체는 도입하지 않되, 빨간 동그라미/취소선 주석 기법만
  차용 가능.
- **원형 배지(뱃지) UI**: 좌상단 작은 원형 아이콘 배지(그녀의 경우
  스폰서 표시) — 우리 채널에서는 "출처/자료" 표시 등 메타정보 배지로
  응용 가능한 패턴.
- **미니멀 네임 태그**: 로고 카드 없이 화이트 볼드 텍스트 한 줄만
  (셜록현준의 로고+국문+영문 3단 카드보다 훨씬 절제됨). §3-3 을 이
  방향으로 더 단순화할 수 있음 — 다만 실제 기관 인용 시엔 로고를
  보여주는 게 신뢰도상 나을 수 있어 상황에 따라 선택.

### 11-5. 이 툴체인으로 재현 불가능한 것 (정직한 한계)

- 실측 영상에는 **전문 3D 렌더(성운·블랙홀 왜곡공간·유리질감 렌더 등
  영화급 VFX)**가 상당수 등장한다. 이건 Blender/After Effects/Cinema4D
  급 도구가 필요한 영역으로, matplotlib+PIL 조합으로는 재현 불가능하다.
  우리가 실제로 가져올 수 있는 건 "순블랙+네온+미니멀 여백"이라는
  **색과 레이아웃 언어**까지이며, 영화 같은 입체 렌더링 자체는 대상이
  아니다 — 이 문서의 §11-1~11-3 스펙이 우리가 현실적으로 도달 가능한
  최대치다.

### 구현 이력 (2026-07-09, 이후 §12 로 대체됨)

`assets_lib.bar_chart()` / `percent_bar()` / `stat_card()` 를 §11-1~11-3
스펙으로 구현했었으나(`_add_glow()` 발광 헬퍼 포함), 같은 날 사용자가
The B1M 으로 레퍼런스를 재지정하면서 색·형태를 §12 로 다시 교체했다.
`_add_glow()`는 더 이상 호출되지 않음(순블랙+네온 전용 효과). 아래 §12
가 최신 구현 기준.

> 사용자 피드백: "현실적으로 The B1M 으로 하자. 이걸 보고 디자인, 그래픽을

### 12-1. 색 시스템 — 네이비 블루프린트 캔버스 + 빈티지 페이퍼 카드 + 블루/레드

  `#EDE3CC`, 그레인 텍스처 적용)가 여백을 두고 얹힌다 — Cleo 의 순블랙
  풀블리드와 달리 "카드가 캔버스 위에 놓인" 구도로 회귀(단, 흰 테두리
  액자는 없음 — 카드 자체 배경색 차이로만 구분).
- 비교/강조는 **블루(`#4A6FA5`) vs 레드(`#B33A3A`)** 2색 체계 — 실측
  사례(건축가 라이벌전 그래픽)는 라이벌 A/B, 신/구, 비교대상 1/2 를

- 카드 위 본문 텍스트는 **다크 차콜브라운**(`#2A2417`), 보조캡션은
  **뮤트 올리브그레이**(`#8A8064`) — 종이 위에서만 쓰는 색.
- 카드 밖 네이비 영역(제목 등)은 **밝은 크림**(`#E8E3D3`, `canvas_text`)

  발견한 버그, 수정됨).

  발광(`_add_glow()`)과 반대되는 텍스처 — 이 스타일에선 발광 없음.

### 12-2. 차트 — 가로 막대 "레이스" (건물 높이 경쟁 그래픽에서 실측)

- 실측 사례(크라이슬러 빌딩 vs 40 Wall Street 높이 경쟁 그래픽): 두
  대상의 막대가 **가로로 나란히 자라나 경쟁**하는 구도. 막대 끝에
  **매칭되는 색의 굵은 수치 라벨**("48M", "40M"), 막대는 각각 블루/레드.
- 우리 구현은 정적 이미지라 "경쟁"은 상대적 길이로만 표현하되, 색 코딩과
  막대-끝-라벨 관례는 동일하게 유지 (`bar_chart()` 가로 막대로 재작성).
- 카테고리 라벨은 막대 왼쪽(축처럼), 제목/부제는 카드 위 네이비 여백에.

### 12-3. 스탯카드(빅넘버) — 종이 위 레드 강조

- 페이퍼 카드 중앙에 라벨(다크 차콜, 작게) → 초대형 숫자(**브릭 레드**,
  발광 없이 플랫한 색) → 캡션(올리브그레이, 작게).
- 화살표 흐름(2단 수치)은 입력값 블루, 결과값 레드로 색 코딩.

### 12-4. 이 채널 특유의 추가 문법 (향후 구현 후보)

- **라이벌전(VS) 배너**: 흑백 아카이브 인물 컷아웃 사진 두 장 + 가운데
  굵은 레드 리본 배너 + 원형 "VS" 배지, 배너 위 화이트 볼드 대문자 이름.
  건축가/기업/도시 비교 서사에 응용 가능.
- **실사 항공사진 + 컬러 사각형 하이라이트**: 실제 흑백/컬러 항공사진
  위에 특정 구역만 얇은 레드 사각 테두리로 강조 — §7-4 와 같은 원리,
  이 채널에서도 반복 확인.
- **인물/건물 캡션 카드**: 페이퍼 배경 + 실사(또는 흑백) 사진 + 굵은
  블랙 타이틀 + 작은 그레이 서브타이틀(예: "CHRYSLER BUILDING /
  WILLIAM VAN ALEN") — §3-3 출처 칩보다 더 큰 규모의 "장(chapter)"
  전환 카드로 활용 가능.
- **흑백 인물 사진 위 블루/레드 원형 테두리**: 라이벌 구도에서 인물
  사진 자체에 팀 색상 원형 테두리를 둘러 소속을 표시.
- **블랙 텍스트 전용 전환 카드**: 순검정 배경에 화이트 볼드 텍스트
  한 줄("Let me explain.") — 챕터 전환/호흡 조절용.

### 12-5. 이 툴체인으로 재현 불가능한 것

- 실측 영상의 **손그림/콜라주풍 커스텀 일러스트**(건물 실루엣 컷아웃,
  인물 사진 정교한 배경 제거 등)는 일러스트레이터의 수작업 수준이라
  matplotlib/PIL 자동 생성으로는 단순화된 버전만 가능하다 — 정교한
  컷아웃 콜라주가 아니라 "색 코딩 + 그레인 텍스처 + 페이퍼 카드"라는
  구조까지가 현실적 목표.

### 12-6. 픽토그램 통합 — "텍스트/막대만 있으면 어색하다" 피드백 반영 (2026-07-09)

- 사용자 피드백: "토지, 건물 이런 게 들어가면 그에 맞는 픽토그램이나
  그림, 이미지가 들어가야 자연스럽다." 순수 타이포+막대만으로 구성된
  카드는 개념을 가리키는 시각 요소가 없어 허전하게 느껴진다는 지적.
- 해결: 기존에 있던 `assets_lib.icon_png()`(Iconify 검색 → 컬러 SVG →
  PNG)를 카드 생성 함수에 실제로 연결. `bar_chart()`/`stat_card()` 에
  `icon` 파라미터 추가 — 검색어(예: `"office building"`, `"land plot"`,
  `"coins"`, `"key"`, `"chart bar"`)를 주면 카드 안에 개념 아이콘이
  자동으로 합성된다(`_place_icon()` 신설, 카드 내부에 배치 + 그레인
  텍스처가 아이콘 위에도 적용되도록 순서 조정).
- 아이콘 선정 원칙: 카드가 다루는 핵심 명사(감정가→건물, 토지 평당가→
  땅/깃발, 총 투자금→동전, 캡레이트→막대그래프, 임대료→열쇠)에서
  가장 직관적인 Iconify 아이콘을 고른다. 색은 기본적으로 종이 위
  본문색(`text`, 다크 차콜)과 통일해 튀지 않게.
- **주의(버그 수정 기록)**: 카드 바깥 네이비 여백에 아이콘을 놓으면
  다크 차콜 아이콘이 안 보인다 — 아이콘은 항상 종이 카드 "안쪽" 좌표에
  배치해야 한다 (`bar_chart()`는 카드가 캔버스 전체를 채우지 않으므로
  카드의 실제 좌표 범위를 계산해서 그 안에 넣어야 함).

### 12-7. 형태·폰트 비율·배경 디테일 재작업 + 출처 인용 애니메이션 (2026-07-11)

- 사용자 피드백 원문: "그래픽이 너무 후지다. 첨부 사진처럼 컬러를
  따라하라는 게 아니라 폰트 크기·가로세로 비율, 그래프 모양, 뒷배경
  같은 디테일을 챙겨라." 첨부는 The B1M 실제 세로 막대그래프 스크린샷
  (에어라인 성장률 비교) — 컬러(청록+옐로그린)는 그대로 베끼지 않고
  **형태만** 참고 대상으로 명시.
- `bar_chart()` 전면 재작성: 기존 "가로 레이스 막대 + 별도 페이퍼 카드"
  구조를 폐기하고, 실측처럼 **세로 막대 + 상단만 둥근 모서리 + 카드 없이
  캔버스에 직접 서는 구도**로 교체. 막대 위 수치 라벨 / 막대 아래
  카테고리 라벨의 폰트 크기도 실측 비율에 맞춰 절제(카드를 지배하지
  않는 크기로 축소). 상단만 둥근 모서리는 matplotlib `FancyBboxPatch`
  (네 모서리 전부 라운드) 위에 아래쪽을 덮는 직각 `Rectangle` 을 한 장 더
  올리는 방식으로 구현(`_rounded_top_bar`).
- `percent_bar()` 도 동일 원칙으로 페이퍼 카드 제거, 캡슐형 막대가
  캔버스에 직접 놓이도록 재작성.
- **배경 디테일**: 플랫 단색 네이비였던 캔버스에 얇은 격자선(블루프린트
  느낌)을 추가하는 `_add_canvas_grid()` 신설 — 전용 배경 Axes를
  `zorder` 최하단에 깔고 콘텐츠 Axes는 `facecolor="none"` 으로 투명하게
  얹는 방식. `stat_card()` 의 네이비 여백에도 동일하게 적용해 카드 밖
  배경까지 일관된 디테일을 갖추도록 통일.
- 이 변경으로 §12-6 의 아이콘 배치 버그 클래스 자체가 사라짐: 막대가
  캔버스 하단에서만 자라므로 우상단 여백은 데이터 값과 무관하게 항상
  비어 있다 — 카드 내부 좌표를 별도 계산할 필요 없이 이미지 전체 기준
  비율(`pos`)을 그대로 아이콘 위치로 쓸 수 있다.
- **출처 인용 애니메이션 클립 신설** — 사용자 피드백: "출처 소스 기사도
  그냥 텍스트 캡션 말고 약간의 애니메이션을 써서 강조해." 실제 기사
  스크린샷이 없으므로 브라우저/문서 형태를 도식화한 카드를 그려
  재현(`assets_lib.render_source_citation()`): 크롬 바(신호점 3개 +
  URL 필) + 헤드라인 + 더미 본문 줄(회색 바) + 인용 문구 한 줄. 인용
  문구 뒤에서 하이라이트 박스가 폭 0→100%로 자라나는 애니메이션(ease-
  out) + 클립 전체에 은은한 Ken Burns 줌을 PIL 프레임 시퀀스로 렌더 후
  ffmpeg 로 인코딩. 실제 화면이 아님을 카드 안에 작게 명시("예시 이미지
  · 실제 화면 아님") — 레퍼런스 채널도 예시 그래프에 "FOR ILLUSTRATIVE
  PURPOSES ONLY" 를 작게 표기하는 관례를 그대로 따름(실제 기사를
  스크린샷/도용하지 않고, 허구임을 숨기지 않는 게 원칙).
- `도산공원빌딩` 프로젝트의 "최근 기사로는..." 문장 구간(9.23–23.37s)을
  3분할해 실증: 막대그래프(4.6억) → 출처 인용 클립(5.0s, "평당 4억
  5천만원" 하이라이트) → 같은 막대그래프로 복귀(비교 확정) — 그래프→
  출처 확인→그래프 복귀의 다큐멘터리 편집 문법.

## 13. 이미지 제작 가이드 — 5개 카테고리 규격화 (2026-07-11)

사용자 요청: "이미지 만드는 가이드를 만들어줘. 규칙." — 기사 캡처
애니메이션, 지도, 그래프, 폰트(국영문 혼용), 배경을 각각 정해진 개수의
변형으로 규격화. 색 팔레트는 그대로(§12), 형태·구성만 카테고리별로
고정 메뉴를 만든다. 실제 샘플은 시각 가이드 아티팩트로 만들어 전달함
(대화 세션에 링크 있음) — 아래는 코드 레퍼런스.

### 13-1. 기사 캡처 애니메이션 — `render_source_capture()` (2 변형)

실제 캡처 이미지 1장을 받아 카드 안에 온전히(contain, 잘리지 않게)
앉힌 뒤 애니메이션 mp4로 만든다. `highlight_box` 유무로 변형이 갈린다:
- **변형 A "줌"**(`highlight_box` 생략): 은은한 Ken Burns 줌만.
- **변형 B "하이라이트"**(`highlight_box=(x0,y0,x1,y1)`, 원본 이미지
  비율 0~1): 줌 + 지정 영역에 외곽선 박스가 자라나는 애니메이션.

`render_source_citation()`(§12-6, 실제 캡처가 없을 때 브라우저 도식을
그려주는 목업 버전)과는 별개 함수 — 실제 캡처가 있으면 항상
`render_source_capture()` 를 우선 사용한다.

### 13-2. 지도·위치 — 3가지 톤앤매너

| 변형 | 함수 | 용도 |
|---|---|---|
| A 플랫 실루엣 | `flat_map()` (기존) | 국가·지역 단위, 실제 GeoJSON 경계 |
| B 블루프린트 핀 | `map_pin_blueprint()` (신규) | 지도 데이터 없이 필지·교차로 단위 지목 |
| C 항공사진 오버레이 | `map_aerial_highlight()` (신규) | 실제 항공/위성 사진 + 반투명 컬러 권역 강조, 가장 사실적 |

`flat_map()` 은 이미 `_palette(config)` 를 쓰고 있어 별도 수정 없이
현재 팔레트(§12)와 호환된다.

### 13-3. 그래프 — 3가지 유형

| 변형 | 함수 | 용도 |
|---|---|---|
| A 세로 막대 비교 | `bar_chart()` (§12-7) | 2개 이상 수치 비교 |
| B 도넛/게이지 | `donut_gauge()` (신규) | 단일 비율 — `percent_bar()`(캡슐형)와 번갈아 써서 리듬 변화 |
| C 추이선 | `trend_line()` (신규) | 시간에 따른 변화(비교 아니라 흐름이 핵심) |

**버그 수정 기록**: `donut_gauge()` 최초 구현은 정사각(9x9) 캔버스로
저장했는데, render.py 의 B-roll 합성이 항상 1920x1080(16:9)으로
스케일하므로 정원이 타원으로 눌리는 버그가 있었다 — 16:9 고정 +
링 전용 정사각 인셋 axes로 수정. 또한 subtitle/source 캡션을 pie 축의
데이터 좌표(-1~1)로 착각해 `xycoords` 를 안 쓰거나 `_source_box` 의
`y` 파라미터(axes-fraction)에 데이터 좌표 값을 넘겨 캔버스 밖으로
잘려나가던 버그도 같이 수정(전용 텍스트 axes를 분리하고 모두
axes-fraction 으로 통일).

### 13-4. 폰트 — 국문/영문 혼용 규칙

폰트 자체(A2Z)는 절대 바꾸지 않는다 — 아래는 크기·트래킹·배열 규칙.

1. 단독으로 쓰이는 짧은 영문 약어(`NOI`, `IRR`, `B1M` 등)는
   `_track_latin()` 으로 글자 사이에 얇은 공백을 넣어 살짝
   트래킹한다 — 국문과 나란히 있을 때 시각적 밀도를 맞춘다.
2. 문장 속에 섞인 영문(예: "필요 순영업이익(NOI)")은 트래킹하지
   않는다 — 문장 흐름이 끊겨 보인다.
3. 국문 타이틀에 영문을 병기할 땐(예: "캡레이트(Cap Rate)") 영문을
   국문 크기의 70~80%로 낮춰 보조 정보임을 표시한다.
4. 숫자가 주인공인 스탯카드는 숫자를 라벨 대비 2.2~3배 크기로 —
   숫자 글자가 한글보다 시각적으로 작아 보이는 것을 보정.

### 13-5. 배경 — 3가지 톤앤매너

| 변형 | 함수 | 용도 |
|---|---|---|
| A 격자 블루프린트 | `_add_canvas_grid()` (§12-7) | 데이터 카드(그래프·스탯) 기본값 |
| B 풀블리드 페이퍼 | `_add_canvas_paper()` (신규) | 인트로·인용구처럼 여백이 많은 한 줄 카피 |
| C 사진 블러 | `_add_canvas_photo()` (신규) | 실제 장소감(대상 건물 항공사진 등)이 필요할 때 |

세 함수 모두 `fig` 에 전체 배경을 깐 뒤, 콘텐츠는 `facecolor="none"`
인 별도 axes를 그 위에 얹는 패턴이 공통 — 배경과 콘텐츠 레이어를
분리해두면 카드 성격이 바뀌어도 콘텐츠 코드를 그대로 재사용할 수 있다.

## 14. 실전 피드백 반영 (2026-07-11, `외국인환자` 프로젝트) — 무질문 자동 적용 규칙

`도산공원빌딩`이 아닌 실제 데이터(보건복지부 보도자료)로 첫 실전
영상을 만든 뒤 받은 피드백. §13 가이드 자체보다 우선하는 **표준
운영 규칙**으로 승격 — 다음 영상부터 묻지 않고 바로 적용한다.

1. **픽토그램(아이콘) 전면 폐기.** §12-6 에서 도입했던 `icon` 파라미터
   (`bar_chart`/`stat_card` 우상단·좌상단 아이콘)는 "이상하다"는
   피드백으로 폐기. 함수 시그니처의 `icon` 파라미터는 하위 호환을 위해
   남겨두되(기존 호출부 깨짐 방지), **새 카드를 만들 때는 절대 넘기지
   않는다.** 카드는 텍스트/도형만으로 완결되어야 한다.
2. **실사 영상에 사람 얼굴이 나오면 안 된다.** 클로즈업 인물 샷(예:
   피부과 시술받는 여성 얼굴)은 무조건 제외 — 이 채널은 애초에
   "얼굴 미촬영 스크립트 컷" 원칙이었는데 실전 프로젝트에서 실사
   B-roll을 고르며 놓쳤다. B-roll 후보를 고를 때 사람이 화면의
   초점(클로즈업 인물)인 컷은 자동 탈락, 군중·원경처럼 특정 개인이
   피사체가 아닌 컷(예: 공항 로비 인파)은 허용. 애매하면 그래픽으로
   대체한다.
3. **`bar_chart()` 막대 폭을 더 얇게.** "투박하다"는 피드백 —
   기존 폭 대비 0.75배로 축소(코드에 반영 완료, 향후 그래프도 이
   비율 유지). 필요하면 여기서 더 얇게 튜닝하되, 다시 두꺼워지지
   않도록 주의.
4. **실사 영상 위에 얹는 텍스트(자막 display 타이포)는 항상 또렷해야
   한다.** `subtitle.py`의 Headline/Concept/ConceptSub 스타일이
   원래 `Outline=0` + `\blur2` 조합(그래픽 카드의 어두운 단색 배경만
   가정하고 설계됨)이라 밝고 복잡한 실사 배경 위에서는 글자가 흐릿하게
   묻히는 버그가 있었다 — `Outline=3`(스케일 적용) 스트로크를 항상
   주는 것으로 수정, 인라인 `\blur` 태그도 제거. 앞으로 스타일을
   건드릴 땐 "실사 위에 얹혀도 또렷한가"를 항상 기준으로 삼는다.
