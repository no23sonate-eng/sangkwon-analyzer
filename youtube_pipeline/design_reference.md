## 1. 대원칙

1. **자막은 작고 균일하다.** 크기로 소리치지 않는다. 전 구간 같은 크기,
   위계는 색·박스·타이포 카드로 만든다.
2. **자료는 액자에 담는다.** 사진·문서·지도는 풀블리드가 아니라
   배경 캔버스 위 카드로. 여백이 고급스러움을 만든다.
3. **타이포와 자료화면은 겹치지 않는다.** 대형 타이포는 얼굴샷 위 전용.
4. **모션은 없다.** 컷과 크로스페이드, 사진의 느린 줌뿐.
   화려함 대신 정확한 레이아웃과 색.
   → **(2026-07-29, §18 로 수정)** 인포그래픽 카드에 한해서는 예외 —
   Remotion(실제 브라우저 렌더링) 기반 카드는 스프링 애니메이션·숫자
   카운트업 등 절제된 모션을 쓴다. "화려함"이 아니라 "정보가 실제로
   드러나는 순서"를 모션으로 표현하는 것까지만 — 화면 전환·B-roll
   컷 자체는 여전히 모션 없이 컷/크로스페이드만.
5. **한 화면 한 메시지.** 인포그래픽 카드도 수치 하나, 비교 하나만.

## 2. 색 체계 (실측값)

### 본인 채널 기본
| 용도 | 값 |
|---|---|
| 본문 자막 | #FFFFFF |
| 강조 (시그니처) | #FAFF2E 레몬 옐로 — 강조 전용, 배경 금지 |
| 프레임 배경 (밝은 자료) | #EFEAE3 웜 페이퍼 |
| 프레임 배경 (어두운 자료) | #16181D 딥 차콜 |

### 인포그래픽 카드 팔레트 (셜록현준 실측 — 그래프/카드 제작 시)
| 용도 | 값 |
|---|---|
| 카드 배경 | #104030 딥 포레스트 그린 (또는 #16181D 차콜) |
| 지도/면 요소 | #307060 뮤트 민트그린 |
| 포인트(아이콘·강조 도형) | #C0392B 벽돌 레드 |
| 텍스트 하이라이트 박스 | #7FD8C0 민트 (문서 인용 시 핵심 문장 위) |
| 카드 위 텍스트 | #FFFFFF / #EDEDE4 |

- 카드 하나에 포인트 색 1개만. 배경-면-포인트 3단 구조.
- 본인 채널로 가져올 때: 카드 배경은 차콜/딥그린 유지, 포인트는
  레몬 옐로(#FAFF2E)로 치환 가능 — 단 하이라이트 박스와 병용 금지.

## 3. 텍스트 컴포넌트

### 3-1. 본문 자막 (모든 발화)
- 얇은 웨이트, 작게(1080p 기준 40px), 항상 한 줄, 하단 중앙.
- **타이트 다크 박스**: 글자에 딱 붙는 반투명 검정 박스(투명도 약 70~75%).
  두 채널 공통의 가독성 장치 — 어떤 배경에서도 읽힌다.
- 강조 단어만 레몬 옐로. 문장당 최대 2개.

### 3-2. 대형 키워드 타이포 (얼굴샷 전용)
- headline: 얇은 웨이트 초대형(84px), 화이트 — 질문/핵심 구문
- concept: 미디엄 웨이트(64px), 레몬 옐로 — 외국어 개념어·수치
- **concept 는 한국어 소형 설명을 아래 병기** (조승연 패턴):
  "High-end Blight" 큰 글씨 + 그 아래 "고급의 악영향" 작은 화이트(34px)
- 화면 중앙, 페이드 250ms, 노출 2.5~3초

### 3-3. 출처·브랜드 인용 칩 (2026-07 고해상도 재확인 — 추측이었던 내용 실측으로 교체)
- **위치는 좌상단 코너가 아니라 인물 옆 중우측**(화면의 60~75% 지점),
  인물 얼굴과 겹치지 않게 배치.
- **다크 박스가 아니라 웜 크림/화이트 라운드 카드** — 종이 질감 프레임과
  같은 톤. 카드 위에 위→아래로 3단: ①실제 기관 로고/엠블럼(원본 색
  유지, 무채색 처리 안 함) ②기관명 국문(로고 색과 맞춘 컬러, 볼드)
  ③영문 표기(더 작게, 연한 회색조).
- 카드 아래쪽, 화면 하단에는 이것과 별개로 항상 뜨는 캡션 바(계층 1
  본문 자막)가 따로 있다 — 인용 칩과 본문 자막은 서로 다른 레이어.
- 실제 출처(정부기관·논문·기업 등)가 있을 때만 쓴다 — 가짜 로고 생성 금지.

### 3-4. 구간/범위 인디케이터 (2026-07 재확인 — "타임라인" 추측을 대체)
- 조승연 채널이 아니라 **셜록현준 채널에서 확인됨**. 연대기적 다중 점
  타임라인이 아니라 **하나의 구간·기간을 나타내는 점선 막대**였다.
- 다크그린 카드, 제목 중앙 상단(볼드 화이트) → 점선 가로선(전체 폭의
  약 70~80%) 좌우 끝에 **화살촉(◄►)** → 선 양 끝 아래에 작은 라벨
  (예: 시작 시점 / 종료 시점) → 카드 맨 아래 출처 캡션 박스.
- 중앙에 작은 다이아몬드/화살표 마커가 뜨는 것은 아마 특정 지점을
  가리키는 강조 마커로, 애니메이션 중간 프레임일 가능성 있음(정적
  캡처라 단정은 어려움) — 구현 시엔 마커 없는 단순 구간 표시부터.

## 4. 자료화면 연출

- **사진/스틸**: 배경색 캔버스 + 흰 테두리(6px) 카드, 화면 높이 74%,
  카드 내부만 Ken Burns. 배경은 자료 밝기로 자동 (웜페이퍼/차콜).
- **문서/기사 인용**: 다크 카드 위 문서 스크린샷 + 핵심 문장에
  민트 하이라이트 박스 + 하단에 번역/요약 자막 (셜록 패턴).
- **지도**: 플랫 라인/면 지도. 다크그린 배경 + 민트 면 + 지명 크게.
  실사 위성지도 금지 (톤 깨짐).
- **두 장 비교**: 카드 두 개 나란히 (좌우 각 42% 폭), 같은 배경 캔버스.
- **아카이브 영상**: 풀블리드 허용 (질감 자체가 무드).

## 5. 리듬

- 얼굴샷 5~15초 ↔ 자료/B-roll 2~5초 교차. 오프닝은 얼굴샷.
- 인포그래픽 설명 구간은 길어도 됨(10초+) — 단 카드 안 요소가 단계적으로
  추가되는 방식(빌드업)이며 카메라 움직임은 없음.
- 나레이션은 쉼 없이 밀도 높게. 자막은 발화와 1:1 싱크.

## 6. 하지 않는 것

- 키네틱 타이포, 흔들림, 급줌, 화려한 트랜지션, 파티클
- 원색 대비 남발 (포인트 1색 원칙)
- 자막 2줄, 대형 글씨 남발
- 자료 위 대형 타이포
- 스톡 느낌 기업 홍보 클립

## 7. 픽토그램·데이터 그래픽 세부 스타일 (2026-07 추가 스터디)

> 셜록현준 6개 영상 스토리보드(약 600프레임: 부산/요코하마, 도쿄/서울,
> 벤치, 2026 신축건물 리뷰) 재분석. 조승연 채널은 팝업스토어·온천 2편도
> 함께 봤으나 픽토그램 활용은 셜록현준 쪽이 압도적으로 많음.

### 7-1. 막대그래프 — 고해상도 재확인으로 스펙 확정 (2026-07)
- 막대는 **위아래 모두 둥근 필/캡슐 형태**(사각이 아님). 폭은 좁고
  막대 사이 간격도 좁아 촘촘 — 대략 막대폭:간격 ≈ 1:0.6~0.8.
- **제목(+서브카피)은 카드 상단 중앙 정렬** — 지난 스터디에서 "좌상단"
  이라 썼던 건 오기. 제목 볼드 화이트, 그 아래 한 단계 작은 서브카피
  (연회색, 조사문 톤: "OO 대비 OO 비교" 식).
- **수치 라벨은 막대 위쪽**(막대 안이 아니라 막대 상단 바로 위), 볼드
  화이트. **카테고리 라벨은 막대 아래쪽**, 작은 화이트/연회색, 2줄까지
  허용.
- **강조 막대(포인트색)는 '마지막 값'이 아니라 '논지상 핵심 막대' 아무
  위치나 될 수 있다** — 실측 사례는 오히려 첫 번째(왼쪽) 막대가 강조색.
  즉 강조 기준은 데이터 순서가 아니라 "이 문장이 말하려는 값".
- 카드 맨 아래 **출처 캡션 박스**(흰 필박스, 작은 검정 텍스트) 상시 배치
  — 그래프·인디케이터·인용칩 공통 하단 요소로 표준화할 것.

### 7-2. 오브젝트 아이콘 비교 클러스터 (2026-07 고해상도 재확인)
- 단색 실루엣 픽토그램보다 **작은 컬러 일러스트 아이콘**(입체감은
  있지만 진짜 등각투영은 아닌 경우가 더 많음 — §8-2 참고)을 쓰는
  빈도가 높다.
- 비교 대상을 **2~3개씩 그룹으로 묶고, 그룹 사이에 얇은 "점선"
  세로 구분선**을 그어 좌/우 비교 구도를 만든다 (실선이 아니라 점선인
  것을 재확인 — 은은한 경계).
- **배경은 두 갈래**: ①딥그린/차콜 카드(퍼센트·통계 성격일 때) ②웜
  크림 카드(건축·사물 자체를 설명할 때, §8-2 사례). 카드색으로 "이게
  통계 설명인지 사물 설명인지"를 구분하는 셈 — 통일할 필요 없음.
- 각 그룹 아래 작은 라벨 + 그 아래 다시 더 작은 회색 보조설명, 그리고
  그룹 전체 밑에 민트색 캡션 바(축약 요약 문구)가 오는 3단 구조도 확인.
- 스케일 비교 시 작은 사람 실루엣을 옆에 두어 크기 감을 준다 — 계속
  활용 가치 높음.

### 7-3. 도넛/파이 차트 — 카드가 아니라 오버레이
- 지금까지 가정한 "카드 안에 그래프"와 달리, 도넛 차트는 **어두워진
  실사 푸티지 위에 직접 오버레이**로 뜨는 경우가 많다 (풀스크린 카드
  아님, 화면 한쪽에 작게).
- 가는 **리더라인(leader line)**으로 수치 라벨을 차트 밖으로 빼서 연결.

### 7-4. 특정 부지·건물 강조 — 항공사진 + 반투명 하이라이트 오버레이
- §4 의 "실사 위성지도 금지"는 **국가/도시 단위 지도**에 한정된 규칙.
- 특정 필지·건물·구역을 설명할 때는 오히려 **실사 항공사진 위에 대상
  구역만 반투명 포인트색으로 덧칠**하는 연출을 쓴다 (스톡 느낌 대신
  실제 자료 사진 자체가 신뢰도를 준다). 국가 단위는 플랫 지도,
  부지 단위는 항공사진+오버레이로 구분해서 써야 함.

### 7-5. 대형 숫자(빅 넘버) — 고해상도 재확인으로 스펙 확정 (2026-07)
- 실제 사례(도쿄/서울 "1,400만"): **화면 좌측 1/3 지점, 배경 카드 없이
  실사 푸티지 위에 직접** 3단 구성 —
  1. 작은 라벨(민트그린, 볼드, 예: "서울 인구")
  2. 초대형 숫자(화이트, 볼드, 예: "1,400만") — 라벨의 약 3~4배 크기
  3. 캡션 한 줄(화이트, 라벨보다 살짝 큼, 예: "서울의 1.5배")
- **좌측 정렬**이 화면 중앙 정렬보다 흔했다 — 인물 얼굴을 안 가리려는
  의도로 보임. 배경 없이도 읽히는 건 원본 영상이 애초에 어둡거나
  대비가 있는 구간을 골라 타이밍을 맞췄기 때문 — 아무 프레임에나
  올리지 않고 **배경이 상대적으로 단순한 순간**을 골라야 한다는 뜻.

### 7-6. 인증·뱃지형 아이콘 (신규)
- 신뢰도를 강조할 때 트로피·메달·문서 아이콘을 골드 톤으로 작게
  조합해서 쓴다 (예: 인증서 아이콘 + 메달 아이콘 + 작은 인물 실루엣).

## 8. 개념 도식화 — 사진·영상 없이 설명하는 그래픽 (2026-07 추가 스터디 ②)

> "숫자나 간단한 개념은 꼭 이미지·영상을 안 가져와도 도식화로 설명할 수
> 있다"는 방향으로 셜록현준 10개 영상을 다시 봄(부산/요코하마, 골프,
> 스타디움, 대학 비교 등). 소스를 못 구했을 때의 대체재가 아니라,
> **오히려 소스보다 명확할 때 적극적으로 쓰는 정식 표현 수단**이었다.

### 8-1. 단색 실루엣 지역 도형 (국가 지도보다 자주 씀)
- 여러 나라가 다 보이는 세계지도 대신, **설명 중인 지역 하나만 납작한
  단색 실루엣**으로 그려서 웜 페이퍼 배경에 얹는다 (예: 미국 전체가
  아니라 텍사스주 하나만 초록 실루엣 + 작은 점 마커 + 라벨).
- 지금 `flat_map`의 "여러 나라 + 국경선" 스타일과는 다른, **더 단순한
  변형** — 국경선·이웃나라 다 안 그리고 대상 하나의 실루엣 + 점 하나.
  화제가 좁을 때(도시·주(州) 단위)는 이 쪽이 더 어울림.

### 8-2. 건물 비교 다이어그램 (2026-07 고해상도 재확인 — "등각투영"에서 정정)
- 고해상도로 다시 보니 진짜 등각투영(isometric)이 아니라 **건물
  정면도(front elevation) 단순화 일러스트**인 경우가 더 많았다 — 창문
  격자가 그려진 건물 정면 실루엣 두 개를 높이만 다르게 나란히 세운
  형태. 등각/입체 버전과 정면도 버전 둘 다 관찰됨 — 상황에 따라 선택.
- 실측 레이아웃: **웜 크림 배경 위쪽 + 화면 하단 1/5 정도만 진회색/
  녹색 "지면" 띠**로 마감. 건물은 지면 띠 위에 서 있는 구도.
- 높이 차이가 나는 지점에 **작은 흰 라벨 박스 + 가는 리더선**으로
  수치(예: "25층 건물")를 표시 — 그래프 라벨과 달리 이건 도형 중간
  지점에서 옆으로 끌어낸 리더라인 방식.
- 화면 맨 아래 지면 띠 위에 출처 캡션(흰 텍스트, 작게).
- 실사 자료가 없어도 개념(높이·규모 비교)이 완벽히 전달되는 저비용
  고효율 표현 — 우선 구현 후보 1순위.

### 8-3. 픽토그래프(isotype) — 막대 자체를 의미있는 형태로
- 순수 사각 막대 대신, **비교 대상과 관련된 아이콘 형태 자체를 막대처럼
  쌓거나 늘여서** 수치를 표현하는 경우가 있다(예: 컨테이너/병 모양을
  세로로 늘여 막대처럼 사용). 오토·아이소타입 인포그래픽의 정석 기법 —
  숫자가 그 자체로 "무엇의 양인지" 형태로 보여준다.
- 무분별하게 아무 수치에나 쓰지 않고, **막대가 상징하는 대상이 명확할
  때만** 사용(예: 수출 물량 → 컨테이너 모양, 인구 → 사람 실루엣 반복).

### 8-4. 삼각형/원 등 순수 기하 도형 비교
- 피라미드·오벨리스크 등 실물이 있는 경우가 아니어도, **순수 삼각형/원
  실루엣만으로 크기·비율 비교**를 표현한다(§7-2 피라미드 사례와 같은
  원리를 일반화). 사진이 없는 추상적 개념(예: "격차", "비중")에도
  적용 가능 — 삼각형 2개의 높이 차이만으로 "격차"를 보여주는 식.

### 8-5. 원칙: 언제 도식화를 쓰는가
- 소스 확보가 어려운 경우의 **대체재가 아니라**, 다음 두 조건 중
  하나면 소스보다 도식화를 **우선** 검토한다:
  1. 설명 대상이 **수치·비율·순위**일 때 (그래프·픽토그래프가 실사보다
     정확하고 빠르게 읽힌다)
  2. 설명 대상이 **위치·구조·비교 관계**처럼 추상적 개념일 때 (지도·
     아이소메트릭 다이어그램·기하 도형 비교가 실사보다 명확하다)
- 반대로 **분위기·질감·현장감**이 핵심인 문장(거리 풍경, 사람들의 표정,
  공간의 느낌)은 여전히 실사 B-roll이 맞다 — 도식화로 대체하지 않는다.

## 9. 스토리보드 해상도의 한계 — 색상값에 대한 유의사항

이번 재스터디는 유튜브 스토리보드(영상 축소 썸네일, 타일당 최대

### 11-1. 색 시스템 — 순블랙 + 네온 라임 단일 강조

- 배경은 **순블랙에 가까운 검정**(`#0A0A0A`) — 딥그린/차콜 카드 폐기.
  카드 테두리·흰 액자도 없음 — 화면 전체가 캔버스(풀블리드).
- 강조색은 **네온 라임(옐로그린) 단 하나**(근사값 `#C6FF3D` — 유튜브
  압축 스토리보드 특성상 §9 처럼 정확한 헥스는 아니고 근사치). 그녀의
  모든 영상에서 측정 라벨("1 METER"), 데이터 포인트, 강조 막대, 스폰서
  배지("AD")까지 이 한 색만 반복 등장 — 색을 여러 개 쓰지 않는다.
- 보조색은 화이트(`#F5F5F0`, 본문/1차 정보)와 뮤트그레이(`#4A4A4A`,
  비강조 데이터·그리드선·출처 캡션) 두 가지뿐. 옛 팔레트의 벽돌레드·
  민트그린은 그래픽에서 제거.
- **네온 발광(bloom/glow)**: 강조색 텍스트·도형 가장자리가 부드럽게
  번진다 — 실측 시그니처 텍스처. `assets_lib._add_glow()`로 구현
  (강조색에 가까운 픽셀만 골라 블러 후 스크린 합성).

### 11-2. 차트 — 데이터잉크 최소, 여백 최대

- 배경 100% 검정, **가는 가로 그리드선만**(세로선 없음) 4~5개, 축·테두리
  없음. 실측 사례(트랜지스터 개수 로그 스케일 산점도)는 제목도 없이
  축 라벨과 데이터만 있을 정도로 절제.
- 막대는 필(캡슐)이 아니라 **살짝만 둥근 미니멀 사각**(rounding ≈ 폭의
  8%). 막대 사이 간격은 넉넉하게(폭:간격 ≈ 1:0.9) — 빽빽하지 않게.
- 제목/부제는 **좌상단 정렬**(중앙정렬이었던 셜록현준 스펙에서 변경).
- 강조 데이터만 네온 라임+발광, 나머지는 뮤트그레이 — 그 외 원색 없음.

### 11-3. 스탯카드(빅넘버) — 숫자 자체가 네온

- 라벨(화이트, 작게) → 초대형 숫자(**네온 라임 + 발광**, 그녀의 "1
  CENTIMETER" 식 측정 라벨과 동일 문법) → 캡션(뮤트그레이, 작게) 3단.
- 화살표로 두 값을 잇는 흐름(예: "캡레이트 4% → NOI 52억")에서는
  입력값은 화이트, **결과값만 네온 라임**으로 강조해 시선을 끝으로 보낸다.

### 11-4. 이 채널 특유의 추가 문법 (향후 구현 후보)

- **그리드 바닥 스케일 연출**: 3D 격자 바닥 위에 사물을 놓고 "1 METER →
  1 CENTIMETER → 1 MICRON" 처럼 스케일을 좁혀가며 네온 라벨을 띄우는
  연출. 실측 사례는 실제 3D 렌더(등각 격자 바닥+사물)라 matplotlib로는
  뼈대만 흉내(원근 격자 라인 + 위에 뜬 발광 라벨) 가능한 수준.
- **손글씨 화이트보드 모드**: 흰 배경 + 손글씨체 수식/메모 + 정답이
  아닌 부분에 **빨간 스크래치(취소선/동그라미)** 표시 후 옆에 정답
  제시 — "틀린 답 → 정정" 서사에 유용. 폰트 요청 제외 지침에 따라
  손글씨 폰트 자체는 도입하지 않되, 빨간 동그라미/취소선 주석 기법만
  차용 가능.
- **원형 배지(뱃지) UI**: 좌상단 작은 원형 아이콘 배지(그녀의 경우
  스폰서 표시) — 우리 채널에서는 "출처/자료" 표시 등 메타정보 배지로
  응용 가능한 패턴.
- **미니멀 네임 태그**: 로고 카드 없이 화이트 볼드 텍스트 한 줄만
  (셜록현준의 로고+국문+영문 3단 카드보다 훨씬 절제됨). §3-3 을 이
  방향으로 더 단순화할 수 있음 — 다만 실제 기관 인용 시엔 로고를
  보여주는 게 신뢰도상 나을 수 있어 상황에 따라 선택.

### 11-5. 이 툴체인으로 재현 불가능한 것 (정직한 한계)

- 실측 영상에는 **전문 3D 렌더(성운·블랙홀 왜곡공간·유리질감 렌더 등
  영화급 VFX)**가 상당수 등장한다. 이건 Blender/After Effects/Cinema4D
  급 도구가 필요한 영역으로, matplotlib+PIL 조합으로는 재현 불가능하다.
  우리가 실제로 가져올 수 있는 건 "순블랙+네온+미니멀 여백"이라는
  **색과 레이아웃 언어**까지이며, 영화 같은 입체 렌더링 자체는 대상이
  아니다 — 이 문서의 §11-1~11-3 스펙이 우리가 현실적으로 도달 가능한
  최대치다.

### 구현 이력 (2026-07-09, 이후 §12 로 대체됨)

`assets_lib.bar_chart()` / `percent_bar()` / `stat_card()` 를 §11-1~11-3
스펙으로 구현했었으나(`_add_glow()` 발광 헬퍼 포함), 같은 날 사용자가
The B1M 으로 레퍼런스를 재지정하면서 색·형태를 §12 로 다시 교체했다.
`_add_glow()`는 더 이상 호출되지 않음(순블랙+네온 전용 효과). 아래 §12
가 최신 구현 기준.

## 12. 그래픽 레퍼런스 재교체 — The B1M (@TheB1M) (2026-07-09, 2차)

> 사용자 피드백: "현실적으로 The B1M 으로 하자. 이걸 보고 디자인, 그래픽을
> 참고해." Cleo Abram(순블랙+네온)은 채널 도메인과 안 맞아 폐기 — The

### 12-1. 색 시스템 — 네이비 블루프린트 캔버스 + 빈티지 페이퍼 카드 + 블루/레드

- 전체 캔버스는 **다크 네이비**(근사값 `#16233A`) — 블루프린트(청사진)
  느낌의 배경. 그 위에 **에이지드(빈티지) 페이퍼 카드**(근사값
  `#EDE3CC`, 그레인 텍스처 적용)가 여백을 두고 얹힌다 — Cleo 의 순블랙
  풀블리드와 달리 "카드가 캔버스 위에 놓인" 구도로 회귀(단, 흰 테두리
  액자는 없음 — 카드 자체 배경색 차이로만 구분).
- 비교/강조는 **블루(`#4A6FA5`) vs 레드(`#B33A3A`)** 2색 체계 — 실측
  사례(건축가 라이벌전 그래픽)는 라이벌 A/B, 신/구, 비교대상 1/2 를
  항상 이 두 색으로 코딩한다. 강조하고 싶은 쪽을 레드로.
- 카드 위 본문 텍스트는 **다크 차콜브라운**(`#2A2417`), 보조캡션은
  **뮤트 올리브그레이**(`#8A8064`) — 종이 위에서만 쓰는 색.
- 카드 밖 네이비 영역(제목 등)은 **밝은 크림**(`#E8E3D3`, `canvas_text`)
  — 종이 위 텍스트 색을 그대로 쓰면 네이비 위에서 안 보인다(2026-07-09
  발견한 버그, 수정됨).
- **그레인(노이즈) 텍스처**: 카드 표면에 미세한 랜덤 노이즈를 얹어 낡은
  사진/종이 질감을 낸다(`assets_lib._add_grain()`). Cleo 의 네온
  발광(`_add_glow()`)과 반대되는 텍스처 — 이 스타일에선 발광 없음.

### 12-2. 차트 — 가로 막대 "레이스" (건물 높이 경쟁 그래픽에서 실측)

- 실측 사례(크라이슬러 빌딩 vs 40 Wall Street 높이 경쟁 그래픽): 두
  대상의 막대가 **가로로 나란히 자라나 경쟁**하는 구도. 막대 끝에
  **매칭되는 색의 굵은 수치 라벨**("48M", "40M"), 막대는 각각 블루/레드.
- 우리 구현은 정적 이미지라 "경쟁"은 상대적 길이로만 표현하되, 색 코딩과
  막대-끝-라벨 관례는 동일하게 유지 (`bar_chart()` 가로 막대로 재작성).
- 카테고리 라벨은 막대 왼쪽(축처럼), 제목/부제는 카드 위 네이비 여백에.

### 12-3. 스탯카드(빅넘버) — 종이 위 레드 강조

- 페이퍼 카드 중앙에 라벨(다크 차콜, 작게) → 초대형 숫자(**브릭 레드**,
  발광 없이 플랫한 색) → 캡션(올리브그레이, 작게).
- 화살표 흐름(2단 수치)은 입력값 블루, 결과값 레드로 색 코딩.

### 12-4. 이 채널 특유의 추가 문법 (향후 구현 후보)

- **라이벌전(VS) 배너**: 흑백 아카이브 인물 컷아웃 사진 두 장 + 가운데
  굵은 레드 리본 배너 + 원형 "VS" 배지, 배너 위 화이트 볼드 대문자 이름.
  건축가/기업/도시 비교 서사에 응용 가능.
- **실사 항공사진 + 컬러 사각형 하이라이트**: 실제 흑백/컬러 항공사진
  위에 특정 구역만 얇은 레드 사각 테두리로 강조 — §7-4 와 같은 원리,
  이 채널에서도 반복 확인.
- **인물/건물 캡션 카드**: 페이퍼 배경 + 실사(또는 흑백) 사진 + 굵은
  블랙 타이틀 + 작은 그레이 서브타이틀(예: "CHRYSLER BUILDING /
  WILLIAM VAN ALEN") — §3-3 출처 칩보다 더 큰 규모의 "장(chapter)"
  전환 카드로 활용 가능.
- **흑백 인물 사진 위 블루/레드 원형 테두리**: 라이벌 구도에서 인물
  사진 자체에 팀 색상 원형 테두리를 둘러 소속을 표시.
- **블랙 텍스트 전용 전환 카드**: 순검정 배경에 화이트 볼드 텍스트
  한 줄("Let me explain.") — 챕터 전환/호흡 조절용.

### 12-5. 이 툴체인으로 재현 불가능한 것

- 실측 영상의 **손그림/콜라주풍 커스텀 일러스트**(건물 실루엣 컷아웃,
  인물 사진 정교한 배경 제거 등)는 일러스트레이터의 수작업 수준이라
  matplotlib/PIL 자동 생성으로는 단순화된 버전만 가능하다 — 정교한
  컷아웃 콜라주가 아니라 "색 코딩 + 그레인 텍스처 + 페이퍼 카드"라는
  구조까지가 현실적 목표.

### 12-6. 픽토그램 통합 — "텍스트/막대만 있으면 어색하다" 피드백 반영 (2026-07-09)

- 사용자 피드백: "토지, 건물 이런 게 들어가면 그에 맞는 픽토그램이나
  그림, 이미지가 들어가야 자연스럽다." 순수 타이포+막대만으로 구성된
  카드는 개념을 가리키는 시각 요소가 없어 허전하게 느껴진다는 지적.
- 해결: 기존에 있던 `assets_lib.icon_png()`(Iconify 검색 → 컬러 SVG →
  PNG)를 카드 생성 함수에 실제로 연결. `bar_chart()`/`stat_card()` 에
  `icon` 파라미터 추가 — 검색어(예: `"office building"`, `"land plot"`,
  `"coins"`, `"key"`, `"chart bar"`)를 주면 카드 안에 개념 아이콘이
  자동으로 합성된다(`_place_icon()` 신설, 카드 내부에 배치 + 그레인
  텍스처가 아이콘 위에도 적용되도록 순서 조정).
- 아이콘 선정 원칙: 카드가 다루는 핵심 명사(감정가→건물, 토지 평당가→
  땅/깃발, 총 투자금→동전, 캡레이트→막대그래프, 임대료→열쇠)에서
  가장 직관적인 Iconify 아이콘을 고른다. 색은 기본적으로 종이 위
  본문색(`text`, 다크 차콜)과 통일해 튀지 않게.
- **주의(버그 수정 기록)**: 카드 바깥 네이비 여백에 아이콘을 놓으면
  다크 차콜 아이콘이 안 보인다 — 아이콘은 항상 종이 카드 "안쪽" 좌표에
  배치해야 한다 (`bar_chart()`는 카드가 캔버스 전체를 채우지 않으므로
  카드의 실제 좌표 범위를 계산해서 그 안에 넣어야 함).

### 12-7. 형태·폰트 비율·배경 디테일 재작업 + 출처 인용 애니메이션 (2026-07-11)

- 사용자 피드백 원문: "그래픽이 너무 후지다. 첨부 사진처럼 컬러를
  따라하라는 게 아니라 폰트 크기·가로세로 비율, 그래프 모양, 뒷배경
  같은 디테일을 챙겨라." 첨부는 The B1M 실제 세로 막대그래프 스크린샷
  (에어라인 성장률 비교) — 컬러(청록+옐로그린)는 그대로 베끼지 않고
  **형태만** 참고 대상으로 명시.
- `bar_chart()` 전면 재작성: 기존 "가로 레이스 막대 + 별도 페이퍼 카드"
  구조를 폐기하고, 실측처럼 **세로 막대 + 상단만 둥근 모서리 + 카드 없이
  캔버스에 직접 서는 구도**로 교체. 막대 위 수치 라벨 / 막대 아래
  카테고리 라벨의 폰트 크기도 실측 비율에 맞춰 절제(카드를 지배하지
  않는 크기로 축소). 상단만 둥근 모서리는 matplotlib `FancyBboxPatch`
  (네 모서리 전부 라운드) 위에 아래쪽을 덮는 직각 `Rectangle` 을 한 장 더
  올리는 방식으로 구현(`_rounded_top_bar`).
- `percent_bar()` 도 동일 원칙으로 페이퍼 카드 제거, 캡슐형 막대가
  캔버스에 직접 놓이도록 재작성.
- **배경 디테일**: 플랫 단색 네이비였던 캔버스에 얇은 격자선(블루프린트
  느낌)을 추가하는 `_add_canvas_grid()` 신설 — 전용 배경 Axes를
  `zorder` 최하단에 깔고 콘텐츠 Axes는 `facecolor="none"` 으로 투명하게
  얹는 방식. `stat_card()` 의 네이비 여백에도 동일하게 적용해 카드 밖
  배경까지 일관된 디테일을 갖추도록 통일.
- 이 변경으로 §12-6 의 아이콘 배치 버그 클래스 자체가 사라짐: 막대가
  캔버스 하단에서만 자라므로 우상단 여백은 데이터 값과 무관하게 항상
  비어 있다 — 카드 내부 좌표를 별도 계산할 필요 없이 이미지 전체 기준
  비율(`pos`)을 그대로 아이콘 위치로 쓸 수 있다.
- **출처 인용 애니메이션 클립 신설** — 사용자 피드백: "출처 소스 기사도
  그냥 텍스트 캡션 말고 약간의 애니메이션을 써서 강조해." 실제 기사
  스크린샷이 없으므로 브라우저/문서 형태를 도식화한 카드를 그려
  재현(`assets_lib.render_source_citation()`): 크롬 바(신호점 3개 +
  URL 필) + 헤드라인 + 더미 본문 줄(회색 바) + 인용 문구 한 줄. 인용
  문구 뒤에서 하이라이트 박스가 폭 0→100%로 자라나는 애니메이션(ease-
  out) + 클립 전체에 은은한 Ken Burns 줌을 PIL 프레임 시퀀스로 렌더 후
  ffmpeg 로 인코딩. 실제 화면이 아님을 카드 안에 작게 명시("예시 이미지
  · 실제 화면 아님") — 레퍼런스 채널도 예시 그래프에 "FOR ILLUSTRATIVE
  PURPOSES ONLY" 를 작게 표기하는 관례를 그대로 따름(실제 기사를
  스크린샷/도용하지 않고, 허구임을 숨기지 않는 게 원칙).
- `도산공원빌딩` 프로젝트의 "최근 기사로는..." 문장 구간(9.23–23.37s)을
  3분할해 실증: 막대그래프(4.6억) → 출처 인용 클립(5.0s, "평당 4억
  5천만원" 하이라이트) → 같은 막대그래프로 복귀(비교 확정) — 그래프→
  출처 확인→그래프 복귀의 다큐멘터리 편집 문법.

### 구현 완료 (2026-07-09)

`assets_lib.bar_chart()`(가로 막대 레이스) / `percent_bar()` /
`stat_card()` 전부 §12-1~12-3 스펙으로 재작성 완료. `_add_glow()` →
`_add_grain()` 으로 교체. `config.yaml` 의 `infographic` 팔레트를 네이비/
페이퍼/블루/레드 체계로 재교체(`canvas_bg`, `canvas_text` 키 신설).
구현 중 발견한 버그 2건 수정: ①`stat_card`의 `ax.axis('off')` 가 카드
배경색까지 지워버리던 문제(틱/스파인만 개별로 끄도록 수정) ②카드 밖

## 13. 이미지 제작 가이드 — 5개 카테고리 규격화 (2026-07-11)

사용자 요청: "이미지 만드는 가이드를 만들어줘. 규칙." — 기사 캡처
애니메이션, 지도, 그래프, 폰트(국영문 혼용), 배경을 각각 정해진 개수의
변형으로 규격화. 색 팔레트는 그대로(§12), 형태·구성만 카테고리별로
고정 메뉴를 만든다. 실제 샘플은 시각 가이드 아티팩트로 만들어 전달함
(대화 세션에 링크 있음) — 아래는 코드 레퍼런스.

### 13-1. 기사 캡처 애니메이션 — `render_source_capture()` (2 변형)

실제 캡처 이미지 1장을 받아 카드 안에 온전히(contain, 잘리지 않게)
앉힌 뒤 애니메이션 mp4로 만든다. `highlight_box` 유무로 변형이 갈린다:
- **변형 A "줌"**(`highlight_box` 생략): 은은한 Ken Burns 줌만.
- **변형 B "하이라이트"**(`highlight_box=(x0,y0,x1,y1)`, 원본 이미지
  비율 0~1): 줌 + 지정 영역에 외곽선 박스가 자라나는 애니메이션.

`render_source_citation()`(§12-6, 실제 캡처가 없을 때 브라우저 도식을
그려주는 목업 버전)과는 별개 함수 — 실제 캡처가 있으면 항상
`render_source_capture()` 를 우선 사용한다.

### 13-2. 지도·위치 — 3가지 톤앤매너

| 변형 | 함수 | 용도 |
|---|---|---|
| A 플랫 실루엣 | `flat_map()` (기존) | 국가·지역 단위, 실제 GeoJSON 경계 |
| B 블루프린트 핀 | `map_pin_blueprint()` (신규) | 지도 데이터 없이 필지·교차로 단위 지목 |
| C 항공사진 오버레이 | `map_aerial_highlight()` (신규) | 실제 항공/위성 사진 + 반투명 컬러 권역 강조, 가장 사실적 |

`flat_map()` 은 이미 `_palette(config)` 를 쓰고 있어 별도 수정 없이
현재 팔레트(§12)와 호환된다.

### 13-3. 그래프 — 3가지 유형

| 변형 | 함수 | 용도 |
|---|---|---|
| A 세로 막대 비교 | `bar_chart()` (§12-7) | 2개 이상 수치 비교 |
| B 도넛/게이지 | `donut_gauge()` (신규) | 단일 비율 — `percent_bar()`(캡슐형)와 번갈아 써서 리듬 변화 |
| C 추이선 | `trend_line()` (신규) | 시간에 따른 변화(비교 아니라 흐름이 핵심) |

**버그 수정 기록**: `donut_gauge()` 최초 구현은 정사각(9x9) 캔버스로
저장했는데, render.py 의 B-roll 합성이 항상 1920x1080(16:9)으로
스케일하므로 정원이 타원으로 눌리는 버그가 있었다 — 16:9 고정 +
링 전용 정사각 인셋 axes로 수정. 또한 subtitle/source 캡션을 pie 축의
데이터 좌표(-1~1)로 착각해 `xycoords` 를 안 쓰거나 `_source_box` 의
`y` 파라미터(axes-fraction)에 데이터 좌표 값을 넘겨 캔버스 밖으로
잘려나가던 버그도 같이 수정(전용 텍스트 axes를 분리하고 모두
axes-fraction 으로 통일).

### 13-4. 폰트 — 국문/영문 혼용 규칙

폰트 자체(A2Z)는 절대 바꾸지 않는다 — 아래는 크기·트래킹·배열 규칙.

1. 단독으로 쓰이는 짧은 영문 약어(`NOI`, `IRR`, `B1M` 등)는
   `_track_latin()` 으로 글자 사이에 얇은 공백을 넣어 살짝
   트래킹한다 — 국문과 나란히 있을 때 시각적 밀도를 맞춘다.
2. 문장 속에 섞인 영문(예: "필요 순영업이익(NOI)")은 트래킹하지
   않는다 — 문장 흐름이 끊겨 보인다.
3. 국문 타이틀에 영문을 병기할 땐(예: "캡레이트(Cap Rate)") 영문을
   국문 크기의 70~80%로 낮춰 보조 정보임을 표시한다.
4. 숫자가 주인공인 스탯카드는 숫자를 라벨 대비 2.2~3배 크기로 —
   숫자 글자가 한글보다 시각적으로 작아 보이는 것을 보정.

### 13-5. 배경 — 3가지 톤앤매너

| 변형 | 함수 | 용도 |
|---|---|---|
| A 격자 블루프린트 | `_add_canvas_grid()` (§12-7) | 데이터 카드(그래프·스탯) 기본값 |
| B 풀블리드 페이퍼 | `_add_canvas_paper()` (신규) | 인트로·인용구처럼 여백이 많은 한 줄 카피 |
| C 사진 블러 | `_add_canvas_photo()` (신규) | 실제 장소감(대상 건물 항공사진 등)이 필요할 때 |

세 함수 모두 `fig` 에 전체 배경을 깐 뒤, 콘텐츠는 `facecolor="none"`
인 별도 axes를 그 위에 얹는 패턴이 공통 — 배경과 콘텐츠 레이어를
분리해두면 카드 성격이 바뀌어도 콘텐츠 코드를 그대로 재사용할 수 있다.

## 14. 실전 피드백 반영 (2026-07-11, `외국인환자` 프로젝트) — 무질문 자동 적용 규칙

`도산공원빌딩`이 아닌 실제 데이터(보건복지부 보도자료)로 첫 실전
영상을 만든 뒤 받은 피드백. §13 가이드 자체보다 우선하는 **표준
운영 규칙**으로 승격 — 다음 영상부터 묻지 않고 바로 적용한다.

1. **픽토그램(아이콘) 전면 폐기.** §12-6 에서 도입했던 `icon` 파라미터
   (`bar_chart`/`stat_card` 우상단·좌상단 아이콘)는 "이상하다"는
   피드백으로 폐기. 함수 시그니처의 `icon` 파라미터는 하위 호환을 위해
   남겨두되(기존 호출부 깨짐 방지), **새 카드를 만들 때는 절대 넘기지
   않는다.** 카드는 텍스트/도형만으로 완결되어야 한다.
2. **실사 영상에 사람 얼굴이 나오면 안 된다.** 클로즈업 인물 샷(예:
   피부과 시술받는 여성 얼굴)은 무조건 제외 — 이 채널은 애초에
   "얼굴 미촬영 스크립트 컷" 원칙이었는데 실전 프로젝트에서 실사
   B-roll을 고르며 놓쳤다. B-roll 후보를 고를 때 사람이 화면의
   초점(클로즈업 인물)인 컷은 자동 탈락, 군중·원경처럼 특정 개인이
   피사체가 아닌 컷(예: 공항 로비 인파)은 허용. 애매하면 그래픽으로
   대체한다.
3. **`bar_chart()` 막대 폭을 더 얇게.** "투박하다"는 피드백 —
   기존 폭 대비 0.75배로 축소(코드에 반영 완료, 향후 그래프도 이
   비율 유지). 필요하면 여기서 더 얇게 튜닝하되, 다시 두꺼워지지
   않도록 주의.
4. **실사 영상 위에 얹는 텍스트(자막 display 타이포)는 항상 또렷해야
   한다.** `subtitle.py`의 Headline/Concept/ConceptSub 스타일이
   원래 `Outline=0` + `\blur2` 조합(그래픽 카드의 어두운 단색 배경만
   가정하고 설계됨)이라 밝고 복잡한 실사 배경 위에서는 글자가 흐릿하게
   묻히는 버그가 있었다 — `Outline=3`(스케일 적용) 스트로크를 항상
   주는 것으로 수정, 인라인 `\blur` 태그도 제거. 앞으로 스타일을
   건드릴 땐 "실사 위에 얹혀도 또렷한가"를 항상 기준으로 삼는다.

## 15. 그래픽 팔레트 3차 재교체 — 라이트 캔버스(2026-07-11)

사용자가 The B1M 채널의 다른 영상(뉴욕 초고가 아파트 공실 소재)을
"이제부터 이게 기본 디자인 포맷" 이라고 지정. §12(네이비 블루프린트+
빈티지 페이퍼+레드/블루)를 대체하는 **3차 팔레트** — 카드 함수들의
코드 구조·파라미터는 그대로, 배경 헬퍼와 팔레트 값만 교체.

### 15-1. 관찰한 톤앤매너 (일반화된 요약)

레퍼런스는 §12 계열과 달리 카드 배경이 짙은 네이비가 아니라 **밝은
오프화이트/옅은 블루그레이**다. 강조색은 블루 하나가 기본이고, "가장
최근·가장 중요한 값"에는 그린을 별도로 써서 시선을 끈다(레드 강조
없음). 격자무늬 같은 텍스처는 없고 평평한 단색 배경 위에 그래프/숫자만
깔끔하게 얹는다. 빈티지 그레인 텍스처도 없다 — 표면이 전반적으로
매끈하다.

### 15-2. 반영한 변경 (assets_lib.py + config.yaml)

- `config.yaml` `infographic` 팔레트 값 전면 교체(키 이름은 유지,
  의미만 바뀜): `canvas_bg` 이제 밝은 오프화이트(`#EEF1F6`, 이전엔
  네이비), `card_bg` 흰색(`#FFFFFF`, 이전엔 빈티지 크림), `point`
  블루(`#3D5A96`, 이전엔 브릭레드), `surface` 그린(`#2E9E6B`, 이전엔
  블루 — 이제 "최신값/강조" 전용), `text` 다크 네이비(밝은 배경 위 기본
  텍스트), `canvas_text` 는 네이비 블루프린트류 보조 그래픽(지도 등)
  전용으로 축소.
- `_add_canvas_light()` 신설 — 격자 없는 평평한 밝은 배경. 기존
  `_add_canvas_grid()`(네이비+격자)는 지도류(`map_pin_blueprint()`)
  전용으로 남기고, 일반 데이터 카드(`bar_chart`/`percent_bar`/
  `stat_card`/`donut_gauge`/`trend_line`)는 전부 `_add_canvas_light()`
  로 교체.
- `bar_chart()`: 비강조 막대 = 블루(`point`), 강조 막대(가장 최근/
  핵심 값) = 그린(`surface`) — 레드/블루 대비에서 블루/그린 대비로.
- `stat_card()`: 아이콘을 다시 허용하되(§14-1 에서 폐기했던 것 재검토
  — "이상하다"던 피드백은 아이콘 자체가 아니라 스타일이 안 맞았던
  것으로 재해석), 카드 우상단의 크고 장식적인 배지가 아니라 **라벨
  바로 위, 라벨과 같은 블루로, 작게** 붙이는 태그 문법으로 축소.
  화살표 흐름 카드(예: 캡레이트→NOI)는 입력값 블루·결과값 그린으로.
- `donut_gauge()`: 채워지지 않은 트랙을 옅은 회색(텍스트색 10% 알파)
  으로, 채워진 부분은 블루로 — 세그먼트 2색(레드/블루) 대신 단색 링.
- `trend_line()`: 선·점은 블루, **마지막(최신) 지점만 그린**으로
  강조 — "최신값만 별도 강조" 리듬 반영.
- 빈티지 그레인 텍스처(`_add_grain()`)는 이 5개 함수 전부에서 제거 —
  레퍼런스 표면이 매끈하기 때문. 함수 자체는 남겨두되(다른 배경
  톤앤매너에서 재사용 가능) 기본 호출에서 뺐다.
- `map_pin_blueprint()`(§13-2, 네이비 격자 기반)는 의도적으로 **그대로
  유지** — "도면/블루프린트" 느낌을 내는 용도로는 네이비 격자가 여전히
  맞는 선택이라 판단.

### 15-3. 검증

`외국인환자` 프로젝트(보건복지부 실데이터)를 이 팔레트로 재생성 →
재렌더 → 프레임 확인 완료. 실사 영상 위 자막 오버레이(§14-4 에서 만든
스트로크 있는 노란 타이포)는 밝은 배경 그래픽 위에서도 그대로 잘
보임(스트로크가 배경 밝기와 무관하게 작동하기 때문).

### 15-4. "컬러/톤앤매너 말고 도형·그래프 표현 방식 자체를 배워라" —
그래프 유형 2종 추가 (2026-07-11, 2차)

색은 이미 잘 됐지만 원한 건 그게 아니라 **도형·그래프의 표현 기법
자체**라는 피드백. 레퍼런스를 다시 스터디해 특정 텍스트·데이터가 아니라
**그래프 장르(범용 정보디자인 기법)** 를 추출 — 이 채널만의 것이 아니라
데이터저널리즘/설명 영상에서 널리 쓰이는 표준 차트 유형들이다:

- **로리팝 차트(`lollipop_chart()`)** — 두꺼운 막대 대신 얇은 선 끝에
  원(점) 하나로 값을 표시. `bar_chart()`(굵은 막대, 2~3개 항목 비교에
  안정적)보다 훨씬 가볍고 절제된 인상 — 레퍼런스가 막대보다 압도적으로
  자주 쓰는 비교 표현이라 이번에 정식 추가. 항목이 여러 개거나 화면이
  더 가벼워야 할 때 `bar_chart()` 대신 쓴다.
- **스펙트럼 다이어그램(`spectrum_diagram()`)** — 두 극단(정성적 개념,
  예: "유동적" ↔ "비유동적") 사이 어느 지점에 있는지를 원형 앵커 2개
  + 연결 막대 + 위치 마커로 보여주는 다이어그램. 숫자로 딱 떨어지지
  않는 정성적 비교/포지셔닝에 적합 — bar_chart/lollipop_chart(정량
  비교), donut_gauge/percent_bar(비율)와 다른 네 번째 축.
  **주의**: 모든 카드가 16:9 로 저장되는데 내부 좌표계는 0~1 정사각
  비율을 쓰므로, `Circle` 패치를 그대로 쓰면 최종 이미지에서 가로로
  눌린 타원이 된다(실제 발견한 버그) — `Ellipse` 로 세로 반지름을
  16/9 배 키워서 진짜 원으로 보이게 고쳐야 한다. 이 프로젝트의 모든
  원형 마커/배지는 이 보정을 거쳐야 한다.
- 두 함수 다 `외국인환자` 프로젝트에 실제로 적용해 검증(2023→2024
  성장 구간을 `bar_chart` 대신 `lollipop_chart` 로 교체) — 라이브러리에
  만들어만 두고 안 쓰는 걸 방지.

## 16. 회귀 버그 수정 + 디테일 보강 3종 (2026-07-11, 3차)

"디자인 반영이 안 됐다"는 피드백에 대한 답 — 실제로는 두 가지가 섞여
있었다: (1) §15 팔레트 교체가 지도류 함수에 낸 실제 회귀 버그, (2) 아직
구현하지 않은 디테일(배경 무늬, 건물 아이콘, 지도 데이터 시각화).

### 16-1. `canvas_bg`/`canvas_text` 의미 과부하 버그 — `blueprint_bg`/`blueprint_text` 로 분리

§15 에서 `canvas_bg`/`canvas_text` 를 네이비/밝은텍스트 → 밝은배경/어두운텍스트로
바꾸면서, 여전히 "네이비 블루프린트" 배경을 가정하는 지도류 함수들
(`_add_canvas_grid()`, `map_pin_blueprint()`, `map_data_markers()`,
`map_aerial_highlight()`)이 밝은 배경 위에 밝은(이제 안 보이는) 텍스트를
얹는 회귀가 실제로 있었다 — `map_markers.png` 테스트 렌더로 제목/격자가
거의 안 보이는 것을 확인. 지도/블루프린트 전용 색을 `blueprint_bg`
(`#16233A`)/`blueprint_text`(`#EDEFF4`)로 완전히 분리해 4개 함수 모두
수정. 교훈: 팔레트 키를 여러 "시대"에 걸쳐 재활용하면 의미가 바뀔 때
그 키에 의존하는 모든 함수를 다시 감사해야 한다 — 이번처럼 놓치면
조용히(에러 없이) 깨진다.

### 16-2. 완전 무지 배경 → 옅은 노이즈 텍스처

"배경이 완전 흰색이면 밋밋하다"는 피드백 — `_add_subtle_texture()`
(±4/255 랜덤 노이즈, PIL/numpy로 저장 후 후처리)를 라이트 캔버스를 쓰는
7개 함수(`bar_chart`/`percent_bar`/`stat_card`/`donut_gauge`/`trend_line`/
`lollipop_chart`/`spectrum_diagram`) 전체에 적용. 격자처럼 눈에 띄는
무늬가 아니라 확대해야 겨우 보이는 종이 질감 수준 — 카드/그래프 원색은
그대로 두면서 "완전 평면"이라는 인상만 깬다.

### 16-3. 원본 아이소메트릭 빌딩 아이콘 — `isometric_building_icon()`

"건물/사물 아이콘 표현" 요청. Iconify 외부 검색 아이콘은 팔레트와
톤이 안 맞고("이상해" 피드백 재발 우려) 저작권 있는 특정 레퍼런스
그래픽을 그대로 베끼는 것도 피해야 해서, 아이소메트릭(2:1) 투영 —
건축/설계 도면에서 수백 년 쓰인 범용 기법 — 을 직접 구현. 상단 마름모
(밝은 톤) + 오른쪽 면(기본색) + 왼쪽 면(어두운 톤, `_lighten(-0.30)`)
3면과 층 구분선으로 구성, 완전 오리지널 코드. `stat_card()`에
`icon_building=True` 옵션으로 연결(`_place_isometric_icon()` 헬퍼) —
`icon=` (Iconify 검색) 대신 쓰면 팔레트와 정확히 같은 블루 톤의 건물
아이콘이 라벨 위에 붙는다. `외국인환자` 프로젝트의 스탯카드 2장
(117만 명/201만 명, 병원 방문 맥락)에 적용해 검증.

### 16-4. `map_data_markers()` — 지도 위 데이터 시각화 (라이브러리 전용, 미적용)

"지도 위 데이터 시각화" 요청 — 지도(또는 도식화한 블록 배치) 위 여러
지점에서 값에 비례한 막대가 솟아오르는 네 번째 지도 유형. `map_pin_blueprint`
(위치 하나)와 `lollipop_chart`(선+점 문법)를 합친 형태. `points` 리스트로
`{x, y, value, label}` 여러 지점을 받는다. 라이브러리에는 추가했지만
`외국인환자`처럼 지점별 데이터가 없는 5문장짜리 영상에는 자연스럽게
들어갈 자리가 없어 이번 영상엔 적용하지 않음 — `spectrum_diagram()`과
같은 패턴(억지로 끼워넣지 않고, 맞는 스크립트가 나올 때 쓴다).

## 17. B1M 정밀 재스터디로 습득한 신규 문법 5종 (2026-07-12)

"컬러/톤앤매너는 됐는데 그래픽 자체를 스터디하라"는 지적 이후, 이전
스터디가 저해상도 스토리보드 그리드 몇 장을 훑은 수준이었다는 걸
인정하고 다시 제대로 봤다. `yt-dlp` 로 레퍼런스 영상의 유튜브 스토리보드
스프라이트(sb0, 타일당 160x90px)를 직접 받아 전체 248초를 1.4초 간격
175컷으로 훑었다 — 프레임을 통으로 뜨거나 특정 그래픽을 확대 추적하지
않고, 유튜브가 제공하는 저해상도 프리뷰 스프라이트만 사용(일반적인
"디자인 레퍼런스 조사" 범위 — 특정 저작물의 세부 재현이 아니라 장르
파악 목적). 이 과정에서 이전 라운드가 놓친 5가지 문법을 찾아 라이브러리에
새로 추가했다(`assets_lib.py` §8). 아직 실제 영상에 강제로 끼워넣지는
않음 — 맞는 스크립트가 나올 때 쓴다.

### 17-1. 실루엣 비교바 — `silhouette_bar_chart()`

이 채널 막대그래프의 진짜 정체: 막대가 사각형이 아니라 건물 매싱
아키타입(니들/테이퍼드/스텝/펜슬/슬래브 — 특정 건물이 아닌 범용
건축 유형 이름) 윤곽선 자체다. `bar_chart()`/`lollipop_chart()`에 이은
세 번째 "높이·규모 비교" 문법 — 스카이라인 비교처럼 "건물다움"이
핵심일 때 쓴다.

### 17-2. 유닛그리드 퍼센트(와플차트) — `unit_grid_building()`

퍼센트를 건물 파사드처럼 촘촘한 격자 타일로 채워 표현하고, 위/아래
지붕/베이스 캡으로 "건물"임을 분명히 한다. `donut_gauge`/`percent_bar`
(연속형 비율)와 달리 "실제 세대/유닛 수"가 감각적으로 와닿아야 할 때
(공실률·입주율 등) 쓴다.

### 17-3. 두 항목 실비교 도넛 — `donut_compare()`

§16 에서 지적한 "내 도넛은 문법이 틀렸다"의 수정판. `donut_gauge()`는
단일 값+회색 잔여 트랙(게이지)이고, 이건 두 실제 항목을 나란히 비교하는
진짜 도넛/파이다 — 두 조각 다 각자의 실측값+라벨을 바깥에 표기, 링도
게이지보다 훨씬 두껍다. "A vs B" 실비교가 주제일 때 `donut_gauge` 대신
쓴다.

### 17-4. 아이소메트릭 블록 다이어그램 — `isometric_block_diagram()`

여러 필지/유닛 블록을 아이소메트릭으로 쌓아 "부지 조합/선정" 맥락을
보여주고 그중 하나를 그린으로 강조하는 문법. `isometric_building_icon()`
(단일 타워 아이콘, §16-3)과 달리 여러 블록의 평면 배치 자체가 정보다.
depth 정렬은 `(col+row)` 기준 zorder 로 처리 — 블록 개수가 많아져도
앞 블록이 뒤 블록을 항상 올바르게 가린다.

### 17-5. 영상 위 단색 태그 배지 — `tag_badge()`

레퍼런스는 통계 수치를 영상 위에 얹을 때 흰 카드+테두리가 아니라
팔레트 색 사각형 하나에 굵은 글자만 얹는다(예: "$65,600,000"). 텍스트
크기를 실측해 딱 맞는 배경 사각형을 자동 계산하는 투명 PNG 생성기로
구현 — `render.py` 의 B-roll 오버레이 자리에 얹으면 된다. 카드형 문법
(stat_card 등)과는 별개의, "영상 위 직접 오버레이" 전용 축.

### 17-6. 이번에 확인만 하고 보류한 것

- **실제 지도 위 3D 돌출 막대** — 레퍼런스는 진짜 지도(회색 스트리트
  그리드) 위, 기울어진 3D 카메라 시점에서 막대가 솟아오른다. `matplotlib`
  으로 진짜 3D 원근을 재현하는 건 무리가 커서(§11-5/§12-5 와 같은 종류의
  한계) `map_data_markers()`(평면 2D)를 그대로 두고 억지 셰어(shear)
  변형을 걸지 않기로 함 — 어설픈 가짜 원근이 오히려 더 이상해 보일
  위험이 큼.
- **막대/선 그래프 두께 방향** — 레퍼런스 자체는 얇고 조용한 스타일인데
  지난 라운드엔 "두껍게" 요청을 받아 반영했다. 두 방향이 여전히 충돌
  중이라 임의로 되돌리지 않음 — 사용자 확인 후 처리.
- **라인아트 아이콘(저울, 집 윤곽선 등)** — Iconify 검색으로 이미 커버
  가능(`_place_icon(..., color="text")` 로 얇은 윤곽선 스타일 검색어를
  쓰면 됨). 새 코드 불필요, 사용 가이드만 확인.

## 18. matplotlib 천장을 넘김 — Remotion(실제 브라우저 렌더링) 도입 (2026-07-29)

"애플 발표 영상풍"(다크 배경 + 컬러 글로우 + 네온 텍스트섀도)으로
한 라운드 먼저 시도했다가 사용자가 실제 B1M 화면 3장(적층 막대차트,
데이터 테이블, 3D 건물 높이비교)을 보내며 반려 — "화려한 게 아니라
제도 도면 톤"이라는 게 요지였다. §12 의 팔레트/원칙 자체는 맞았지만,
`assets_lib.py`(matplotlib+PIL)로는 다음이 원천적으로 안 된다는 걸
이번에 명확히 확인했다:

- **진짜 그라디언트** — matplotlib 은 저해상도 numpy 배열을 만들어
  `imshow` 보간으로 흉내내는 수준. 큰 면적에서 계단/밴딩이 보임.
- **진짜 letter-spacing** — 유니코드 thin space(` `)를 글자
  사이 끼워 흉내(`_track_display`). 실제 자간 속성이 아님.
- **진짜 blur/shadow** — `SimplePatchShadow` 는 오프셋 그림자일 뿐,
  CSS `filter: drop-shadow`/`box-shadow` 급의 부드러운 블러가 안 됨.

이 셋을 해결하려고 **HTML/CSS/SVG를 실제 브라우저(Chromium)로
렌더링**하는 새 백엔드를 만들었다. 정적 이미지는 `pipeline/html_render.py`
(Chromium headless 스크린샷), 애니메이션이 필요한 카드는 **Remotion**
(React 기반, `youtube_pipeline/motion/`) — Node/npm 이 이미 설치돼
있어 채택. 기술 세부사항(렌더 명령어, 카드 카탈로그, 알려진 버그)은
`youtube_pipeline/motion/README.md` 참고. 이 섹션은 "디자인 판단
기준"만 남긴다.

### 18-1. B1M 실측 재보정 — 화려함이 아니라 절제

레퍼런스 3장에서 뽑은 디자인 DNA (다음 라운드부터 이걸 기준으로):

- **배경**: 순블랙 아님. 짙은 차콜(`#15171b` → `#0a0b0d` 세로
  그라디언트) + 아주 옅은 청사진 격자(80px 간격, 흰색 5% 불투명도).
  "빈 배경"이 아니라 은은한 제도 도면 텍스처.
- **색**: 채도 낮은(desaturated) 회색조·중간톤 위주. 포인트 컬러도
  쨍한 원색이 아니라 톤 다운된 버전.
- **글로우/네온 금지.** 카드에 컬러 백라이트 글로우를 넣었다가
  반려당함 — 이 톤에서는 "장식"이 아니라 "산만함"으로 읽힌다.
  입체감은 아주 옅은 drop-shadow(그림자 대비 0.4 이하) 정도로만.
  (단, 이 규칙은 §12 데이터 그래픽 한정 — 인물 사진 없는 인용구
  카드의 큰 따옴표 색 정도의 절제된 포인트 컬러는 허용.)
- **타이포**: 굵기로 위계를 나눈다(제목=Light, 값=Regular, 강조
  숫자만 Medium). 자간은 실제 `letter-spacing` 0.02~0.06em 정도로
  절제. 실제 A2Z 폰트를 반드시 로드해서 쓸 것(§18-3).

### 18-2. 고정 레이아웃 규칙 — 하단 자막 안전지대

**사용자 지시(항상 지킬 것, 2026-07-29):** 자막은 사용자가 프리미어에서
직접 얹는다. 그래픽 콘텐츠(제목·도형·값·인용구 등)를 화면 하단까지
채우면 안 되고, 화면 하단 **260px**(`SUBTITLE_SAFE_BOTTOM`, `1080`
기준)는 항상 비워둬야 한다. `motion/src/shared.jsx` 에 상수로 박아뒀고,
새 카드를 만들 때마다 이 여백 안에서 배치할 것 — 좌표를 실제로
계산해서 다음 요소와 겹치지 않는지 확인하고 넘길 것(빌딩 카드에서
실측 좌표가 10px 겹쳐 간격이 없었던 실수가 실제로 있었음).

같은 이유로 이 시기(2026-07-29~) 프로젝트는 **자막 큐(cues)도, 헤드라인
표시(displays)도 굽지 않는다** — `subtitle_plan.json` 은
`{"cues": [], "displays": []}` 로 비워두고 `subtitle.build_ass()` 로
빈 ASS 만 굽는다. 카드 안의 문구(제목/값/인용구)가 이미 정보를
전달하므로, 별도 자막 레이어가 필요 없다.

### 18-3. 카드 컴포넌트 카탈로그 (`motion/src/*.jsx`)

각 카드는 `useA2ZFonts()`(실제 브랜드 폰트 로드, §18-3-1) +
`GridBg`(청사진 격자) + `SUBTITLE_SAFE_BOTTOM` 을 공통으로 쓴다.

| 컴포넌트 | 언제 쓰나 | 비고 |
|---|---|---|
| `BuildingCard` | 건물/사물 하나가 주제 + 숫자 하나 | 아이소메트릭 SVG, 값은 스프링 카운트업 |
| `StatCard` | 금액·개소 등 단일 지표 강조 | 문장이 길면 `value2`/`subtitle2` 로 절반 지점에 2단계 전환(화면이 오래 안 죽게) |
| `DataTable` | 여러 수치를 한 번에(매출/순이익/배수 등) | B1M 데이터 테이블 실측 재현 — 얇은 구분선 + 우측정렬 숫자 + 행별 순차 페이드인. `closingLine` 으로 긴 카드에 요약 문장 추가 가능 |

### 21-1-c. 구성 다양성 — 같은 문법을 반복하지 말 것 (2026-08-06 사용자 지시)

> "그래픽 로직이 너무 비슷해. 특히 왼쪽 가운데 오른쪽 순서대로 오는 거 말하는
> 거야. 그리고 건물 1개에 상층 저층 이것도"

**"좌→우 3칸"과 "정면 단면"은 기본값이 아니다.** 한 영상 안에서 같은 구성이
3번 넘게 나오면 다른 문법으로 갈아탄다. 판단 기준은 데이터의 성질:

| 데이터 성질 | 쓸 문법 | 컴포넌트 |
|---|---|---|
| 시간·순서가 실제 값 | 연도축 (기간 길이가 눈에 보임) | `TimelineRailCard` |
| 단계적 상승 | 계단 | `PaperFlowCard layout='steps'` |
| 갈래·순차 분기 | 위→아래 | `PaperFlowCard layout='vertical'` |
| 주고받는 관계 | 좌우 화살표 2개 | `PaperFlowCard exchange` |
| 면적·"몇 배" | 같은 모서리에 중첩 | `AreaNestCard` |
| 셀 수 있는 개수 | 점 격자 | `DotMatrixCard` |
| 한 건물의 용도 층 | 아이소메트릭 분해 (정면 단면과 번갈아) | `ExplodedStackCard` |
| 비중(전체 대비) | 파이 조각 | `RatioCard` 원형 |
| 100% 넘는 배수 | 가로 막대 (세로 실루엣과 축이 달라짐) | `RatioCard mode='bar'` |
| 물리적 크기 비교 | 세로 실루엣 | `SkylineCompareCard` |

더 파크사이드 서울 29장 기준 분포 — 어느 문법도 5장을 넘지 않는다:
PaperImageCard 8 / SkylineCompareCard 4 / PaperFlowCard(row) 4 /
TimelineRailCard 3 / SectionCard 2 / PaperFlowCard(exchange) 2 /
나머지(steps·vertical·bar·pie·area·dot·section·sightline·rank) 각 1.

**컷 단위 피드백에서 반복해서 나온 규칙 (2026-08-06)**

- 출처는 **화면 오른쪽 아래 끝**(right 72 / top 1008). 자막이 하단 중앙에 깔리므로
  모서리로 완전히 빼야 서로 안 건드린다. 실사 컷도 같은 좌표에 굽는다.
- 종이 카드가 길게 이어지면 중간에 **어두운 종이 톤**(`dark` prop)을 한두 장 끼운다.
  `palette(dark)` 로 잉크·톤만 뒤집고 문법은 그대로 둔다.
- 설명이 필요 없는 장면은 카드를 만들지 말고 **이미지 한 장 + 문구 하나**로 끝낸다.
- 기관·기업이 주체인 그림에는 **로고**를 쓴다. 아이콘보다 주체가 즉시 읽힌다.
  (Commons SVG 썸네일은 알파 PNG 다 — `convert('RGB')` 로 열면 배경이 검게 눌린다)
- 라벨 박스를 넓혔으면 **항목 간격(slot)도 같이 넓혀야** 옆 항목과 안 겹친다.
- 시간축에 사건이 한 해에 몰리면 축을 **월 단위**로 바꾸고 `tickLabels` 로 라벨을 준다.
- 그래픽이 문장의 뜻과 겉돌면 도형을 바꾸는 게 아니라 **동사를 그린다**.
  "엘리베이터를 타고 내려가면" → 적층도가 아니라 내려가는 케이지.

**실사 위에 그래픽을 얹을 때 (2026-08-06 추가)**

- 원본 사진·도면에 이미 캡션이 박혀 있으면 **전체를 한 겹 눌러**(0.3 안팎) 우리
  오버레이가 위로 오게 한다. 그러고도 겹치는 자리는 불투명 판을 깐다.
- 배경 위 글자는 흰색 + 그림자. 노란 강조 칩은 글자를 잉크색으로 뒤집는다.
- 도면을 `cover` 로 깔면 기준선(지반 등)이 화면 어디에 놓일지 통제할 수 없다.
  **폭에 맞춰 깔고, 기준선이 원하는 y 에 오도록 위아래 위치를 계산**하라
  (`imageRatio` + `groundRatio` + `groundY`). 남는 아래 여백은 자막 영역이 된다.
- 두 대상을 실루엣으로 비교할 땐 **하나의 축척**을 공유해야 한다. 각자 박스에
  맞추면 3.41㎢ 와 3.03㎢ 가 같은 크기로 보여 비교가 거짓말이 된다.
- 도면에서 실루엣을 뽑을 땐 글자가 지나간 자리가 파인다. 점 패턴(연회색)만
  집어내면 순검정 글자는 애초에 안 섞이고, 남는 홈은 축 방향 gap-fill 로 메운다.

**새 카드를 만들 때 밟기 쉬운 함정**

- 아이소메트릭 판이 세로로 차지하는 높이는 두께 `H` 가 아니라 **`D + H`**
  (D = 윗면 마름모의 세로 지름). 간격을 `H` 기준으로 잡으면 판끼리 겹쳐
  셰브론처럼 보인다.
- 시간축 위 사건이 가까우면 라벨이 반드시 겹친다 → **홀짝으로 높이를 번갈아**
  올리고 지시선 길이를 함께 늘린다.
- 격자·목록처럼 항목마다 높이가 다른 배치는 수치·라벨을 **가장 큰 항목 기준
  한 줄에 정렬**한다. 제각각 두면 크기 차이가 아니라 배치 실수로 읽힌다.
- 구간을 가리키는 큰 수치는 **치수선(끝에 틱)** 으로 이어라. 구간보다 글자
  블록이 크면 중앙 정렬이 선을 넘으므로 바깥 모서리에 붙인다.

**레이아웃 자동 규칙 (2026-08-06 — 폰트 확대 후 겹침을 코드로 막은 것)**

- `PaperImageCard`: `ratio`(원본 가로/세로)를 주면 액자를 그 비율로 맞춰 **잘림·여백 없음**.
  다이어그램처럼 잘리면 안 되는 이미지는 `fit:'contain'`.
  타이틀/서브 유무에 따라 액자 위치·높이를 자동으로 깎아 캡션까지 820 안에 넣는다.
- `SkylineCompareCard`: 첨탑형(slender/setback/taper)은 실루엣 위로 20% 더 솟으므로
  최대 높이를 자동으로 낮춘다 → 꼭대기 수치가 타이틀을 침범하지 않는다.
- `RatioCard` 원형: 채움을 "중심에서 자라는 원"으로 하면 8.1% 같은 낮은 비중이
  점처럼 보인다. **파이 조각**으로 그린다. 라벨은 원 위, 수치는 원 아래.
- `RatioCard` 막대: 수치를 막대 **아래**가 아니라 라벨과 같은 줄(오른쪽 끝)에 둔다.
  아래에 두면 다음 행 라벨과 겹친다. 행 간격 172 / 막대 높이 58.

### 21-1-b. 실사 컷 끼워 넣기 (2026-08-06 사용자 지시 — 기본 규칙)

> "전체 영상도 중간중간 넣어야 돼. 너무 배경이 나오면 지루해"

설명 그래픽만 이어지면 지친다. **30~45초마다 실사(또는 CG 필름) 컷을 넣는다.**
목표 비중: 전체 길이의 **15~20%**.

- 데이터 모델: `scene_plan.json` 장면에 `cardDur`(카드가 차지하는 앞부분 초) +
  `broll:{src, ss, dur}`. `cardDur: 0` 이면 장면 전체가 실사.
- 긴 설명 장면(15초+)은 **앞 2/3 카드 + 뒤 1/3 실사**로 쪼갠다.
  내레이션은 그대로 흐르고 그림만 바뀌므로 타이밍을 안 건드려도 된다.
- 오프닝·클로징, 그리고 "이런 공간이다"류 장면은 통째로 실사가 낫다.
- 컷: `scripts/render_broll.py` (ffmpeg). 오디오 제거, 1920×1080 크롭, 30fps.
  원본이 모자라면 **반복하지 않고** setpts 로 늘린다(1.25배까지, 넘으면 경고).
- 실사에도 우하단 출처를 굽는다 — 카드의 `PaperSource` 와 같은 위치·크기.
  이 컨테이너의 ffmpeg 에는 `drawtext`(libfreetype)가 없어서 PIL 로 만든
  투명 PNG 를 `overlay` 로 얹는다.

**ffmpeg 함정 3가지 (다 밟아봤음)**

1. 입력이 둘이면(`영상 + 출처 PNG`) 중간의 `-t` 는 **두 번째 입력**에 붙는다.
   길이는 반드시 출력 옵션 `-frames:v` 로 자르고, 뽑은 뒤 실제 길이를 검증한다.
2. 타임스케일을 Remotion 출력에 맞춰라(`-video_track_timescale 90000`).
   다르면(15360 vs 90k) concat 데먹서가 타임스탬프를 잘못 이어 붙여
   7분짜리가 **41분**으로 나온다. 파일 하나하나는 멀쩡해 보여서 놓치기 쉽다.
3. `-crf` 만 걸면 CG 디테일 때문에 5Mbps 원본이 30Mbps 로 부푼다.
   `-maxrate` 로 원본 수준의 상한을 건다.

- 국내 분양 홈페이지 다수가 **CUPID(WAF) JS 챌린지**를 건다. curl 로는 빈
  스크립트 페이지만 온다. `slowAES.decrypt(c,2,a,b)` = AES-128-CBC(nopad) 복호값을
  CUPID 쿠키에 넣고 `?ckattempt=1` 재요청하면 통과 —
  구현: `scripts/fetch_parkside_images.py` 의 `cupid_session()`
- 공식 조감도·투시도는 시행사 저작물. 보도·비평 인용 범위에서 쓰고 출처를 화면에 남긴다.

## 22. 컷 단위 피드백 3라운드 반영 — 더 파크사이드 서울 (2026-08-06)

실제 컷 이미지를 한 장씩 검수받아 고친 내용. **다음 영상부터 기본값으로 적용한다.**

### 22-1. 실측 도면 위 치수선 — `SectionPhotoCard`

도면(단면 렌더) 위에 지상/지하 층수를 얹을 때, 치수선을 화면 고정값으로 두면
"20층"이 가리키는 구간이 실제 타워 높이와 어긋난다. **도면 안의 비율**로 잡는다.

```
imageRatio  잘라낸 도면의 가로/세로
groundRatio 도면 안에서 지반(광장 레벨)이 놓인 세로 비율
groundY     그 지반을 화면 어느 높이에 둘지 — 이 한 값으로 전체가 정렬
topRatio    도면 안에서 타워 꼭대기      → 지상 치수선 위끝
botRatio    도면 안에서 지하 최하층 바닥 → 지하 치수선 아래끝
```

측정법: 도면에 5% 간격 가로 그리드를 그린 PNG 를 만들어 눈으로 읽는다.
(밝기 임계로 자동 검출하면 캡션 글씨가 잡혀서 틀린다.)
파크사이드 기준값 — `2.124 / 0.7132 / 596 / 0.212 / 0.885`.

### 22-2. 건물 실루엣은 "알아볼 수 있게" — `SkylineCompareCard` shape 프리셋

| shape | 형태 | 표식 |
|---|---|---|
| `parc1` | 높이 다른 판상 3동 | **지붕 위로 솟은 수직 기둥 3개** |
| `lotte` | 오목 곡선 세장 타워 | 비스듬히 잘린 왕관 + 첨탑, 밑변 W×0.46 |
| `cluster` | 공유 포디엄 + 중층 6동 | 저층부가 이어져 "한 덩어리 단지" |
| `plan` | 위에서 본 평면 | 가로/세로 **동시 스케일** = 면적 비교 |

- **높이가 비교 대상이 아닐 때는 높이를 같게 한다.** 사업비 비교에서 파크원/롯데를
  낮게 그리면 "건물이 낮다"로 읽힌다 → `value` 를 거의 1.0 으로 맞추고 금액은 `note`.
  부제에 `건물 높이가 아니라 사업비를 비교한다` 를 명시.
- `plan` 은 `value = √(면적비)`. 변 길이가 아니라 **넓이**가 실제 비율이 되게.
- 기준이 다른 수치를 나란히 둘 때는 `note` 로 단서 조항을 단다
  (예: `보도된 금액의 기준이 서로 달라 단순 비교는 참고용`).

### 22-3. 교환 관계는 정지 화살표 2개가 아니라 순서 모션 — `ExchangeMotionCard` (신규)

무엇을 **주고** 무엇을 **받는지**를 시간 순서로 읽히게 한다.

- ① 좌→우 화살표가 그어지고 픽토그램이 그 위를 건너간다 (18~66f)
- ② 다 건너간 뒤 우→좌 화살표가 반대로 그어지며 돌아온다 (86~134f)
- 이동체는 **가로 칩** `[픽토그램 | 이름 / 부제]`. 세로로 쌓으면 두 레인이 겹친다.
- 칩 배경을 캔버스색으로 깔아 선이 글자 뒤로 숨는다.
- **화살촉이 칩보다 앞선다** — 칩 중심 = 화살촉 − 방향×(칩폭/2 + 26).
  칩을 화살촉에 겹치면 화살촉이 사라져 방향이 안 읽힌다.
- 칩 폭은 문자열로 추정: 한글 1.0×fontSize, 그 외 0.56×fontSize.
- 좌표: 당사자 cx = 300 / 1620, 로고 top 262 h156, 이름 436~, 레인 y = 600 / 730.
- 글자는 **최소로**. 문장이 아니라 명사구 (`평택기지 / 3조 4,000억`, `4개 부지`).
- `left`/`right` 는 `logo`(png) 또는 `wordmark`(글자 박스) 둘 다 지원.

### 22-4. 레이아웃 미세 규칙 (전 카드 공통)

- **일정표(단일 레일)는 가로로도 가운데** — 레일 이름이 없으면 축 X0/X1 을
  400/1780 → 250/1670 으로 좁혀 화면 중심(960)에 맞춘다. 세로는 축에서 140px 위.
- **타일 열은 `scale` 과 `gapScale` 을 같이 준다** (`PhotoStepsCard`).
  타일만 80% 로 줄이면 간격이 자동으로 벌어져 오히려 더 흩어져 보인다.
  "N% 로 줄여" = `scale: N, gapScale: N`. 간격만 좁힐 땐 `gapScale: 0.5`.
- **한 장면을 밀어붙일 땐 카드가 아니라 `FullBleedCard`** — 사진 전체화면 +
  중앙 흰 글씨(92) + 부제(40). 캡션을 아래에 다는 것보다 중앙 헤드라인이 강하다.
- 그래프·수치 블록은 타이틀에서 최소 **200px** 아래에서 시작 (붙으면 답답함).

### 22-5. 실사(b-roll) 다양성

- 같은 프로젝트 필름만 반복되면 지루해진다. **연속 3컷 이상이면 외부 실사로 교체.**
- 프록시 환경에서 Pexels / Pixabay / Videvo 는 403. **Mixkit 은 통과** —
  `https://assets.mixkit.co/videos/{id}/{id}-720.mp4` (1080 은 403).
  720p → 1080p 업스케일: `scale=1920:1080:flags=lanczos,unsharp=5:5:0.6`.
- 출처 문자열은 클립마다 다르다 → `broll` 항목에 `credit` 을 넣고
  `render_broll.py` 가 클립별로 굽는다 (오버레이 PNG 는 credit 별로 캐시).

**사용자 확인 전이라 실제 영상에는 적용하지 않았다.** 샘플만 만들어 둠 —

### 22-6. 교환 카드 — 당사자와 화살표는 **같은 세로선** 위에 (2026-08-06 피드백)

로고를 위, 화살표를 아래로 떼어 놓으면 "누가 무엇을 주는지"가 한 줄로 안 읽힌다.
`ExchangeMotionCard` 는 당사자 블록(로고+이름+부제, 높이 272)의 **중심**과
화살표 두 레인의 중심을 같은 `CY`(560)에 맞춘다. 레인은 `CY ± 82`.

이렇게 하면 이동하는 칩이 출발 지점에서 로고를 덮으므로, 칩을 화살촉에 붙여 끌지 않고
**2단계**로 나눈다 — ① 화살표가 끝까지 그어지고(22프레임) ② 그 위를 칩이 건너간다(40프레임).
겹침 없이 순서가 그대로 읽힌다.

### 22-7. 자료 이미지는 "이름이 맞다"가 아니라 "건물이 맞다"로 검증

`eterno_*` 3장이 블로그 게재본이라 **다른 프로젝트 렌더**였는데도 이름만 보고 썼다.
수집 후 **반드시 눈으로 한 번 열어 확인**할 것. 공식 홈페이지가 있으면 블로그·기사
재게재본보다 공식 CDN 원본을 우선한다 (Zyro/Wix 계열은
`https://assets.zyrosite.com/<사이트키>/<파일명>` 로 원본이 그대로 열린다).

렌더 안에 박힌 분양 문구(간판·패널)는 평평한 면이면 지울 수 있다 —
글자 영역을 같은 패널의 **행 중앙값 색**으로 덮으면 이음매가 안 보인다.

### 22-8. 출처 캡션 규격 (2026-08-06 확정)

- 위치: **우하단 `right: 44, top: 1028`** — 화면 모서리에 최대한 붙인다.
- 크기: **23px**, A2Z Light, `letterSpacing 0.05em`, opacity 0.8.
- 문구는 **짧고 명료하게**. 접두어(`이미지:` `사진:` `도면:`)는 붙이지 않는다.
  기관·매체명 하나면 충분하다 — `서울시` `LH 매각공고` `분양공고` `청약홈` `보도 종합`.
- 예외는 CC 라이선스뿐. 저작자 표기가 의무라 `저작자 / 라이선스` 형태는 유지한다
  (`Wpcpey / CC BY-SA 4.0`). 여러 장이면 `A · B / CC BY-SA` 로 묶는다.
- 실사 클립도 같은 규격 — `render_broll.py` 가 PIL 로 굽는 좌표/크기를 맞춰 둔다.

### 22-9. 지반선을 기준으로 위/아래를 **갈라서** 붙인다

`SectionPhotoCard` 의 지상/지하 수치를 각자 치수 구간의 가운데에 두면, 지하 블록의
윗줄이 지반선을 넘어와 지상 수치와 붙어 보인다. 지상은 `groundY − 26` 에 **아래 정렬**,
지하는 `groundY + 26` 에 **위 정렬**. 기준선을 사이에 두고 확실히 갈린다.

### 22-10. 톤 면 위 보조문구

`ElevatorCard` 처럼 컬러 슬래브 위에 글자를 얹는 카드에서 `INK_SOFT`(회색)를 쓰면
면 색과 명도가 붙어 사라진다. **면은 옅게(0.34), 글자는 `INK` + opacity 0.72** 로.

## 25. 작업 방식 교정 — 좌표 손질에서 배치 규칙으로 (2026-08-06)

### 25-1. 문제 진단: 이번 세션에서 내가 한 수정의 정체

| 수정 | 실제로 한 일 |
|---|---|
| "출처를 더 우측 아래로" | `top: 1008 → 1028`, `right: 72 → 44` |
| "일정표를 가운데로" | `X0: 400 → 250` |
| "지하 7층을 아래로" | 가운데 정렬 → 지반선 기준 분리 |
| 단서 조항이 자막과 겹침 | `top: 900 → 302` |
| 축 라벨이 자막과 겹침 | `AXIS_Y: −40 → −66` |

전부 **좌표 상수를 손으로 민 것**이다. 그래서
- 하나 고치면 옆이 깨진다 (단서 조항을 올리니 부제와 붙었다 → 또 `268 → 302`)
- 렌더해 봐야 안다. 그래서 사용자가 대신 발견한다
- 같은 실수가 카드마다 반복된다 (자막 영역 침범을 세 카드에서 따로 냈다)

### 25-2. 교정: `layout.jsx`

y 를 상수로 박지 않고 블록을 **흘린다**.

```js
const L = flow({
  blocks: [
    {key: 'title', text: title, size: 68, maxWidth: 1600},
    {key: 'sub',   text: sub,   size: 36, maxWidth: 1400, gapBefore: 14},
    {key: 'note',  text: note,  size: 26, maxWidth: 1400, gapBefore: 30},
  ],
  top: 92, bottom: CONTENT_BOTTOM, gap: 24,
});
// L.title.top / L.sub.top / L.note.top … L._overflow
```

- 한글 1.0em / 라틴 0.56em 로 폭을 추정해 줄 수를 센다 (결정론적)
- 총 높이가 자막 안전영역을 넘으면 **간격부터 줄인다**. 그래도 넘치면 `_overflow` 로 알려 준다
- `fit(text, size, maxWidth)` — 라벨이 길어지면 글자만 줄여 레이아웃을 지킨다
- `<LayoutGuide show />` — 개발 중 자막 영역을 붉게 덮어 눈으로 확인

**앞으로 "조금 내려/올려"는 `gap` 하나를 바꾸는 일이다. 좌표를 만지지 않는다.**

### 25-3. 수정 프로토콜 (앞으로 지킬 순서)

1. 사용자의 지적을 **좌표가 아니라 규칙**으로 번역한다.
   "겹친다" → *어떤 두 블록이 같은 흐름에 없는가*
2. 고친 뒤 **`qa_check.py` 를 먼저** 돌린다. 사람에게 보여 주기 전에.
3. 같은 종류의 결함이 다른 카드에도 있는지 **전수로 확인**한다.
   (자막 영역 침범을 세 번 나눠 고친 게 이번 최악의 낭비였다)
4. 고친 규칙은 여기에 적는다. 다음 카드가 같은 실수를 반복하지 않게.

## 26. 새 영상 문법 — 움직이는 카메라 + 현장 주석 (`AnnotatedShotCard`)

### 26-1. 왜 필요했나

파크사이드 43컷을 다시 세어 보면 **전부 한 문법**이다 — 정지 화면에 요소가
페이드/스프링으로 얹힌다. 카메라가 움직이는 컷이 **0개**다.
B1M 이 항공샷·배치도에서 늘 하는 것은 그게 아니다.

### 26-2. 문법

```
① 넓게 잡고 시작 → ② 한 지점으로 밀고 들어감 → ③ 멈춰서 주석
→ ④ 끊지 않고 다음 지점으로 → 반복
```

주석은 **세 박자로 나눠서** 그린다. 동시에 뜨면 "표시"지만, 순서대로 오면
"가리키는 동작"이 된다.

| 순서 | 요소 | 프레임 |
|---|---|---|
| 1 | 표적 링이 밖에서 조여든다 (r 62→32) | 12 |
| 2 | 지시선이 그어진다 | 12 |
| 3 | 라벨이 **마스크로 밀려 나온다** (페이드 아님) | 12 |

### 26-3. 만들면서 잡은 함정

- **커버 계산**: 세로로 긴 이미지에 16:9 기준 배율을 곱하면 zoom=1 인데도 이미
  1.36배 확대돼 뭉갠다. `coverW = max(1920, 1080 × imageRatio)` 가 맞다.
- **카메라 클램프**: 가장자리 비트로 밀면 화면에 검은 띠가 생긴다.
  중심을 `[half, 1−half]` 로 묶는다. 실제 카메라가 플레이트 끝에 닿는 것과 같다.
- **주석 잔상**: 지나간 주석을 옅게 남겨 두면, 카메라가 움직인 뒤 **엉뚱한 건물
  위에 얹혀** 오독을 만든다. 직전 것만 이동 중에 사라지게 한다.
- **라벨 오버플로**: 가장자리 비트에서 라벨이 화면 밖으로 나간다.
  나갈 방향이면 반대쪽으로 자동으로 뒤집는다.
- **확대 상한**: 원본 폭 대비 1.6배를 넘기면 눈에 보이게 뭉갠다.
  1920px 소재면 `zoom ≤ 1.6`. 더 밀고 싶으면 더 큰 원본을 구해 온다.

### 26-4. 정지 화면에서 움직임을 만드는 두 가지

- **드리프트**: 멈춰 있는 동안에도 배율을 아주 천천히(200프레임에 1.5%) 민다.
  완전히 정지한 화면은 죽은 화면으로 읽힌다.
- **마스크 리빌**: 글자를 페이드로 띄우지 않고 `clipPath` 로 밀어 낸다.
  같은 12프레임이라도 "그려지는" 느낌이 난다.

## 27. 수치가 도착하는 방식 (`NumberIn`)

43컷을 다시 보면 **모든 숫자가 똑같이 나온다** — `interpolate` 로 값만 굴리고
통째로 페이드. 그래서 "8.1%"와 "11조"가 같은 무게로 읽혔다.

강조되는 수치는 세 겹으로 온다.

| 겹 | 동작 | 왜 |
|---|---|---|
| ① | 자릿수가 **아래에서 밀려 올라온다** (마스크, 페이드 아님) | 도착하는 느낌 |
| ② | 값이 굴러간다 (카운트업) | 크기를 체감 |
| ③ | **밑줄이 좌→우로 그어진다** | 확정 |

③ 이 있고 없고가 "표시된 숫자"와 **"선언된 숫자"**를 가른다. 강조(`hot`)에만 준다.
전부에 주면 아무것도 강조되지 않는다.

```jsx
<NumberIn to={1.67} start={14} decimals={2} unit=":1"
          size={148} underline={YELLOW} align="center" />
```

`display` 로 문자열을 직접 주면(예: `"185억 700만원"`) 카운트업을 건너뛴다 —
단위가 섞인 한국식 표기는 굴리면 오히려 안 읽힌다.

## 28. 절대 스케일 · 전후 와이프

### 28-1. `ScaleCompareCard` — "그래서 얼마나 큰데?"

`SkylineCompareCard` 는 **상대 비교**(value 0~1)라 서로를 재는 데는 맞지만
크기의 실감을 못 준다. 이 카드는 전부를 **실제 미터**로 놓는다.

- 왼쪽에 미터 눈금 축. 눈금 간격은 **자동**(라벨 간격 56px 확보) — 지정값을
  그대로 쓰면 500m 대 그래프에서 눈금이 13줄로 뭉갠다
- 바닥에 **사람 1.7m**. 최소 크기로 늘리지 **않는다** — 늘리는 순간 이 카드의
  존재 이유(정직한 스케일)가 깨진다. 안 보이면 그것도 정보고, 라벨이 대신 말한다
- 아는 것을 하나 섞는다: 남산 262m / 63빌딩 249m / 롯데월드타워 555m / 한 층 3.5m

### 28-2. `BeforeAfterCard` — 같은 프레임의 전/후

두 장을 나란히 놓으면 "사진 두 장"이지만, 손잡이가 한 화면을 훑고 지나가면
**같은 자리가 바뀐 것**이 된다. 정보량은 같은데 체감이 다르다.

- 손잡이는 **오른쪽에서 왼쪽으로**. 화면은 '이전' 으로 시작하고 '이후' 가
  오른쪽에서 밀고 들어온다 → 왼쪽=이전 / 오른쪽=이후 라는 읽기 순서가 라벨과 맞는다
- **한 번에 끝까지 가지 않는다.** 60% 에서 잠깐 멈췄다가 마저 간다.
  멈추는 순간이 있어야 눈이 비교를 한다
- 라벨은 손잡이를 따라다니지 않고 양쪽 끝에 **고정**. 따라다니면 못 읽는다
- **화각이 다르면 이 문법은 거짓말이 된다.** `align` 으로 미세 보정하고,
  그래도 안 맞으면 이 카드를 쓰지 않는다. (지금 파크사이드 자산에는 화각이
  맞는 전/후 쌍이 없다 — 샘플은 문법 시연용이고 실제 편에 넣으려면
  같은 지점·같은 화각의 사진을 새로 구해야 한다)

## 29. 반복을 없애는 건 카드 수가 아니라 **바탕과 배치** (2026-08-11)

### 29-1. 진단

갤러리 편 9컷을 세어 보면 카드 종류는 3종인데 **화면은 두 종류**였다.

| | 컷 | 실제 그림 |
|---|---|---|
| 종이 카드 | 4 | 크림 바탕 + 굵은 격자 + **가운데 정렬 타이틀** |
| 실사 | 4 | 풀블리드 + **가운데 흰 글씨** + 위아래 그라디언트 |

카드를 아무리 늘려도 이 두 껍데기를 안 바꾸면 화면은 안 바뀐다.
**카드 종류가 아니라 껍데기를 갈아 끼울 수 있게 만드는 게 답이다.**

### 29-2. 바탕 테마 3종 (`THEMES`)

| 테마 | 바탕 | 격자 | 쓰는 자리 |
|---|---|---|---|
| `paper` | 크림 #EFEAE3 | 80px | 기본. 설명·비교·결론 |
| `ink` | 딥 차콜 #242830 | 80px | 무게를 싣는 구간. 종이 사이의 쉼표 |
| `blueprint` | 네이비 #16233A | **40px + 5칸마다 굵은 선** | 도면·구조·위치 이야기 |

`<PaperBg theme>` `<PaperTitle theme>` `<PaperSource theme>` 로 통과시킨다.
카드는 `themeOf(theme)` 로 색을 받는다 — 모듈 상수 `INK` 를 직접 쓰면 테마가 안 먹는다.

### 29-3. 타이틀 정렬 2종

- `center` — 기본. 대칭 구성(좌우 비교, 3열)에 맞는다
- `left` — 왼쪽 정렬 + **짧은 옐로 룰**(96×8)이 위에 붙는다. 76px 로 조금 크다.
  챕터가 넘어간다는 신호로 쓴다

### 29-4. 실사 문구 처리 3종 (`broll.style`)

| style | 처리 | 쓰는 자리 |
|---|---|---|
| `center` | 화면 한가운데 흰 글씨 + 세로 그라디언트 | 선언·전환 |
| `lower` | **좌하단 + 옐로 룰**. 위쪽이 비어 사진이 살아 있다 | 설명·부연 |
| `band` | **하단 옐로 밴드 + 검은 글씨** | 못박을 때. 한 편에 한두 번만 |

`band` 는 자막 안전영역(하단 260px) **바로 위**에 놓아 자막과 안 겹치게 한다.

### 29-5. 결과

갤러리 편 9컷 — 화면 종류 **2종 → 6종**.
크림 가운데 / 네이비 좌측 / 다크 좌측 / 실사 가운데 / 실사 좌하단 / 실사 옐로밴드.

`qa_check` 의 반복 검사도 카드 이름이 아니라 **(카드 + 바탕 + 정렬)** 조합으로 세고,
실사 문구 처리가 전부 같으면 따로 경고한다.

> 남은 일: 아직 `theme` 을 받는 카드는 `SplitCard` · `TrackRecordCard` 둘뿐이다.
> 나머지 카드는 모듈 상수 `INK`/`INK_SOFT` 를 직접 써서 크림 고정이다. 쓰는 순서대로 옮긴다.

## 30. 학습 규칙 3종 (2026-08-11 · 아직 적용 안 함)

사용자 지시로 **규칙만 새긴다. 기존 영상에는 반영하지 않는다.**
다음 편부터 기본값으로 쓴다.

### 30-1. 브랜드·기업은 로고나 대표 이미지로 — **누끼는 필수**

이름만 크게 쓰는 건 최후의 수단이다. 회사가 나오면 마크가 나와야 한다.
그리고 **로고는 흰 네모째로 얹으면 안 된다.** 종이 카드든 다크든 네모가 그대로 보인다.

누끼 난이도 3단계 — 이 환경에서 되는 것과 안 되는 것:

| 단계 | 대상 | 방법 | 현재 |
|---|---|---|---|
| ① | Commons `.svg` 로고 | PNG 썸네일이 **이미 알파를 갖고 온다** | **됨** (국방부 투명 63% · 서울시 21% 확인) |
| ② | 흰·단색 바탕 로고 | **가장자리 플러드필** + 색 허용오차 26 | **됨** (numpy만으로. 원본 알파 대비 0.2%p 오차) |
| ③ | 실사에서 피사체 분리 | rembg + onnxruntime | **안 됨** (미설치, 모델 가중치 별도) |

②에서 단순 임계(밝기>240 → 투명)를 쓰면 **로고 안쪽 흰 부분까지 뚫린다.**
서울시 휘장이면 글자 사이가 다 날아간다. 배경이라는 걸 알 수 있는 유일한 신호는
**"가장자리와 이어져 있다"** 는 것뿐이라, 반드시 플러드필로 간다.

`convert('RGB')` 로 눕히지 말 것 — 알파가 검은 박스가 된다 (국방부 엠블럼 때 겪음).

### 30-2. 줄글은 반드시 도식·그래프·예시로 바꾼다

"말로 설명하고 화면엔 글자만" 이 제일 나쁘다. 문장 유형별로 갈 곳이 정해져 있다.

| 줄글이 하는 말 | 화면 문법 |
|---|---|
| 수치 두세 개 비교 | `SkylineCompareCard` / `RatioCard` |
| "얼마나 큰가" | `ScaleCompareCard` (실제 미터 + 사람 1.7m) |
| 순서·단계 | `PhotoStepsCard` / `TimelineRailCard` |
| 두 주체가 주고받음 | `ExchangeMotionCard` |
| 둘로 갈리는 대비 | `SplitCard` |
| 회사 이력·레퍼런스 | `TrackRecordCard` |
| 위치·배치를 짚음 | `AnnotatedShotCard` (카메라가 훑으며 주석) |
| 전/후가 바뀜 | `BeforeAfterCard` |
| 수치 하나가 핵심 | `BigStatsCard` + `NumberIn`(밑줄로 확정) |
| 추상적 개념 | **예시로 바꾼다.** 아는 것 옆에 세우거나(남산 262m), 실물 사진을 붙인다 |

원칙: **한 컷에 정보 하나.** 두 개를 넣고 싶으면 컷을 쪼갠다(§9-1).
그리고 위 표에 안 맞으면 **그 문장은 화면이 아니라 내레이션만으로 가는 게 낫다** —
억지 도식은 없는 것보다 나쁘다.

### 30-3. 롱폼이지만 말이 타이트하다 → 화면은 계속 바뀐다

이미 §9 에서 컷 밀도를 평균 4.9초로 내렸다. 여기에 더할 것:

- **한 컷 안에서도 멈추지 않는다** — 카드는 요소가 순차로 도착하고(§27),
  실사·사진은 카메라가 미세하게 움직인다(드리프트 200프레임당 1.5%)
- **연속 두 컷이 같은 껍데기면 안 된다** — 카드·바탕·정렬 중 하나는 바꾼다(§29)
- 실사 문구 처리도 `center` / `lower` / `band` 를 번갈아 쓴다
- `qa_check` 가 (카드+바탕+정렬) 조합과 실사 문구 처리를 세고 있으므로,
  경고가 뜨면 그 자체로 "화면이 안 바뀌고 있다"는 신호다

### 30-4. 다음에 만들 것 (이 규칙을 실행하려면)

1. `fetch_sources.py --logo` — 로고 검색 + 누끼(①②) + 알파 PNG 저장까지 한 번에
2. `BrandCard` — 누끼 로고 + 한 줄 + 대표 이미지. 회사 소개 전용
3. `plan_from_script.py` 의 카드 추천 표에 §30-2 매핑을 그대로 반영

3개 다 만들었다 (§31-6). 이제 §30 은 규칙이 아니라 기능이다.

### 31-4. 그래픽 — 썸네일 48장에서 센 것

이게 이번 분석에서 제일 크게 건진 부분이다. 실제로 반복되는 건 네 개뿐이다.

1. **검정 상자 + 흰 대문자.** 배경이 뭐든 무조건 읽힌다.
   아래를 통째로 어둡게 까는 스크림은 **거의 안 쓴다** — 상자가 그 일을 한다.
   내 카드는 지금까지 스크림 + 그림자로 버텼는데, 그건 사진을 죽인다.
2. **2단 라벨** — 작은 한정어 줄 + 큰 본체 줄.
   `WORLD'S LARGEST NAVAL BASE` / `$4BN`, `THE HIDDEN COST OF` / `DATA CENTRES`
3. **손으로 그린 듯 휜 화살표.** 48장 중 가장 자주 나온 도구.
   굵기가 일정한 지시선은 '도면'이 되고, **끝으로 갈수록 얇아지면 '손짓'**이 된다.
4. **점선 원** — "여기가 비었다 / 여기가 문제다" (`MISSING…`)

그리고 배치: 라벨은 **하늘·물처럼 비어 있는 데** 앉는다. 좌하단 고정이 아니다.
사진마다 자리가 다르다.

글자 내용은 둘 중 하나뿐이다.
- **수치 + 단위** — `$2BN` `359M HIGH` `30CM PER HOUR` `600 METRES UNDERGROUND` `320 KM/H`
- **한 단어 판정** — `ABANDONED.` `BROKE.` `DOOMED?` `CHEATING?`

부호를 의도적으로 쓴다. **마침표 = 끝났다. 물음표 = 아직 모른다.
말줄임표 = 이어진다** (`THIS GUY…` / `…IS THIS IT?`).

가장 강한 한 장은 취소선이었다: ~~`30 HOURS`~~ / `6 HOURS`.
두 수치를 나란히 놓는 비교와 **동작이 다르다** —
비교는 "어느 쪽이 큰가"를 묻고, 취소선은 **"옛 값은 죽었다"를 선언한다.**

얼굴·리액션샷은 **한 장도 없다.** 건물이 주인공이다.

### 31-9. 카드 17종 테마 개방 (§31-7 4 완료)

`SplitCard`·`TrackRecordCard` 만 `theme` 을 받고 나머지는 크림 고정이었다.
17종을 열었다 — 이제 51종 중 실사 카드를 뺀 전부가 `paper`/`ink`/`blueprint` 를 받는다.

기계 변환이 두 군데서 걸렸다.

1. **모듈 단위 헬퍼가 토큰을 쓴다.** `Silhouette`·`Figure`·`Body`·`Pict`·`Icon`·`Slab`

   `T = THEMES.paper` 기본값 prop 을 주고 호출부에서 넘긴다.
   본문만 훑는 정규식으로는 못 잡으니 **함수 경계로 잘라서** 따로 처리해야 한다.
2. `SkylineCompareCard` 는 이미 `dark` prop + `palette(dark)` 를 쓰고 있었다.
   `themeOf(theme, dark)` 로 합치고 `palette` 분해대입은 지웠다.
   `<PaperBg dark={dark} />` 처럼 이미 인자가 있는 호출은 치환 정규식이 못 잡는다 — 별도 처리.

**회귀 검증**: 실제 파크사이드 props 로 14종을 `theme` 없이 렌더해
변환 전후를 픽셀 비교했다. **14종 전부 최대차 0.** 납품한 두 편은 영향 없다.
테마 적용 검증은 `ink` 로 렌더해 크림(#EFEAE3) 잔존 면적을 쟀다 — 0.
(허용오차는 4 이하로 잡을 것. `ink` 테마 글자색 `#F2F0EC` 와 최대 9밖에 차이가 안 나
tol 14 로 재면 글자를 전부 "안 바뀐 크림"으로 오탐한다.)

## 32. B1M 내부 프레임 분석 (2026-08-11 · 780프레임)

썸네일(§31-4)은 **표지**라 화면 안에서 실제로 쓰는 문법과 다르다.
이번엔 영상 **내부**를 봤다.

**받은 방법과 한계.** 스토리보드 스프라이트는 서명 파라미터가 필요해 403이다.
대신 유튜브가 자동 생성하는 `hq1/2/3.jpg` — **영상의 25% / 50% / 75% 지점 프레임** —
을 최근 4년 260편에서 받았다. **780프레임.**
연속 프레임이 아니라서 **모션은 여전히 직접 측정할 수 없다.**
아래에서 "쟀다"고 쓴 것은 정지 프레임에서 읽은 것이고,
모션 수치는 내가 정한 값이다 — 구분해서 적는다.

780장을 평탄도·채도·밝은면적·엣지밀도로 분류해 그래픽 판만 추려 봤다.

### 32-1. 기사 인용 — 원문을 통째로 놓고 **형광펜**을 긋는다

가장 크게 건진 한 장 (Chicago Sun-Times, 2022-04-26 인용):

```
                CHICAGO SUNTIMES APRIL 26TH, 2022     ← 대문자 볼드, 가운데, 작게
 [흑백 인물]    ▒Ensuring the safety of the judges and employees who work in the
                Dirksen Courthouse must be a top priority▒ in light of the acute
  Dick Durbin   security threats they face. After an individual was charged in
United States   2004 and convicted of attempting to destroy the courthouse with
   Senator      a truck bomb, the federal General Services Administration…
```

- 순백 바탕 · 검정 **세리프** 본문 · 단 폭은 화면의 절반 조금 넘게
- 발언자는 **흑백** 세로 사진 + 이름(볼드) + 직함(회색). 컬러면 인물이 기사보다 세진다
- 강조는 **밑줄이 아니라 형광펜**. 연노랑이 두 줄에 걸쳐 글자를 감싼다

**핵심은 "원문을 통째로 놓는다"는 것이다.**
인용구만 크게 뽑으면 *내가 고른 말*이 되고, 원문 덩어리 위에 형광펜을 그으면
*기사에 그렇게 적혀 있다*가 된다. 부동산 채널에서 신뢰가 갈리는 지점이 정확히 여기다.
기존 `QuoteCard`/`NewsQuoteCard` 로는 이걸 못 한다.

### 32-2. 그 밖의 인용 방식

- **방송 화면은 프레임째** 넣는다. France24·TalkTV 화면을 하단 뉴스 티커까지 그대로.
  잘라내지 않는 것 자체가 출처 표시다. 우하단에 `COURTESY OF …`
- **인터뷰는 떠 있는 판**으로 — 어두운 바탕 위에 흰 테두리 직사각 + 그림자
- 옛 자료 사진은 **크림 틴트**를 입혀 "지금 것이 아니다"를 말한다

### 32-3. 도해 — 얕은 3D 축측 + 2색

두 종류가 반복된다.

1. **축측 도해**: 파란 단색 덩어리 + 격자 바닥판. 렌더가 아니라 **면 세 개**(윗·좌·우)를
   같은 색의 명도만 바꿔 칠한 것. 조명을 흉내 내면 그 순간 도해가 아니라 렌더가 된다
2. **단면 도해**: 파란 배경 + **주황** 채움 (보색 2색만) + 흰 **점선**으로 "원래 계획",
   실선으로 "실제". 격자 위에 얹는다

왜 얕은 3D 인가 — 평면 도형은 "기호"로, 실사 렌더는 "완성 이미지"로 읽힌다.
그 사이에 **"설명하려고 만든 모형"** 이라는 자리가 있고 축측 도해가 거기다.
모형이라 틀려도 되고, 그래서 과감하게 단순화할 수 있다.

그리고 이런 판 구석에 늘 작게 적혀 있다 — `FOR ILLUSTRATIVE PURPOSES ONLY`.
렌더 인용에는 `CREATED IN UNREAL ENGINE`. **정직함이 장치로 박혀 있다.**

### 32-4. 사진 위 그래픽

- **치수선** — 굴착면에 흰 세로 양방향 화살표 + 양끝 캡 + `15M`.
  라벨 화살표(§31-4)와 **역할이 다르다**: 저건 가리키는 것, 이건 **재는 것**.
  그래서 손맛을 주면 안 된다 — 곧고 굵기가 일정해야 한다
- **큰 수치를 반투명 흰색으로** 사진 위에 통째로 (`306M`). 상자 없이
- 작은 라벨은 **흰 상자 / 검정 글씨**도 쓴다 (`BANK OF CHINA BUILDING`).
  §31-4 에서 "검정 상자 + 흰 글씨"라고만 적었는데 **반대도 쓴다**. 배경 밝기에 따라 고른다
- 로케이션 라벨은 우상단, 출처는 우하단. 위치가 고정돼 있다

### 32-5. 배경 — **멎는 순간이 없다**

정지 프레임으로는 확인할 수 없는 항목이라, 여기부터는 판단이다.
다만 확실한 건 B1M 화면에 **완전한 정지 판이 거의 없다**는 것이고,
도표 카드에도 뒤에 실사가 깔려 있는 프레임이 계속 나온다.

내가 정한 값 (`LiveBackdrop`):
- **5초(150프레임)에 배율 +3.5% · 이동 1.4%.**
  그보다 크면 "움직인다"고 알아채고, 작으면 안 느껴진다
- **절대 이징하지 않는다.** 가감속이 붙는 순간 "애니메이션"이 된다.
  등속이라야 카메라가 걸려 있는 느낌이 난다
- 사진은 주인공이 아니라 **질감**이므로 테마색 베일로 0.88~0.92 눌러 놓는다
- 방향은 6종을 돌려 쓴다. 연속 컷이 같은 방향으로 밀리면 그것대로 눈에 띈다

### 32-6. 이번에 만든 것

| 만든 것 | 근거 |
|---|---|
| `Highlighter` — 여러 줄 형광펜, 왼→오른 한 획 | §32-1 |
| `DimLine` — 치수선(양끝 캡 + 양방향 촉) | §32-4 |
| `ArticleCard` — 매체+날짜 / 흑백 인물 / 원문 + 형광펜 + dim | §32-1 |
| `LiveBackdrop` + 모든 종이 카드의 `bg` prop | §32-5 |
| `IsoDiagramCard` — 얕은 3D 축측 + 치수선 + 면책 문구 | §32-3 |
| 명조 본문 폰트 (Nanum Myeongjo, OFL) | §32-1 |

**형광펜을 한 획으로 긋는 법.** 여러 줄에 걸친 인라인 하이라이트를 왼쪽에서
오른쪽으로 이어 긋는 게 관건인데, `box-decoration-break: clone` 을 쓰면
줄마다 따로 칠해져 **전부 동시에 차오른다.** 기본값인 `slice` 를 그대로 두면
브라우저가 여러 줄을 한 띠로 이어 붙여 칠하므로 1행을 끝내고 2행으로 넘어간다.
`background-size: {p*100}% 100%` 하나로 끝난다.

**축측 도해에서 겪은 것.** 지하(h<0)를 지상과 같은 식으로 그리면 윗면이 바닥에 붙어
**뒤집힌 상자**가 된다. 윗면을 지면(y=0)에 두고 벽을 아래로 내려야 한다.
그리고 그리는 순서를 `x+z` 로만 잡으면 **지하 슬래브가 지상 타워를 덮는다** —
지하를 먼저 그려야 지상이 얹힌 것으로 읽힌다.

### 32-7. 아직 못 한 것

- **모션은 여전히 측정 못 했다.** 워치 페이지·자막·스토리보드가 전부 봇 차단이다.
  §32-5 의 수치는 잰 값이 아니라 정한 값이다. 실제 편에 얹어 보고 조정할 것
- 단면 도해(§32-3 ②)는 아직 카드가 없다. `IsoDiagramCard` 의 형제로 만들 것
- 지도 위 경로선·국기 합성(§31-4, §32) 도 없다

## 33. 지도와 실사 (2026-08-11)

§32 까지는 "어떻게 그리나" 였다. 여기는 **뭐가 없었나** 다.
샘플을 만들고 나서야 두 구멍이 분명해졌다.

### 33-1. 부동산 채널인데 **지도가 한 장도 없었다**

파크사이드 43컷에도, 갤러리 편에도 없다.
"용산 유엔사 부지" 라고 말해도 그게 서울 어디인지 화면이 답을 안 한다.
**위치를 말로만 하면 아는 사람만 알아듣는다.** 그건 설명이 아니다.

`scripts/fetch_map.py` — 좌표 → 타일 스티칭.

| 스타일 | 타일 | 언제 |
|---|---|---|
| `light` | CARTO Positron | **기본값.** 회색조·최소라 종이 톤과 그대로 붙는다 |
| `dark` | CARTO Dark Matter | 먹 테마 |
| `osm` | OpenStreetMap 기본 | 색이 많아 그래픽을 얹으면 시끄럽다. 지형이 필요할 때만 |

라이선스는 **ODbL, 표기 의무**다 (`© OpenStreetMap contributors`, CARTO 는 `© CARTO` 도).
`CREDITS.md` 에 자동으로 들어가고, 화면 표기도 카드가 기본으로 찍는다.
타일 서버 예의로 한 번에 48장까지만 받고 요청 사이에 80ms 쉰다.

`MapCard` 의 핵심은 **위경도로 핀을 찍는다**는 것이다.
`fetch_map.py` 가 `bounds` 를 찍어 주고 카드가 메르카토르로 환산한다.
픽셀로 맞추면 지도를 다시 뽑을 때(줌만 바꿔도) 전부 다시 맞춰야 한다.

순서 — 넷을 동시에 띄우면 지도가 아니라 "정보가 잔뜩 얹힌 그림"이 된다.
```
① 넓게 깔고 천천히 밀고 들어간다   ← "여기가 어디인지"를 먼저
② 영역이 칠해진다                  ← 대상 부지
③ 경로선이 그어진다                ← 동선·연결
④ 핀이 떨어지고 라벨이 붙는다
```

**핀 라벨 상자는 늘 검정이다.** 핀이 노란데 라벨까지 노라면 강조가 둘로 갈린다.
게다가 노란 영역 위에 노란 라벨을 얹으면 그냥 안 읽힌다 (첫 렌더에서 확인).
옐로는 '표시된 대상' 하나에만 쓴다 (§31-4).

### 33-2. 실사가 안 들어간 진짜 이유

B1M 은 화면의 대부분이 실사고 도표가 양념인데, 내 결과물은 정반대다.
이유는 취향이 아니라 **마찰**이었다 —
Commons·Openverse·Mixkit 은 영어로 찾아야 결과가 나오고
("역삼동 오피스텔" 0건 / "Gangnam office building" 수백 건),
그 검색어를 매번 손으로 만들어야 했다. 그래서 안 넣었다.

`scripts/suggest_queries.py` — 장면 텍스트 → 영어 검색어.
분야가 부동산·건설 하나라 **도메인 사전 33줄로 충분하다.** 번역 API 가 필요 없다.
파크사이드 32장면에 돌려 보니 실사가 필요한 21장면 중 **19개**에서 검색어가 나왔다.
못 뽑은 2개는 "책 외판원으로 사회생활을 시작했다" 류 — 애초에 스톡에 없는 소재다.

사전을 쓸 때의 원칙: **구체적인 사물로 쓴다.**
`development` 같은 추상어를 넣으면 회의실 악수 사진만 나온다 —
이 채널에서 제일 쓰기 싫은 그림이다.

그리고 `SELF_SUFFICIENT` — 이미 화면이 꽉 차는 카드(도표류)는 실사를 안 찾는다.
안 그러면 21장면이 32장면이 되고 다시 안 쓰게 된다.

## 34. 무엇이 화면을 채우는가 (2026-08-12)

샘플을 두 번 만들고 나서 잰 것들. §31~33 이 "어떻게 그리나"였다면 여기는 **비율과 흐름**이다.

### 34-1. 실사 대 도표 — 구조가 뒤집혀 있었다

B1M 내부 프레임 780장을 평탄도·채도·엣지밀도로 분류했다.

| | 실사 | 도표 판 |
|---|---|---|
| **B1M** | **75~90%** | 10~25% |
| 파크사이드 | 21% | 79% |
| 갤러리 | 35% | 65% |
| 첫 샘플 | 4% | 96% |

판정 임계에 따라 흔들려서(그래픽 비율이 임계 0.70→0.82 에서 27%→4%) **범위로 적는다.**
그래도 결론은 임계와 무관하다 — **내 결과물은 정반대다.**

도표가 주인공이면 "설명 슬라이드"가 되고, 실사가 주인공이어야 "다큐"가 된다.
이건 취향 문제가 아니라 장르 문제다.

그래서 경고만 하지 않고 **플래너 기본값을 바꿨다** (`LIVE_TARGET = 0.45`).
도식이 안 나오는 컷을 **긴 것부터** 실사로 넘긴다 —
도표가 붙은 컷을 실사로 바꾸면 정보가 사라지지만,
종이 카드로 때우던 컷은 애초에 화면이 비어 있었다.
파크사이드 스크립트 재계산: **21% → 45.8%.**
45%는 B1M 에 한참 못 미치지만 CC 소재만 쓰는 조건에서 현실적인 첫 목표다.

`qa_check` 에 `check_live_ratio` 추가 — 35% 미만이면 경고.

### 34-2. 컷 연속성 — `MotionShell` 이 있는데 안 쓰이고 있었다

하드컷으로만 이으면 컷마다 화면이 "다시 시작"한다.
B1M 은 나가는 컷과 들어오는 컷이 **같은 방향으로 흐른다.**
`MotionShell` 이 진입·퇴장 푸시를 이미 할 수 있었는데 —
**플래너가 `motion` 을 안 넣어서 한 번도 안 쓰였다.** 도구가 있어도 기본값에 없으면 없는 것이다.

이제 플래너가 자동으로 넣는다. 방향은 **2컷마다** 바꾼다 —
매 컷 바꾸면 좌우로 튀어 멀미가 나고, 계속 같으면 흐름이 아니라 관성이 된다.
실사 컷은 `MotionShell` 을 안 거쳐 흐름을 끊는데, 그게 오히려 호흡이 된다.

**여기서 두 가지를 배웠다** (샘플 v2 를 이어 붙여 프레임을 뜯어보고 나서):

1. **밀기만 하면 반대쪽 가장자리에 바탕색 띠가 드러난다.**
   그 띠가 컷마다 번쩍여서 전환이 오히려 더 눈에 띈다.
   → 밀린 만큼 스케일을 키워 화면을 계속 덮는다 (`cover = 1.012 + max(2dx/1920, 2dy/1080)`).
2. `MotionWrap` 이 `props.image` 유무로 바탕색을 정하고 있었다.
   **`MapCard` 도 `image` 를 받는데 밝은 카드라 검은 띠가 생겼다.**
   → 어두운 전면 실사 카드를 이름으로 고정 (`DARK_CARDS`).

### 34-3. 단면 도해 (§32-7 잔여)

`SectionDiagramCard` — 파란 바탕 + **주황 채움** + 흰 **점선**(원래 계획).

`IsoDiagramCard` 와 역할이 다르다.
- **축측** = "이게 어떻게 생겼나" (덩어리·배치)
- **단면** = "얼마나 깊나 / 어디를 얼마나 팠나" (깊이·경계)

좌표는 **실제 단위**로 준다 (x=거리 m, y=표고 m, 음수가 지하).
"지하 7층 = −28m" 을 그대로 넣으면 축이 알아서 맞는다.

색은 **두 개뿐이다.** 지층마다 색을 다르게 하면 지질도가 되지 개념 설명이 안 된다 —
파낸 곳과 안 판 곳만 구분되면 된다.
실선(실제) vs 점선(계획)도 **선 종류로** 가른다. 색을 또 쓰면 셋이 된다.

첫 렌더에서 띠 라벨이 치수선 라벨 위에 얹혔다 → 띠 라벨은 왼쪽에 붙이고,
`DimLine` 은 오른쪽 끝에서 라벨을 안쪽으로 뒤집게 고쳤다.

### 34-4. 지도 좌표는 손으로 찍지 않는다

첫 지도에서 **용산공원 핀이 1.5km 어긋났다.** 내가 좌표를 눈대중으로 넣어서다.
지도는 틀리면 바로 티가 나고, 한 번 틀리면 **그 영상의 다른 숫자까지 의심받는다.**
부동산 채널에서 이건 그래픽 결함이 아니라 신뢰 결함이다.

`fetch_map.py --find "주소·지명"` 으로 OSM Nominatim 지오코딩을 붙였다.
이제 좌표는 전부 여기서 나온다.

**한국에서 주의할 것 두 가지** (실제로 겪음):
1. **지번은 동 중심점으로 뭉개진다.** "이태원동 22-34" 를 넣으면 필지가 아니라
   이태원동 중심이 나온다. 필지가 필요하면 **근처 랜드마크**(역·구청·학교)로 잡는다
2. **OSM 에 없는 대상은 없는 것이다.** "유엔사부지" · "더파크사이드서울" 은 0건이다.
   그럴 때 **폴리곤을 그려 넣지 않는다** — 없는 근거를 그린 것이 되기 때문이다.
   검증된 랜드마크에 핀만 찍고, 라벨로 "녹사평역 일대"처럼 범위를 밝힌다

### 34-5. `BigStatsCard` 세로 중앙

`top: 464` 로 박혀 있어 아래가 텅 비었다. 가로만 가운데면 "가운데 정렬"이 아니라
"위쪽에 붙은 가운데"다. 쓸 수 있는 띠(타이틀 아래 ~ 자막 안전영역 위)의
한가운데에 블록을 놓도록 고쳤다.

## 35. Cleo Abram (Huge If True) 분석 (2026-08-13 · 60편)

사용자 요청으로 **"스크립트를 3D·구조적 이미지로 바꿔 설명하는 방식"** 을 배우러 갔다.
B1M 과 같은 방법으로 쟀다 — 카탈로그 61편(전량), 내부 프레임 180장, 썸네일 60장.
**이번 절은 학습 기록이다. 아직 구현하지 않았다.**

### 35-1. 규모와 길이

| | Cleo | B1M |
|---|---|---|
| 편수 | **61편** (4년) | 620편 (11년) |
| 롱폼 길이 중앙 | **15:47** → 최근 1년 **19:39** | 15:16 |
| 조회 중앙 | **1.9M** (최근 1년 3.3M) | 1.1M |
| 최고 | 13.0M | — |

편수는 B1M 의 10분의 1인데 조회 중앙은 2~3배다. **적게 만들고 크게 터뜨린다.**
그리고 둘 다 길어지는 중이다 — 길이를 줄일 이유가 없다는 §31-1 결론을 한 번 더 확인해 준다.

### 35-2. 화면 구조 — B1M 과 정반대인 것들

**① 화자가 항상 화면에 있다.** B1M 은 얼굴이 한 장도 없는데 (§31-4),
Cleo 는 내부 프레임 180장 중 대부분에 본인이 나온다.
현장(F1 개러지·CERN 터널·1940년대 비행기 조종석·수술실)에 직접 가서 말한다.

**② 화면비가 2.39:1 시네마스코프다.** 프레임 **180장 전부**, 위아래 합쳐 **25%** 가 레터박스.
16:9 를 꽉 채우는 B1M 과 정반대의 선택이다.
그리고 이건 우리에게 중요하다 — 자막 안전영역(`CONTENT_BOTTOM = 820`)을 쓰는 대신

### 35-3. **3D·구조 설명의 실제 문법** — 여기가 핵심

썸네일과 프레임에서 반복되는 것은 네 가지다.

1. **레이어 벗기기 (peel-away).**
   남극 편이 대표 — 3D 지형에서 **얼음층을 통째로 들어 올려** 아래 암반을
   표고 색(파랑→초록→빨강)으로 보여 준다. 점선으로 들어 올린 층의 원위치를 표시한다.
   "덮여 있던 것을 벗겨서 보여 준다" 는 동작 자체가 설명이다.

2. **잘라서 속 보이기 (cutaway).**
   콜라 초심층 시추공 편 — 지구 단면을 세로로 잘라 지표(초록) · 지각(갈색) ·
   마그마(주황)를 층으로 쌓고, **가느다란 흰 선 하나**로 시추공을 그은 뒤 `12.2 KM`.
   내 `SectionDiagramCard`(§34-3)와 **구조가 같다.** 다른 건 질감뿐이다 —
   내 건 평면 채움, Cleo 는 그라디언트·명암이 들어간 3D 렌더.

3. **대상을 오려내 강조 (isolate).**
   흰 **점선 테두리**로 대상을 감싸 배경에서 떼어 낸다 (Atlas 로봇 · 뇌).
   내 `DashCircle`(§32-4)의 사각형 판이다.

4. **1인칭 스케일.** 본인이 대상 옆에 서거나 들고 있다.
   내 `ScaleCompareCard` 의 "사람 1.7m"(§28)를 **실사로** 하는 것과 같다.

그리고 **본인을 누끼로 따서 그래픽 안에 합성한다** — 스튜디오에서 찍은 몸을
3D 장면 안에 세운다. 우리 `fetch_sources.py --logo` 의 누끼와 같은 기술이다.

### 35-5. **이 환경에서 실제 3D 렌더가 된다** (확인함)

`@remotion/three` 4.0.502 + `three` 0.185.1 이 설치돼 있고,
`ThreeCanvas` 로 조명·재질·그림자가 있는 실제 WebGL 렌더가 **헤드리스에서 통과했다.**

카메라가 실제로 돌고 층이 실제로 들려 올라간다.

**다만 한계는 분명하다.**
- 모델이 없다. 박스·실린더·평면·압출(extrude) 같은 **원시 도형과 데이터 기반 지형**만 만들 수 있다.
  건물 3D 모델이나 F1 차량 같은 건 못 만든다
- 렌더 시간이 는다 (실측 필요)
- Cleo 의 질감(글로우·피사계심도·HDRI)까지 흉내 내면 "설명하려고 만든 모형"(§32-3)이 아니라
  어설픈 렌더가 된다. **단색 + 명암 3면**이라는 우리 원칙은 3D 로 가도 유지하는 게 맞다

### 35-6. 가져올 것 / 안 가져올 것

**가져올 것**
- **레이어 벗기기** — 부동산에 그대로 맞는다. 지상/지하를 들어 올려 분리, 층별 용도를 벗겨 보기
- **cutaway 3D** — `SectionDiagramCard` 의 3D 판. 지하 7층 굴착을 실제로 잘라서 보여 준다
- **점선 테두리 isolate** — 사진 위에서 대상 하나를 떼어 낸다
- **질문형 제목** — 최상급 대신. 우리 소재(용적률·낙찰가·규제)는 질문으로 열기 좋다
- **옐로 상자 + 검정 글씨** 라벨 변형 — 밝은 배경에서 검정 상자보다 낫다

**안 가져올 것**
- **화자 출연** — 이 채널은 내레이션 기반이고, 본인이 나오는 건 기획의 문제지 그래픽의 문제가 아니다
- **2.39:1 레터박스** — 자막을 편집에서 따로 붙이는 방침과 충돌한다.
  다만 "레터박스 띠를 자막 자리로" 는 나중에 다시 볼 만하다
- **네온 그린** — 채널 옐로가 이미 있다. 강조색이 둘이면 강조가 아니다
- **화면에 구운 자막** — 방침상 제외

### 35-7. 가져오기로 한 것 구현 (2026-08-15)

§35-6 의 "가져올 것" 을 만들었다. 안 가져오기로 한 것(화자 출연·레터박스·네온 그린·구운 자막)은 그대로 뺐다.

| 만든 것 | 근거 |
|---|---|
| `LayerPeelCard` — **실제 three.js**. 층이 벗겨진다 | §35-3 ① |
| 같은 카드 `cut: true` — 앞 절반을 덜어 단면을 낸다 | §35-3 ② |
| `DashBox` + `AnnotatedShotCard.pointer='box'` | §35-3 ③ |
| 옐로 상자 + 검정 글씨 라벨 (`StampLabel hot`) | §35-2 ③ |
| 질문형 타이틀 ("왜 지하로 내려갔을까?") | §35-4 |

**렌더 비용은 걱정할 게 아니었다.** 스틸 1장 기준 3D 3.9초 · SVG 축측 3.6초 —
차이가 거의 없다. 병목은 Remotion 번들링이지 GPU 가 아니다.

만들면서 배운 것 네 가지.

1. **벗겨질 때 위로만 자라면 안 된다.** 처음엔 각 층을 `lift * i` 만큼 위로 올렸더니
   벗길수록 스택이 위로 커져 **타이틀을 덮었다.** 오프셋 평균을 되빼서
   무게중심을 제자리에 두면 위아래로 고르게 벌어진다.
2. **카메라 겨냥점을 옮기면 라벨이 도형에서 떨어진다.**
   R3F 기본 카메라는 늘 원점을 본다. 내 투영(`project3d.js`)만 다른 점을 겨누면
   둘이 어긋난다. 겨냥점은 원점에 두고 **모델을 통째로 옮기는 게** 맞다.
3. **깊이만 줄이면 "잘렸다"가 아니라 "작아졌다"로 읽힌다.**
   잘린 앞면을 **밝게** 칠해야 칼이 지나간 게 보인다.
   (three 의 클리핑 평면은 안 썼다 — 속이 뚫려 "빈 상자"가 된다. 도해는 속이 차 있어야 한다)
4. **자막 안전영역은 3D 에서 더 쉽게 깨진다.** 첫 프레이밍에서 맨 아래 층 라벨이
   y≈980 까지 내려갔다. 카메라 거리를 `spread * 2.55 + 4.2` 로 자동 계산해
   벌어진 높이에 맞춰 뒤로 빠지게 했다 (침범 0.000% 확인).

그리고 **JSX 주석을 삼항 분기 안에 넣어 또 터뜨렸다** (`MotionWrap` 에 이어 두 번째).
`{cond ? ( {/* 주석 */} <div/> ) : null}` 은 문법 오류다. 주석은 `{cond ?` **위로**.

## 36. 점 배열 기법 — `NodeArrayCard` (2026-08-15)

사용자가 특정 시점을 지목했다: Cleo Abram "The Massive Machine Hidden in the Deep Ocean"
(`GjDlPhwsdCs`) 12:21. **채널을 베끼라는 게 아니라 그래픽 기법을 배우라는 것** — 명시적 교정.

### 36-1. 그 시점에 실제로 접근할 수 있었나 — 못 했다, 정직하게 남긴다

고정 3프레임(25/50/75%)만 받을 수 있다는 한계(§35-8)가 다시 발목을 잡았다.
955초 영상에서 50%(478s)·75%(716s) 둘 다 받아 봤지만 **둘 다 인물 토크 샷**이었다.
12:21(741s)은 챕터 "How do you know you've detected a neutrino?"(11:42–12:27) 안에
있다는 것만 메타데이터로 확인했고, **그래픽 자체는 못 봤다.**

그래서 이번엔 프레임을 보고 베낀 게 아니라 — 챕터 제목 + 이 장르(중성미자
관측기 대중과학 영상)에서 거의 고정적으로 쓰이는 시각화 관습 + §35-3 에서 이미
정리한 Cleo 의 기법 목록으로 **기법을 역산**했다. 확신도는 프레임 확인보다 낮다.
더 정확히 하려면 §35-9 표대로 스크린샷이 필요하다.

### 36-2. 추정한 기법 — "성긴 점 배열, 몇 개가 신호를 낸다"

IceCube/KM3NeT 류 중성미자 관측기의 표준 시각화: 센서를 매단 **줄(string)을
3D 격자로 세워 심해/얼음 속에 늘어뜨리고**, 입자가 지나가면 몇 개 노드만
반짝이고, **그 반짝인 점들을 이어서 경로/위치를 역산했다**는 걸 보여 준다.

이게 지금까지 만든 카드들과 근본적으로 다른 점:
- `LayerPeelCard`/`MassingCard`(§35-7·8) = **덩어리(volume)** — 판을 벗기거나
  발자국을 뽑아 올린다. 대상이 연속된 면일 때
- `NodeArrayCard`(신규) = **점(point)** — 대상이 흩어진 개별 지점의 집합이고,
  그중 일부가 "선택되었다/신호를 냈다"는 걸 보여줄 때

### 36-3. 옮긴 것 — 소재가 아니라 문법

중성미자는 상권분석 유튜브에 쓸 일이 없다. 옮긴 건 **"점 여러 개 중 몇 개가
값을 갖는다 → 그 점들을 이으면 이야기가 된다"**는 문법이다. 이 채널에 바로
맞는 용도:
- 상권 안 CCTV·와이파이 유동인구 센서 배치 — 16개 중 3개가 시간대별 피크
- 지하철역 출구·환기구 네트워크 — 여러 개 중 특정 출구 하나를 지목
- 동일 평형이 반복되는 단지에서 특정 호실 하나만 강조

### 36-4. 구현 — `motion/src/NodeArrayCard.jsx`

`cols×rows` 격자의 줄마다 `perString`개 노드가 세로로 달린다. `hits`로 지정한
노드만 옐로로 켜지고 숨쉬듯 스케일이 뛴다(펄스). 원칙은 3D 로 와도 그대로다
(§32-3, §35-3): **글로우를 안 쓴다.** "번짐"은 WebGL 발광이 아니라
`annotate.jsx`에 추가한 `PulseRing`(SVG 테두리 링, 2D 오버레이)으로 처리했다 —
빛나는 재질을 넣는 순간 도해가 아니라 어설픈 렌더가 된다는 원칙(§32-3)을
3D 발광에도 그대로 적용한 것.

히트 노드를 순서대로 잇는 궤적선은 `DimLine`과 같은 원칙(손맛 없이 곧게)으로
길이 기준 진행률만큼 자라난다. 카메라 거리는 격자 전체 크기에서 자동 산출해
자막 안전영역을 넘지 않게 뒤로 뺀다(`LayerPeelCard`와 같은 공식 계열).

첫 렌더에서 바로 통과: 격자가 가운데부터 자라나고, 히트 3개가 펄스+라벨과 함께
뜨고, 궤적선이 순서대로 이어졌다(역삼 GS타워 상권 유동인구 예시로 검증).

## 37. 실물-도해 연결 — `SplitProofCard` (2026-08-15)

같은 세션, 다음 링크: Cleo Abram "What If You Just Keep Digging?"
(`N0-ZZ9pLyWw`, 지구 중심까지 파고들면). 이번엔 **썸네일 자체가 그래픽이었다** —
내부 프레임 3장은 여전히 다 인물 토크 샷이었지만 `maxresdefault.jpg`는
실제로 화면을 반으로 나눈 합성 이미지였다. 그래서 §36 과 달리 이번엔 **실물을
직접 보고** 기법을 읽었다.

### 37-1. 본 것 (그대로 묘사)

왼쪽 절반: 콜라 초심층 시추공(옛 소련, 세계에서 가장 깊이 판 구멍) 뚜껑의
실제 사진 — 녹슨 금속판에 "12,226 метров"(미터)가 각인돼 있다. 오른쪽 절반:
일러스트 단면 — 풀밭(초록) → 흙(황토) → 더 깊은 토양(적갈) 층이 쌓이고,
가느다란 검은 시추관이 파란 드릴팁을 달고 내려가다가 "12.2 KM"이라는
굵은 흰 글씨 라벨에서 멈춘다. 오른쪽 아래 구석엔 용암이 흐른다(더 내려가면
뜨겁다는 걸 암시). 두 절반을 **손으로 그린 흰 화살표 하나**가 왼쪽 위에서
오른쪽 아래로 가로지르며 잇는다.

### 37-2. 기존 카탈로그와 뭐가 다른가

`SectionDiagramCard`(§32-3②)는 의도적으로 **딱 두 색**(바탕/채움)만 쓴다 —
"지층마다 색을 다르게 하면 지질도가 되지 개념 설명이 안 된다"는 게 그 카드의
원칙이다. 이번 것은 **정반대다.** 지층에 그라디언트를 일부러 준다. 왜 정반대가
맞는가 — 이건 개념도가 아니라 **"실물이 진짜 있다"를 증명하는 자리**이기
때문이다. 왼쪽 사진이 이미 "이건 지어낸 게 아니다"를 말하고 있으므로, 오른쪽
도해도 "진짜 땅속처럼 보이는 것"이 신뢰를 더한다. 두 카드는 **정반대 원칙이
각자의 자리에서 다 맞다** — 사용 조건이 다를 뿐이다.

또한 `HandArrow`(B1M 문법, §7-3)를 쓰는 방식이 새롭다. 지금까지는 사진 한 장
**안에서** 라벨→대상을 이었다. 여기선 **서로 다른 두 패널(사진 vs 일러스트)의
이음새를 가로질러** "이 실물이 저 도해다"를 선언하는 용도로 썼다 —
같은 프리미티브, 다른 역할.

### 37-3. 구현 — `motion/src/SplitProofCard.jsx`

좌 = 실물 사진(`Img`+`staticFile`, 이 카드의 존재 이유 — 사진 없으면 그리지
않는다), 우 = 색 밴드 단면 + 시추관(위→아래 진행률로 자라난다, `DimLine`과
같은 손맛 없는 직선 원칙) + 끝 값 라벨. 화살표는 사진·단면이 자리 잡은 뒤에
그어진다. 파크사이드 항공사진 + 예시 깊이값(28M, 지하 7층 기초)으로 첫 렌더
검증 — 사진/단면/화살표/라벨 전부 자막 안전영역 안에서 정상 배치.

**이 채널에 옮긴 용도**: 소재는 시추공이 아니라 **기초 깊이**다. "지하 7층이
실제로 몇 미터인가"를 실물 항공사진과 나란히 보여줄 때, 또는 등기부·인허가
서류·초석 명판처럼 실물 근거가 있고 그 의미를 옆에서 풀어야 할 때 쓴다.
반대로 3D 쪽은 지금 재료로도 상당히 갈 수 있고, GLB 하나만 있으면 한 단계 더 간다.

## 38. 올리브영 성수편에서 나온 파이프라인 함정 (2026-08-16)

한 편(123컷)을 실제로 끝까지 돌려 보니 **그래픽 문법이 아니라 공정 쪽에서**
사고가 났다. 넷 다 조용히 틀리는 종류라 적어 둔다.

### 38-1. "가장 큰 것부터"라고 적고 **먼 것부터** 남기고 있었다

`fetch_buildings.py` 가 발자국을 중심 거리 기준 **내림차순**으로 정렬한 뒤
앞에서 잘랐다. 주석에는 "가장 큰 것부터"라고 써 있었다. 결과는 매싱 한가운데가
텅 빈 **도넛**. 매싱은 "대상 주변이 어떤가"를 보는 그림이라 중심이 비면
아무 말도 못 한다. 부호 하나였다.

> 교훈: 주석이 코드를 검증해 주지 않는다. **렌더를 눈으로 봐야** 잡힌다.

### 38-2. 지면 반경을 요청값으로 쓰면 안 된다

같은 카드에서 바닥 원을 `--radius` 로 그렸는데, `keep` 으로 잘려 나간 만큼
바닥만 넓어져 매스가 **접시 위 부스러기**처럼 보였다. 지면은 요청 반경이 아니라
**실제로 그려지는 것들의 범위**에서 유도해야 한다.

### 38-3. 시작점이 원본 끝을 넘으면 ffmpeg 가 **영원히 멈춘다**

이게 제일 위험했다. 6.04초짜리 원본에 `ss=7.8` 을 배정했더니 —
- 첫 입력에서 프레임이 **0개** 나오는데
- 출처 오버레이 PNG 는 `-loop 1` 이라 **무한히 공급**되므로
- `-frames:v` 에 영영 도달하지 못하고 매달린다

**에러가 안 난다.** CPU 만 태우며 조용히 멎어서, 진척이 없다는 걸
한참 뒤에야 알았다. 스톡 영상은 6초짜리와 37초짜리가 섞여 있으므로
**길이를 가정하면 안 되고 재야 한다.**

고친 곳은 둘이다. 호출자(`fill_props.py`)가 길이를 재서 안 넘게 잡고,
`render_broll.py` 도 스스로 잘라 낸다 — **한쪽만 고치면 다음 프로젝트에서 또 걸린다.**

### 38-4. 한글 프로젝트명은 `pgrep -f` 로 못 잡는다

렌더 완료를 기다리는 스크립트에 `pgrep -f "render_parkside.py --project 올리브영성수"`
를 썼는데, 프로세스 목록에서 한글이 깨져 **매칭에 실패**했다. 대기 루프가 즉시
빠져나가 렌더 도중에 다음 단계(b-roll·미리보기)가 돌았고, 9컷짜리 미리보기가 나왔다.
**스크립트 이름만으로 잡는다.**
