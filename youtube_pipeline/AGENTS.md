# AGENTS.md — 이 폴더에서 일하는 에이전트가 먼저 읽을 것

부동산·건축 지식 교양 유튜브(B1M 결)의 **그래픽 파이프라인**이다.
대본을 넣으면 컷별 mp4가 나오고, 프리미어 타임라인 XML까지 만들어 준다.
Remotion(React로 영상을 그린다) 위에 종이 질감 디자인 시스템을 얹었고,
그 앞뒤(설계·소재·검사·납품)는 Python 스크립트가 맡는다.

최종 편집은 사람이 프리미어에서 한다. **나레이션과 자막은 이 파이프라인이
만들지 않는다.**

---

## 0. 절대 규칙 (채널 확정 — 협상 대상이 아니다)

어긴 화면은 다시 만든다. 코드를 고칠 때도 이걸 깨는 방향으로는 고치지 않는다.

1. 출처는 화면 **우상단 `Source : 0000`**. 위치·형식 예외 없다
2. **나가는 모션 금지.** 들어오는 것만. `exitSec` 는 항상 0
3. 전환 모션은 **18컷 안팎**만 (챕터 첫 컷 + 판이 뒤집히는 자리).
   늘 있으면 전환이 아무 뜻도 없다
4. **막대 위에 숫자를 올리지 않는다.** 01/02 같은 번호는 세로선 **오른쪽**
5. **소재 0중복.** 같은 사진·영상·그래픽을 두 번 쓰지 않는다
6. 배경을 베이지 한 종류로만 쓰지 않는다
7. 저작권물은 **출처를 밝히고 쓴다.** 로고 포함
8. **실존 장소·건물·브랜드는 실사만.** 구조·개념만 도해 또는 생성 이미지.
   실존하는 것을 생성물로 대신하면 안 된다
9. 가정·추정·자체계산은 **화면에 명시**한다
10. 캡레이트는 4.5 / 5.0 / 5.5% 셋 다 산출. 임대료 단위는 **만원/평/월**
11. **영상마다 힉스필드 생성 이미지를 2장 이상** 쓴다. 고퀄리티로. 특히
    건축물·공간의 **구조**를 설명하는 자리(단면·아이소메트릭·동선). 실존물의
    외관을 생성물로 대신하는 건 아니다 — 규칙 8 이 먼저다
12. **인용하거나 인물이 나오면 그 사람 사진을 넣는다.** 잘 따와서.
    전체 화면일 필요는 없다 — 이름표 옆 인셋이면 된다. 단 **얼굴 위에
    글자를 얹지 않는다**. 실존 인물의 눈·입에 글자가 앉은 적이 있다
13. **도형·이미지·글자는 절대 잘못 겹치지 않는다.** 간격(`SP`)과 층 순서
    (배경 → 이미지 → 도형 → 글자 → 출처)를 지킨다. 글자가 선·막대·그림 위에
    앉으면 그 컷은 틀린 것이다 — `check_overlap.py` 가 잰다

### 화면 글자

**자막은 사람이 `script.md` 에서 따로 태운다.** 화면 글자가 나레이션을
되풀이하면 같은 말이 두 번 나온다.

남긴다 — 그래픽이 뜻을 지는 데 필요한 것만:
숫자와 단위(`147실`, `22,892원/㎡`) · 축과 항목 이름 · 고유명사 ·
가정과 기준(`공시 요금 기준`) · 출처.

지운다: 나레이션을 옮겨 적은 제목·부제·캡션 / 사진 위 설명 문장(그 자리가
자막 자리다) / "그만큼 중요해진다" 같은 결론 문장.

**한 컷에 글자 덩어리 두 개를 넘기지 않는다.** 숫자 하나 + 라벨 하나면 된다.

### 글자는 최소화한다 — 딱 중요한 것만 (2026-09-17 · 사용자 확정)

0 으로 만들라는 게 아니다. **있어야 할 이유가 있는 것만** 둔다. 이유는 셋뿐:
숫자·단위 / 고유명사 / 가정·기준·출처. 그 밖의 글자는 하나씩 물어라 —
"자막이 이미 말하는가?" 그렇다면 뺀다.

- 제목은 기본으로 없다. 숫자의 **이름표**(`월 실부담`)나 **기준**(`주거형만 셀 때`)
  일 때만 둔다. "TOKIORI의 역할", "아파트가 못 하는 것" 같은 **주제 제목은 뺀다** —
  나레이션이 그 문장이다
- 항목 라벨은 **아이콘으로 대체할 수 있으면 아이콘**으로 (`items[].icon`,
  Lucide 이름). 식사·병원·돌봄은 글자보다 그림이 빠르다
- 값 밑 보조 줄(note · lines)은 숫자·고유명사·가정일 때만
- `apply_design.py --check` 가 **글자 예산**을 센다: 숫자·단위·출처를 뺀 글자
  덩어리가 셋을 넘으면 걸린다. 렌더 전에 잡아라

### script.md 는 함부로 건드리지 않는다

**줄 하나가 컷 경계다.** 한 줄을 끼워 넣으면 컷이 다시 쪼개지고 그 뒤 컷
번호가 전부 밀린다. 실제로 인용 한 줄을 넣었다가 224컷의 id가 +1 됐다.
대본을 고쳐야 하면 **그 영향 범위를 먼저 말하고 확인을 받아라.**

## 1. 일하는 순서

**렌더 전에 설계를 확정한다.** 269컷 렌더는 30분이고, 다 뽑은 뒤 고치면 또
30분이다. 설계 단계에서 고치면 몇 초다.

```bash
# ① 대본 → 컷 초안. 분할·길이·카드 추천이 한 번에 나온다
python3 scripts/plan_from_script.py <대본>.md --project <이름> --dry

# ② design.json 을 손으로 확정한 뒤 검사 → scene_plan/scene_props 생성
python3 scripts/apply_design.py <이름> --check
python3 scripts/apply_design.py <이름> --placeholder

# ③ 소재. 컨택트시트를 눈으로 보고 채택한다
python3 scripts/fetch_sources.py <이름> --q "검색어" --video "검색어"
python3 scripts/fetch_sources.py <이름> --adopt <id> <파일명>

# ④ 렌더
python3 scripts/render_parkside.py --project <이름> --fresh -j 4
python3 scripts/render_parkside.py --still --project <이름>     # 검수용 스틸

# ⑤ 검사 (5장 참고)
# ⑥ 납품
python3 scripts/build_premiere_xml.py --project <이름>
python3 scripts/pack_premiere.py <이름> --max-mb 28
```

`apply_design.py` 는 **경고가 있으면 0이 아닌 코드로 끝난다.** `&&` 로 이어
붙이면 뒤가 안 돌아간다. 따로 실행해라.

`design.json` 이 **대본→화면의 단일 원본**이다. 컷 번호 → `[카드, 이유, props]`.
`scene_plan.json` · `scene_props.json` 은 여기서 생성되는 파생물이다.

## 2. 「설계 상태」 리포트를 먼저 읽어라

`plan_from_script.py --dry` 의 맨 끝 세 줄이 이 도구의 진짜 출력이다.

- **규칙에 안 걸린 문장 N컷** → 도구가 못 골랐다. 사람이 한 줄씩 설계해야 한다
- **실사 계열 N%** → 권장 25~52%. 넘으면 설명 문장을 사진으로 때우고 있는 것
- **최다 카드 N%** → 32% 넘으면 그 카드 하나로 때우고 있는 것

이게 왜 있냐면: 올리브영 성수편 123컷을 다 만들고 세어 보니 **82컷(67%)이
`LowerThirdCard` 하나**였다. 실사 위에 자막 얹는 카드다. 화면은 계속 바뀌는데
문법은 하나였다.

원인은 실력이 아니라 **순서**였다. 대본을 읽으며 소재부터 고르면 거의 모든
문장이 "여기 어울리는 영상"으로 풀린다. 문장의 **구조**를 먼저 보면 값·비교·
인과·선택·배분처럼 그림이 따로 있는 것들이 갈라져 나온다.

> **소재보다 구조를 먼저 정한다.**

카드 고르는 법은 `docs/카드-고르기.md`, 특히 5번 「구조·배분」부터 봐라.

### 가장 중요한 판단 하나

**"이 문장은 설명인가, 장면인가."**

- **설명**이면 그림이 뜻을 져야 한다. 나레이션이 없어도 화면만으로 절반은
  전달돼야 한다. 회색 사각형 하나 띄우고 나레이션이 다 지고 가면 그건
  설명이 아니라 자막이다
- **장면**이면 소재가 주인공이다. 꽉 채우고 글자는 최소로

## 3. 코드 지도

```
scripts/           Python 52개 — 설계·소재·렌더·검사·납품
motion/src/        Remotion 카드 88종 + paper.jsx (디자인 시스템)
  paper.jsx          테마·상수·공통 조각. 카드는 전부 여기에 기댄다
  cardRegistry.jsx   카드 이름 → 컴포넌트. design.json 이 문자열로 부른다
  MotionWrap.jsx     컷을 감싸 모션을 얹는다
projects/<이름>/   design.json(원본) · script.md · 출처.md
docs/              카드 고르기 · 설명을 그림으로 · 규칙과 함정
```

### paper.jsx 상수 — 직접 숫자를 적지 말고 이걸 써라

| | |
|---|---|
| 테마 | `paper` · `ink` · `blueprint` — `themeOf()` 가 고른다 |
| 강조색 | `YELLOW` `#FAFF2E` **하나**. 항목별 색 팔레트는 쓰지 않는다 |
| 글자 `FS` | MICRO 29 · SMALL 35 · LABEL 40 · BODY 50 · LEAD 64 · TITLE 80 · HERO 104 · MEGA 148 |
| 간격 `SP` | TIGHT 12 · NEAR 26 · GAP 44 · BLOCK 64 · BAND 96 |
| 안전선 | `SUBTITLE_SAFE_BOTTOM` 176 · `CONTENT_BOTTOM` 904 · `OPTICAL_CENTER` 512 |
| 도우미 | `estW()` 글자폭 추정(한글 1, 그 외 0.62) · `useFitEnd()` · `useFade()` · `stageTop()` |
| 공통 조각 | `PaperBg` `PaperTitle` `PaperSource`(우상단) `PaperCaption` `NumberIn` `ValueChip` |
| 도면 조각 | `CropMarks`(모서리 재단선, PaperBg 기본 켜짐) · `TechBox`(이름표 상자, 얼굴 인셋) · `DimLine`(양끝 T 치수선) · `Callout`(직선 지시선, 실측값용) · `PairLabel`(이름 Bold / 수치 Light) |

**`SP` 간격은 넓히는 쪽으로 한 번 조정된 값이다. 좁히지 마라.**
글자가 붙어 보인다는 지적을 받고 올린 것이다.

### 크림 종이 위에는 흰 글자를 쓰지 마라

`StageCard` 글자는 어두운 실사용(흰색 + 그림자)이다. 힉스필드 개념도처럼
**종이 톤 이미지** 위에 올릴 때는 `onPaper: true` — 잉크 글자 + 형광펜 띠,
스크림 없음. 발광은 어두운 바탕에서만 성립한다.

인용 컷의 인물 사진은 `QuoteCard` 의 `inset`(이름표 왼쪽 96px 칸)에 넣는다.
`photo`(오른쪽 큰 칸)는 전신·상황 사진용이다. 둘 다 얼굴 위에 글자를 얹지 않는다.

### 색으로 항목을 구분하지 마라

먹 + 노랑 하나다. 색으로 항목을 나누면 **색이 뜻을 갖게 되고, 그러면 색을
계속 설명해야 한다.**

### 카드를 새로 만들 때

```bash
python3 scripts/register_card.py <이름>Card --props   # 레지스트리·Root 둘 다
grep -L "themeOf\|PaperBg" motion/src/*Card.jsx       # 안 걸리면 옛 계열이다
```

옛 계열(먹 배경 + 발광)에서 옮길 때: 발광 → 형광펜 띠나 먹 테두리
(발광은 어두운 바탕에서만 성립한다. 크림 종이 위에서는 번져 흐릿하기만 하다) /
카드가 따로 그리던 격자 → `PaperBg` 격자 / 배경별 글자색 분기 → 없앤다.

### 모션

`MotionWrap` 이 감싼다. **기본은 꺼져 있다** — 105컷에 같은 밀어내기를
넣었더니 어지럽다는 지적이 왔다.

- `motion: {transition: true}` = 화면 밀어내기. 챕터 첫 컷과 판이 뒤집히는 자리만
- `punchAt` = 3.5% 한 번 확대하고 멈춤(22프레임). transition 과 독립이다
- `exitSec` 는 항상 0 (규칙 2)

### JSX 함정 두 개 (둘 다 실제로 번들을 깨뜨렸다)

- **삼항 분기 안에 `{/* 주석 */}` 을 넣지 마라.** 표현식 하나가 와야 하는
  자리다. `//` 를 써라
- 좌표를 손으로 적지 마라. `const bandTop = title ? 244 : 190` 같은 상수는
  제목 높이가 바뀌는 날 낡는다. `stageTop()`·`estW()` 로 계산해라

## 4. 이 폴더에 **없는** 것

- `motion/public/<프로젝트>/` **소재 사진 188MB.** 저작권 출처가 제각각이라
  통째로 재배포할 물건이 아니다. `bin/자료받기.sh` 가 공식 사이트에서
  다시 받는다. 소재 없이도 코드 수정·타입 검사·구조 작업은 다 된다
- `clips/` `stills/` 렌더 결과 약 1GB. `design.json` 에서 다시 나온다
- `node_modules/` — `cd motion && npm install`

## 5. 검수는 눈이 아니라 **재서** 한다

이 저장소의 검사기들은 전부 **실제로 났던 사고**에서 나왔다. 새 기능을 만들면
검사기도 같이 만들어라. 그게 이 파이프라인의 방식이다.

```bash
python3 scripts/check_settled.py <이름> --tol 200   # 숫자가 다 안 자란 채 끝나는 컷
python3 scripts/check_balance.py <이름>             # 위로 몰리고 아래가 빈 컷
python3 scripts/check_bleed.py <이름> -v            # 자막 안전선·화면 밖
python3 scripts/check_contrast.py <이름>            # 밝은 사진 위 흰 글자
python3 scripts/check_layout_rules.py               # 손으로 적은 좌표 (소스 검사)
python3 scripts/check_premiere.py <이름> --deep     # XML 구조·경로
python3 scripts/qa_check.py <이름>                  # 납품 직전 종합
python3 scripts/contact_sheet.py <이름>             # 한 장에 모아 흐름을 본다
```

### 겪은 사고 — 같은 데 빠지지 마라

- **스틸로는 못 잡는 게 있다.** 스틸은 프레임 78을 굽는데, 2.2초(66프레임)
  컷에는 **그 시점이 존재하지 않는다.** 카운트업이 [16,70]프레임이라
  다 세기 전에 컷이 끝나서 **화면에 틀린 수가 나갔다.**
  → 짧은 컷의 숫자는 `check_settled.py` 로 확인해라
- **측정기가 조용히 성공하는 게 제일 위험하다.** `check_settled.py` 는
  컨테이너 길이(2.26초)와 마지막 디코딩 가능 프레임(2.167초)이 달라
  **268컷 전부를 건너뛰고 "끝까지 다 자란다"고 출력한 적이 있다.**
  못 잰 건 통과가 아니다. 건너뛴 개수를 반드시 세서 보고해라
- **눈으로 본 범인은 틀렸다.** 균형이 깨진 카드를 눈으로는 `SpecGridCard`
  로 지목했는데, 재 보니 멀쩡했다. 진짜 원인은 **"예약한 칸이 내용보다
  넓은"** 카드 넷이 그림을 반대쪽으로 밀고 있던 것이다
- **화질이 깨졌다는 말의 실제 원인이 "깨짐"이 아니었다.** 1920×482 로
  갖고 있던 사진의 서버 원본이 3840×1200 이었다. 절반으로 줄여 받아 놓은 걸
  16:9에 채우니 늘어나 뭉갠 것이다. `refetch_official.py` 가 되돌린다
- **받아진 파일을 열어 보고 나서 재시도해라.** Wikimedia 는 실패해도
  200으로 **2,256바이트 HTML 에러 페이지**를 준다. 크기만 보고 "받았다"
  하면 안 된다. `curl` 에 `-L` 이 빠지면 0바이트다
- **변수 이름을 재사용하지 마라.** 새 리스트를 `design` 으로 이름 지어
  컷 딕셔너리를 덮어썼다

## 6. 사람이 결정하는 것 — 혼자 판단하지 마라

- **소재 채택.** 컨택트시트를 사람이 보고 고른다. 자동 채택 금지.
  실제로 이런 게 통과될 뻔했다 — 일본 시니어 레지던스 자리에 붉은 레이저를
  쏜 서양인 얼굴 / 나라와 시대가 안 맞는 마스크 쓴 실외 줄 / 글자가 읽히는
  터키 신문 / **실존 인물 얼굴의 눈과 입에 글자가 앉은 초상**
- **숫자 뒤에 장식을 깔 바엔 종이에 숫자를 두는 게 낫다.** 뜻을 지지 않는
  배경 사진은 추가하지 마라
- **렌더 전 설계 시트 승인.** 컷 / 나레이션 / 카드 / 테마 / 소재 표를 보여 주고
  확정을 받은 다음에 렌더한다
- `projects/<이름>/출처.md` 의 **🔴 항목이 design.json 보다 우선한다.**
  화면에 띄우면 안 되는 것, 자막을 반드시 병기해야 하는 것이 적혀 있다.
  소재를 고르기 전에 읽어라
