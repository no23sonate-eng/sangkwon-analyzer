# 디자인 레인 — 편집 세션의 결과물을 비주얼로 고도화하는 역할

> 이 문서는 **두 개의 클로드 코드 세션을 나눠 쓰는 방법**이다.
> 편집 세션은 "무엇을 언제 말할지", 디자인 세션(=이 레인)은 "그걸 어떻게 보여줄지"를 맡는다.

## 1. 역할 분담

| | 편집 레인 | **디자인 레인 (이 역할)** |
|---|---|---|
| 맡는 것 | 대본 → 장면 분해, 타이밍, 실사 B-roll 선택, 자막, 프리미어/캡컷 패키지 | 카드 시스템 설계·구현, 비주얼 문법, 레퍼런스 학습, 장면의 표현 방식 결정 |
| 산출물 | `broll_plan.json` / `selections.json` / 편집 패키지 | `motion/src/*.jsx` 카드, `v2_scenes.json`, 렌더 스틸·클립 |
| 판단 기준 | 내용의 정확성·흐름·호흡 | `design_reference.md` §19~§21 |
| 건드리지 않는 것 | 카드 내부 디자인 | 대본 문구·사실관계 (수치는 대본에 있는 것만) |

**다리는 깃 저장소 하나다.** 편집 레인이 브랜치에 푸시 → 디자인 레인이 fetch·머지 →
고도화해서 다시 푸시. 파일을 주고받을 필요가 없다.

## 2. 계약 — `projects/<프로젝트>/v2_scenes.json`

두 레인이 공유하는 유일한 계약. 편집 레인은 **최소 형태**만 채워도 되고,
디자인 레인이 나머지를 채운다.

```jsonc
{
  "project": "성수올리브영",
  "scenes": [
    {
      "id": 0,                     // broll_plan.json 의 섹션 id 와 1:1
      "line": "대본 문장 그대로",     // ← 편집 레인이 채움 (창작 방지 대조용)
      "card": "YHeadlineCard",     // ← 디자인 레인이 결정
      "props": { "durationSec": 4.5, "...": "카드별 props" },
      "use_v7": false,             // true 면 기존 실사 클립을 그대로 씀
      "v7_file": "broll_candidates/sec0_news.mp4"
    }
  ]
}
```

- `line` 은 **반드시** 채운다 — 린터가 "대본에 없는 숫자"를 잡는 근거가 된다.
- `use_v7: true` 인 장면은 디자인 레인이 렌더하지 않는다(실사 우선, §21-2 1단계).

## 3. 고도화 루프 (매번 이 순서)

```
1) 가져오기    git fetch origin <편집브랜치> && git merge
2) 진단        python3 youtube_pipeline/scripts/scene_lint.py <프로젝트>
3) 위계 점검   §21-2 사다리로 장면마다 "더 낮은 단계로 표현 가능한가?" 확인
4) 카드 교체   글자 카드 → 그래픽 카드, 없으면 신규 카드 구현
5) 렌더 검수   render_v2_stills.py → 시트로 눈으로 확인 (겹침·잘림·대비)
6) 재진단      2번 다시 — 지적 0건 또는 남긴 이유 기록
7) 푸시        커밋 후 편집 브랜치로 푸시, 리뷰 시트 전달
```

## 4. 진단 규칙 (`scene_lint.py` 가 자동 점검)

| 코드 | 규칙 | 왜 |
|---|---|---|
| `FACT` | 대본에 없는 숫자가 화면에 있음 | 창작 금지 — 최우선 |
| `R2` | 강조(hot)가 화면당 2곳 이상 | 강조가 둘이면 강조가 없는 것 |
| `R8` | 데이터 카드에 킥커(맥락) 없음 | 숫자만 떠 있으면 안 읽힘 |
| `SRC` | 수치 카드에 출처 없음 | 신뢰도 |
| `RHY` | 글자 카드 9초 초과 / 데이터 카드 6초 미만 / 같은 카드 3연속 | 화면이 죽거나 애니메이션이 안 끝남 |
| `MIX` | 글자 위주 카드가 40% 초과 | "설명을 그리지 않은" 상태 |
| `LADDER` | 실사가 한 장도 없음 | §21-2 기본층(B1M)을 안 쓴 것 |
| `MEDIA` | 실사 카드가 비었거나 `demo/…` 예시 이미지 | 실사 원칙 위반 — 실제 대상 자료로 교체 |

## 5. 디자인 레인이 지키는 상위 원칙

1. **기본은 B1M, 부족할 때만 Stewart Hicks** (§21-2 6단계 사다리)
2. **글씨는 화이트, 옐로 `#FAFF2E` 는 그래픽과 포인트 단어에만** (§21-3)
3. **한 화면 = 한 명제**, 강조는 한 곳
4. **수량은 글자가 아니라 형태로** (도트·블록·칸·기울기)
5. **라벨은 반드시 대상과 연결** (리더 라인·화살표)
6. **하단 260px 는 자막 안전영역** — 비운다
7. **대본에 없는 사실을 만들지 않는다** — 모르면 중립 표기("상층부")
8. **실사는 실제 대상이 1순위**, 없으면 유사 분위기 스톡. 예시 이미지를 남긴 채 넘기지 않는다 (§23-8)
9. **인물 영상은 만들지 않는다** — 사용자가 직접 넣고 뺀다. 자리만 비워둔다
10. **아카이브·인용은 출처 없이 쓰지 않는다** — 시대 칩 + `COURTESY OF …`
11. **근접성은 실사로 우기지 않는다** — 항공사진이 없으면 `PaperWalkCard` 개념 평면도
